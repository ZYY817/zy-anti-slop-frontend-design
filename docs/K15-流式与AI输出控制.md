# K15 · 流式与 AI 输出控制

> 覆盖 5 个决策对象：追底滚动判定、停止与中断语义、重新生成与版本、渲染节奏与未闭合标记、上下文与用量显示。
> B50/G6/B83 把流式的视觉规格与信任原则写得很深，但最关键的**行为判定**——用户上滑时新 token 到达要不要滚、停止后部分内容算谁的、重新生成是替换还是分支——此前零决策点。本文件补行为层，视觉规格衔接 B50。

## K·追底滚动判定（Streaming Autoscroll）

- **领域**：AI/滚动 · **成本**：中
- **定义**：流式输出不断增长时，视口是否跟随新内容滚到底——以及用户主动上滑阅读时，跟随权何时让出、何时收回。这是 AI 聊天产品最经典的交互冲突。
- **症状**：用户上滑读前面的内容，新 token 一到就被拽回底部；脱离跟随后没有"回到底部"入口；流式结束后用户不知道已经输出完了；移动端键盘弹出打断跟随状态。
- **适用**：聊天/流式输出/日志流/实时列表 ｜ **不适用**：非增长内容（静态页）、内容量小无滚动场景。
- **决策点**：
  ① **跟随状态机**——跟随中（atBottom=true 随新内容滚）/ 已脱离（用户上滑后不自动滚）/ 恢复条件（用户回到底部 or 点击"回到底部"按钮）
  ② **脱离阈值**——用户滚动即脱离？还是上滑超过 N px 才脱离？（推荐：wheel/touch 主动滚动立即脱离；程序性滚动不脱离）
  ③ **回接阈值**——距底部多少 px 视为"回到底部"恢复跟随？（常用 40-80px 容差；严格 0 容易永远脱离）
  ④ **新内容指示**——脱离期间新 token 到达："跳到底部"浮动按钮 + 未读计数/新消息条（B50 已有组件规格，决策在何时出现/消失）
- **实现**：
  - 判定：`atBottom = scrollHeight - scrollTop - clientHeight < 80`；轮询或 scroll 事件维护
  - 用户意图区分：`onWheel`/`onTouchStart` 标记 userScroll；程序 scrollTo 不触发脱离
  - 流式中 `if (atBottom) scrollTo(bottom)`；脱离期间渲染新内容但不滚
  - 按钮出现：脱离 && 有新内容；点击回底 + 恢复跟随 + 清计数
- **验收**：跟随中新内容平滑追底；上滑立即脱离不再被拽；回到底部或点按钮恢复跟随；脱离期间浮动按钮出现且带未读感；流式结束态可区分（光标停止/完成标记）。
- **衔接**：B50:105-135（流式视觉规格）、B50:285-286（跳到底部+新消息指示）、G6（AI 对话规格）、K6·滚动锚定（同族判定）、F4

## K·停止与中断语义（Stop / Abort）

- **领域**：AI/交互 · **成本**：低
- **定义**：用户点"Stop"后发生什么——请求何时真断、部分内容去留、界面呈现什么。
- **症状**：点了 Stop 还在输出（abort 没传到流）；停止后整段内容消失用户白等；停止后没有"已停止"标记看起来像是输出完了；停止按钮和发送按钮同一位置误触。
- **适用**：一切可中断的 AI 生成/长请求 ｜ **不适用**：瞬时响应（无需中断）。
- **决策点**：
  ① **真停时延**——Abort 要在 100ms 内真正停止渲染新内容（B83 实测原则）；abort 传 AbortController 而非只改 UI 态
  ② **部分内容语义**——保留已输出 + 标记"已停止"（推荐）vs 整体丢弃？保留是信任资产：用户可能正需要前半段
  ③ **停止后状态**——输出尾部加"■已停止"标记；输入框恢复可用；不允许"停止但看起来还在生成"的幽灵态
  ④ **按钮互斥**——生成中发送钮变 Stop（同位互斥，不误触）；键盘 Enter 在生成中默认不触发新请求
- **实现**：
  - `AbortController.abort()` → ReadableStream cancel；服务端真停需协议支持（SSE/WebSocket 中断）
  - 停止态 = 独立状态非"完成"：消息尾部渲染停止标记 + 可选"继续生成"
  - aria-live：停止动作对读屏可感知（polite 播报"已停止生成"）
- **验收**：点 Stop 100ms 内无新 token 渲染；已输出内容保留且有停止标记；输入区立即可用；无幽灵生成态。
- **衔接**：B83:106-108（Abort 100ms 实测）、B50（停止按钮规格）、G6:33（Stop generating）、K12·异步请求链（abort 同一机制）、B76

## K·重新生成与版本（Regenerate / Versioning）

- **领域**：AI/交互 · **成本**：中
- **定义**：对同一条请求重新生成时，旧输出如何处理——替换、折叠、还是版本分支。
- **症状**：点重新生成旧答案直接没了（没法比较哪版好）；版本 1/2/3 切换后不知道当前看的是哪版；分支后对话上下文到底基于哪一版含糊不清。
- **适用**：AI 对话/生成式产品 ｜ **不适用**：一次性工具调用（无版本概念）。
- **决策点**：
  ① **版本模型**——替换（旧版丢弃）/ 分支保留（版本切换条）/ 追加（新答案续写）？对话推荐分支保留：旧版折叠可回溯（B50 已有版本切换组件规格）
  ② **版本指示**——当前版本 N/M 显式可见；切换用 ‹ › 而非下拉（对比要快）
  ③ **上下文基点**——后续对话基于当前显示的版本；版本切换后新提问应明确基于所见版本
  ④ **再生成节流**——防连点（生成中禁用按钮）；次数上限或成本提示（长文再生成贵）
- **实现**：
  - 消息结构：`{versions: [{content, status}], activeIndex}`；分支渲染切换条
  - 旧版本默认折叠为版本条（"版本 1/3 ‹ ›"），点击展开对比
  - 版本切换更新后续渲染树基点；删除中间版本需防上下文断裂
- **验收**：重新生成保留旧版本可回切；当前版本指示清晰；后续提问基于所见版本；生成中不可连点。
- **衔接**：B50:293（版本切换规格）、G6（迭代对话 diff 高亮）、B83（Agent 控制感）、C5（版本文案）

## K·渲染节奏与未闭合标记（Render Pacing / Unclosed Markdown）

- **领域**：AI/工程 · **成本**：中
- **定义**：token 到达与 DOM 渲染之间的节奏控制，以及流式中未闭合 Markdown（```代码块、表格、加粗）的安全渲染。
- **症状**：每个 token 一次 DOM 更新导致闪烁和滚动跳动；未闭合的代码块把后半段对话全染成代码样式；表格流式一半时布局乱跳；token 太快时数字连滚看不清。
- **适用**：Markdown 流式渲染的聊天/生成 UI ｜ **不适用**：纯文本输出。
- **决策点**：
  ① **渲染节流**——每 token 渲染 vs 批次渲染（rAF 或 50-80ms 批量 flush）？批次渲染减少回流、仍显流式
  ② **未闭合处理**——流式中解析器对未闭合结构的策略：代码块等闭合 ``` 才整块渲染（G6 已采用），行内结构（加粗/链接）容错渲染
  ③ **布局稳定**——流式区预留 min-height、宽度固定，避免逐字撑开导致滚动与布局抖动；光标占位（2px 竖线）固定尾部
  ④ **完成态切换**——流式结束切换到完整渲染管线（KaTeX/高亮/图片加载），中间态与最终态不跳版
- **实现**：
  - 缓冲：`pendingTokens` 累积 → rAF flush 追加；React 下用 ref 直写 DOM 或 memo 分块
  - 代码块状态机：检测 ``` fence 计数，奇数=未闭合 → 暂存原文不渲染后半
  - 流式容器：`overflow-anchor` 或手写 scroll；`contain: layout` 限制重排范围
- **验收**：渲染不逐 token 闪烁；未闭合代码块不污染后续内容；表格/数学块完成后稳定渲染；滚动跟随不受渲染节流打断（衔接 K·追底滚动）。
- **衔接**：G6:29-62（流式规格：闭合```才渲染、虚拟滚动、ReadableStream）、B50（光标闪烁/逐字节奏）、F4、F3（渲染性能）

## K·上下文与用量显示（Context / Token Visibility）

- **领域**：AI/信息 · **成本**：低
- **定义**：AI 对话中"它现在看着多少上下文、还剩多少额度、这次调用花了多少"的可见性决策。
- **症状**：对话长了以后 AI 忘了前文用户不知道为什么；额度用完突然报错；工具调用的成本不透明用户不敢放开用；附件上传了但不知道 AI 是否真的看到。
- **适用**：AI 产品、按量计费工具 ｜ **不适用**：无额度概念内部工具。
- **决策点**：
  ① **上下文可见性**——"基于以上 N 条对话"提示（B50 规格）；上下文截断时明确告知"早期内容已折叠"
  ② **用量指示**——token/条数/额度的显示粒度：实时条 vs 仅不足时提示？（推荐：默认低存在，<20% 时显性化）
  ③ **附件确认**——上传的附件进入上下文有确认标记（缩略图+已读入），不是静默
  ④ **失败语义**——额度耗尽/上下文超限的错误用 inline+恢复路径（清空历史/升级），不只弹错
- **实现**：
  - 上下文条：`aria-live=off` 的静态区域，显示 "上下文：最近 12 条" 或 token 计量
  - 用量阈值：remaining <20% 显示计量；<5% 阻断前预警
  - 附件入上下文：气泡内缩略附件卡，模型确认引用才计
- **验收**：用户能说出当前上下文范围；额度不足有提前预警非突然失败；附件状态明确（已读入/未入上下文）；超限错误有恢复路径。
- **衔接**：B50（上下文窗口规格/附件展示）、B83（信任与可追溯）、G6（composer）、C6（真实状态文案）、K14·打断层级（额度预警属 banner 级）
