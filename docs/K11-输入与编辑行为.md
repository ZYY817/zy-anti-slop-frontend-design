> 覆盖 5 个决策对象：IME 组合输入保护、输入掩码与自动格式化、粘贴处理、Enter/Tab/Esc 语义、内联编辑。

## K·IME组合输入保护（IME Composition Guard）

- **领域**：输入/表单 · **成本**：低
- **定义**：输入法（拼音/日文/手写等）在组合窗口未上屏前，`compositionstart`–`compositionend` 期间浏览器看到的是中间态文本，此时不应触发提交、校验、搜索等动作。
- **症状**：拼音打字打到一半按 Enter 选词，表单却提交了；中文搜索输入时防抖搜索被每个中间字符触发（结果闪烁/请求爆炸）；组合中触发实时校验报"格式错误"；日文输入 Enter 选词发送了聊天消息。
- **适用**：一切有文本输入的产品，凡目标用户含 CJK 语言者默认必须做 ｜ **不适用**：纯英文键盘受众的密码/数字字段（仍建议做，成本极低）。
- **决策点**：
  ① **组合期屏蔽清单**——哪些行为在 `isComposing` 期间必须暂停？（Enter 提交、搜索防抖、实时校验、字符计数、快捷键）
  ② **检测方式**——`e.isComposing` / `e.keyCode === 229` 兼容、compositionstart/end 标记位、React 受控 input 的 `nativeEvent.isComposing`？
  ③ **上屏后补发**——组合结束时被跳过的校验/搜索要不要立即补一次？（要，否则用户打完没有反馈）
  ④ **Enter 双重语义**——组合中 Enter=选词、组合外 Enter=提交；判定顺序必须先查 isComposing 再查 key。
- **实现**：
  - 守卫模式：`onKeyDown(e) { if (e.nativeEvent.isComposing) return; if (e.key === 'Enter') submit(); }`
  - 搜索防抖：compositionstart 时挂起 timer，compositionend 时以最终值重启（衔接 K·搜索触发链、K3·防抖节流）
  - Vue/React 均需注意：`input` 事件在组合中也会触发，值是中间态——计数/校验/搜索都要以 compositionend 后的值为准
  - `enterkeyhint`（go/search/send/done）控制移动键盘回车键文案，与提交语义分开处理
- **验收**：拼音输入中按 Enter 选词不提交；组合中不触发搜索/校验；组合结束后校验与计数正确；日文/韩文输入法同样通过；粘贴和直接输入路径不受影响。
- **衔接**：B51§四（校验时机）、K3·防抖节流、K16·搜索触发链、G3（移动键盘 inputmode/enterkeyhint）、F4（工程约束）

## K·输入掩码与自动格式化（Input Mask / Auto-format）

- **领域**：输入/表单 · **成本**：中
- **定义**：输入过程自动把原始输入整形为目标格式（手机号 138 0000 0000、卡号 4-4-4-4、日期 / 分隔），或限制只能输入合法字符。
- **症状**：用户粘贴"13800001111"变成乱码；光标在格式化插入时跳到末尾；删除一个数字导致整段重排；掩码字段校验报错的时机与视觉格式不一致。
- **适用**：卡号/手机号/证件号/日期/金额等定长格式字段 ｜ **不适用**：自由文本（姓名/地址/搜索框）、变长国际号码（掩码假设长度会错）。
- **决策点**：
  ① **遮蔽式 vs 插入式**——固定骨架占位（`___-____`）还是只加分隔符？遮蔽式适合定长，插入式适合可变
  ② **光标维护**——格式化插入/删除后光标落在哪？（删除时应停在删除点而非跳尾）
  ③ **粘贴路径**——粘贴纯数字要不要套上格式？（要；剥离非法字符再格式化）
  ④ **存储值**——存显示值还是原始值？（存原始值，格式只是显示层）
- **实现**：
  - 分隔符策略：监听 input → strip non-digit → 按模板重排 → setSelectionRange 恢复光标
  - 数字输入优先 `inputmode="numeric"` + `pattern` 而非 `type=number`（spinner 与 e/E/+ 问题，B51/G3 已覆盖）
  - 金额类千分位用 Intl.NumberFormat 只格式化显示，输入中保持原始
- **验收**：逐键输入格式正确；光标不跳尾；中间删除位置正确；粘贴纯文本自动成形；提交的存储值无分隔符；屏幕阅读器读到的是完整值非片段。
- **衔接**：B51（校验时机、inputmode/autocomplete 表）、G4（卡号/有效期字段）、C4（读屏播报）、F4

## K·粘贴处理（Paste Handling）

- **领域**：输入/编辑 · **成本**：低
- **定义**：剪贴板内容进入输入/编辑区域时的归一化决策——剥离什么格式、如何分配、能否粘文件/图片。
- **症状**：从网页复制带格式文本贴进输入框带进不可见样式；Excel 复制多列只进了第一个格子；密码框不让粘贴（逼用户手打）；验证码分格输入粘贴只填了第一格。
- **适用**：富文本编辑器、分格输入（OTP）、表单字段、文件上传区 ｜ **不适用**：单行普通文本框的默认行为通常够。
- **决策点**：
  ① **剥格式粒度**——纯文本 only？保留换行/列表？（富文本编辑器常需 paste plain-text 模式）
  ② **多字段分配**——OTP/卡号分格：粘贴"1 2 3 4 5 6"应拆格填满还是拒收？（拆格填满）
  ③ **非文本类型**——图片/文件粘贴走附件路径还是拒收？粘贴事件里 `clipboardData.files` 非空时
  ④ **禁止粘贴的反模式**——密码/确认邮箱框禁用粘贴是负体验（C3/B84 反操控），除非有真实安全理由
- **实现**：
  - `onPaste` 里 `e.clipboardData.getData('text/plain')` 归一化；富文本额外处理 `text/html` 白名单
  - OTP 分格：在容器层监听 paste，strip 非数字后按格分配 + 聚焦最后一格
  - 文件粘贴：`clipboardData.files` 交给上传管线（衔接 G6 消息编辑器附件）
- **验收**：分格输入整段粘贴一次填满；富文本粘贴不引入脏样式；图片粘贴走附件而非插入乱码；任何输入框不被禁粘贴。
- **衔接**：B51（字段规格）、G6（composer 附件）、C4、K11·掩码（粘贴归一化共用）

## K·Enter·Tab·Esc 语义（Keyboard Semantics in Forms）

- **领域**：输入/键盘 · **成本**：低
- **定义**：表单内三个导航/提交键的行为分配——Enter 跳格还是提交、Tab 顺序、Esc 清空还是撤销。
- **症状**：搜索框按 Enter 提交了半个表单；长表单里 Enter 意外提交丢失数据；Tab 顺序跳动不合视觉顺序；Esc 在弹层里既关弹层又清空输入框。
- **适用**：一切表单、编辑器、对话框 ｜ **不适用**：无——这是基线语义。
- **决策点**：
  ① **Enter 语义**——单输入（搜索/登录）Enter=提交；多字段表单 Enter=跳下一字段还是提交？（推荐：非提交按钮字段 Enter 跳格，末字段/显式按钮才提交；textarea Enter 必须换行）
  ② **Tab 顺序**——DOM 顺序即 Tab 顺序；不要自定义 tabindex>0；视觉上两列布局想清楚单列顺序还是行优先
  ③ **Esc 语义**——弹层里 Esc 只关最上层（衔接 B76 焦点栈）；输入框内 Esc=撤销本次编辑值还是清空？（撤销更安全）
  ④ **防意外提交**——`type="submit"` 按钮位置 + `preventDefault` on Enter；单按钮表单最易踩
- **实现**：
  - 表单内非 submit 控件 `onKeyDown` Enter → `e.preventDefault()` + focus 下一个 `tabIndex` 元素
  - `enterkeyhint="next|go|send|search"` 给移动键盘正确语义
  - Esc 分层处理：浮层捕获 stopPropagation，输入框只做值回滚
- **验收**：多字段表单 Enter 不意外提交；Tab 顺序与视觉一致；Esc 只作用最上层；textarea Enter 换行；IME 组合中上述全部不触发（K·IME）。
- **衔接**：B76（焦点管理/焦点归还）、K11·IME、C4、D4（disabled/readonly 态跳过聚焦）

## K·内联编辑决策（Inline Editing）

- **领域**：编辑/交互 · **成本**：中
- **定义**：在内容所在位置就地进入编辑态（双击标题改名、表格单元格点进编辑），而不是弹窗或跳页。
- **症状**：单击文本想选中却进了编辑；blur 一下就自动保存了半成品；编辑中容器宽度突变导致内容跳动；Esc 取消后旧值没恢复。
- **适用**：重命名（文件/列表项）、表格单元格微调、个人资料单字段、看板卡片 ｜ **不适用**：多字段关联表单（用表单页/Drawer）、富文本长内容（用编辑器）、高风险字段（金额/权限——要显式确认）。
- **决策点**：
  ① **进入方式**——单击文本/双击/铅笔钮/hover 显现按钮？（高频改名=双击或铅笔钮；表格单元格=单击或双击，与选中行为冲突时选后者）
  ② **提交语义**——blur 即存 vs Enter 存 + Esc 取消？（推荐 Enter/blur 提交、Esc 恢复旧值；blur 提交要小心 IME 与点击无关区域）
  ③ **布局稳定性**——进入编辑后控件尺寸必须预占（width 继承/固定高），不允许撑开跳动
  ④ **脏标记与失败**——未保存离开提示？保存失败恢复编辑态保留输入？
- **实现**：
  - 视图态/编辑态双渲染；编辑态初始全选文本（`select()`）便于整改
  - Enter/blur 提交差异：值未变不请求（省流量，衔接 K·异步请求链防重）
  - 失败时保持编辑态 + 内联错误（不弹 toast 丢上下文）
- **验收**：双击/铅笔进入、Enter 存、Esc 恢复旧值；编辑中无布局跳；失败不丢输入；与行选中/拖拽手势不冲突（进入编辑不触发选中切换）。
- **衔接**：K13·单元格编辑（表格特化）、C5（占位与错误文案）、G5（块编辑器）、K11·Enter语义
