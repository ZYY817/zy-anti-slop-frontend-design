# C1 · 信息架构

> 信息架构（IA）决定用户能不能"找到"东西。好 IA 是隐形的。

---

## 一、信息架构定义

**Information Architecture** — 组织、结构化、标记内容的艺术，让用户能高效找到信息、完成任务。

**四大系统（Rosenfeld & Morville）**：
1. **组织系统** — 内容如何分类
2. **标签系统** — 如何命名
3. **导航系统** — 如何浏览
4. **搜索系统** — 如何查找

---

## 二、组织结构（Organization Schemes）

### 精确型（Exact）
- **字母** — A-Z（联系人、词典）
- **时间** — 时间线（历史、日志）
- **地理** — 位置（门店、地图）

### 模糊型（Ambiguous，更常用）
- **主题** — 按内容类别（新闻分类）
- **任务** — 按用户目标（"我想..."）
- **受众** — 按用户群体（学生/教师/管理员）
- **隐喻** — 借用现实概念（桌面、购物车、收件箱）

### 组织结构形态
- **层级 (Hierarchy)** — 树状，最常见
- **矩阵 (Matrix)** — 多维度交叉
- **线性 (Sequential)** — 步骤流程
- **网状 (Web)** — 超链接自由跳转

---

## 三、导航系统

### 类型
- **全局导航** — 全站可见（顶部/侧边）
- **局部导航** — 当前区域内
- **上下文导航** — 相关链接（"你可能喜欢"）
- **辅助导航** — 页脚、站点地图、面包屑

### 导航深度
- **广度优先** — 扁平，一屏多选项（希克定律要控制）
- **深度优先** — 层级深，每层选项少
- **黄金法则** — 尽量 ≤3 层点击到达任何内容

### 导航模式
详见 C2。

---

## 四、标签系统（Labeling）

### 原则
- **用用户的语言** — 不用内部黑话
- **一致性** — 同一概念一个名字
- **具体** — "定价"而非"选项"
- **可扫描** — 短、清晰

### 标签来源
- 用户研究（卡片分类法）
- 竞品对标（雅各布定律）
- 搜索日志（用户实际搜什么词）

---

## 五、内容策略

### 内容审计
- 盘点现有内容
- 评估质量与相关性
- 决定保留/更新/删除

### 内容模型
- 定义内容类型（文章/产品/用户）
- 定义字段（标题/正文/标签/作者）
- 定义关系（文章属于分类）

### 内容层级
- **主要内容** — 用户主要目标
- **次要内容** — 支撑信息
- **元数据** — 时间、作者、标签

---

## 六、研究方法

### 卡片分类法 (Card Sorting)
让用户把内容卡片分组，发现他们的心智模型。
- **开放式** — 用户自由分组并命名
- **封闭式** — 预设分类，用户归类
- **混合式** — 预设 + 可新增

### 树测试 (Tree Testing)
给用户任务，看他们在导航树里能否找到目标。
- 验证 IA 是否合理
- 测量成功率、路径、耗时

### 用户旅程图 (Journey Map)
可视化用户完成目标的全过程，标注触点、情绪、痛点。

### 用户流程图 (User Flow)
用户在产品中的路径，决策点和分支。

## 七、导航设计模式

### 桌面
- 顶部水平导航（≤7 项）
- 左侧栏导航（功能多）
- 超级菜单（大量分类）
- 面包屑（深层级）

### 移动
- 底部标签栏（3-5 核心）
- 汉堡菜单（次要）
- 手势导航

### 常见结构
```
扁平结构（适合内容少）：
首页 → [关于 | 产品 | 定价 | 博客 | 联系]

层级结构（适合内容多）：
首页
├── 产品
│   ├── 功能 A
│   └── 功能 B
├── 解决方案
│   ├── 按行业
│   └── 按规模
└── 资源
    ├── 博客
    └── 文档

中心辐射（适合任务型）：
仪表盘（中心）
├── → 项目
├── → 团队
├── → 设置
└── 各自返回仪表盘
```

## 八、搜索系统

### 组成
- 搜索框
- 自动补全/建议
- 搜索结果页
- 筛选/排序
- 无结果处理
- 搜索历史

### 搜索体验
- 即时搜索（输入即结果）
- 拼写容错
- 同义词处理
- 高亮匹配词
- 结果分类（分面）
- 搜索分析（改进内容）

## 九、URL 与信息架构

好的 URL 反映 IA：
```
✅ /products/laptops/macbook-pro
✅ /blog/2025/design-systems
❌ /page?id=12345
❌ /p/x8f2k
```

原则：
- 语义化、可读
- 反映层级
- 稳定（不轻易改，改了要 301）
- 小写、连字符分词

---

## 十、面包屑

### 类型
- **位置型** — 显示层级位置（首页 > 产品 > 笔记本）
- **路径型** — 显示访问路径（较少用）
- **属性型** — 显示筛选属性（价格：100-500 > 品牌：Apple）

### 规则
- 最后一项是当前页（不可点）
- 首项通常是首页
- 超长可折叠中间项

---

## 十一、常见错误

- ❌ 分类重叠（一个东西不知放哪类）
- ❌ 分类太多（希克定律，决策困难）
- ❌ 层级太深（>3 层难找）
- ❌ 标签用内部黑话
- ❌ 导航项不一致
- ❌ 无搜索（内容多时）
- ❌ 无面包屑（深层级迷路）
- ❌ 孤儿页面（无导航可达）

---

## 十二、Prompt 表达模板

```
【信息架构】：
- 组织方式：按{任务/主题/受众}组织
- 导航结构：{扁平 5 项 / 层级 3 层}
- 全局导航：顶部 [首页|产品|方案|定价|资源]（≤5 项）
- 移动端：底部标签栏 4 项核心 + 汉堡收纳次要
- 深层页面：面包屑导航
- 搜索：全局搜索 + 即时联想 + 分面筛选
- URL：语义化，反映层级 (/products/category/item)
- 任何内容 ≤3 次点击可达
```

## 检验清单

- [ ] 分类互斥、无重叠
- [ ] 导航项 ≤7（每层）
- [ ] 层级 ≤3
- [ ] 标签用用户语言
- [ ] 核心内容 3 次点击内可达
- [ ] 有搜索（内容多时）
- [ ] 深层有面包屑
- [ ] URL 语义化
- [ ] 无孤儿页面
