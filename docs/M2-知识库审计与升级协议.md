# M2 · 知识库审计与升级协议

> **定位**：AI Frontend Prompt Knowledge System 的总控协议。用于理解现有知识库、识别真实缺口、升级已有文档，并持续把知识转化为可执行的前端设计能力。
>
> **核心原则**：先建立全库认知，再做局部升级；优先提升 AI 的判断、组合和验证能力，而不是增加 Markdown 数量。

---

## 一、可直接交给 Coding Agent 的总控 Prompt

```markdown
# ZY'S ANTI-SLOP FRONTEND DESIGN · EVOLUTION PROTOCOL

你负责维护一个已经存在的 ZY's Anti-Slop Frontend Design 知识库。
当前项目中的 Markdown 是现有知识资产，不要把任务理解成从零创建 Prompt 集合。

## 你的首要任务

1. 扫描项目中的全部相关 Markdown，实际读取内容，不根据文件名猜测。
2. 为每个文件记录：核心主题、知识层级、适用场景、执行指令、反模式、验证方式、依赖、冲突、重复和升级空间。
3. 建立 Knowledge Map，并把知识区分为：Knowledge → Principle → Pattern → Prompt → Preset → Validation → Evolution。
4. 审计 Visual、Content、UX、Interaction、Brand、Media、AI/Agent、Accessibility、Performance、Frontend Engineering 等维度。
5. 找出重复、薄弱、缺失和无法直接执行的内容。
6. 优先升级已有高价值文件；只有确认缺口无法由合并、拆分或改写解决时，才新增文件。

## 禁止事项

- 不为数量创建文件。
- 不重复已有定义或只增加形容词词库。
- 不把所有文档一次性塞进最终 Prompt。
- 不只输出“建议”，发现问题必须修改相关文件或生成结果。
- 不把视觉装饰放在产品目标、内容真实性、可用性、无障碍和性能之前。

## 每次审计必须回答

- Current Knowledge Map：已经覆盖什么，哪些是主干，哪些是扩展。
- Missing Dimensions：完全缺失且会显著影响前端生成的能力。
- Weak Dimensions：有内容但没有原因、参数、组合、验证或反模式。
- Duplicate Dimensions：重复内容，以及应该建立的主文档/扩展文档/验证文档关系。
- High-Value Upgrade：最值得升级的已有文件和理由。
- New Knowledge：只有确认必要时才提出新增内容。
- New Prompt Systems：检索、组合、冲突、压缩、评估、版本和进化能力。
- Knowledge Architecture：未来知识如何组织、调用和回写。
- Priority Roadmap：P0 / P1 / P2 / P3，并说明影响和依赖。

## 修改顺序

Analyze → Classify → Compare → Detect Duplicate → Detect Gap → Extract Principle
→ Convert to AI Instruction → Score → Connect → Compose → Validate → Improve

## 完成标准

每项升级都必须说明：修改了哪个文件、解决了什么 AI 决策问题、如何调用、如何验证、是否引入新的冲突。
```

## 二、文档能力契约

每篇知识文档不要求立刻重写成完全相同的格式，但升级时应尽量补齐以下信息：

```yaml
id: B77
title: 前端视觉艺术指导系统
layer: pattern              # knowledge / principle / pattern / prompt / preset / validation / evolution
capabilities: [art-direction, visual-narrative, brand]
use_when: [营销落地页, 品牌首页, 有主视觉的产品页]
inputs: [product-goal, audience, brand-tone, media-availability]
outputs: [visual-concept, motif, art-direction-tokens, implementation-constraints]
must_include: [可执行参数, 组合方式, 反模式, 验证清单]
depends_on: [A1, B54]
extends: [B78, B79, B80]
conflicts_with: []
priority: high
maturity: tested              # draft / usable / tested / canonical
```

升级文档时至少要把“是什么”转成下面的闭环：

```text
原则 → 适用条件 → 设计决策 → 参数/代码表达 → 反模式 → 验证问题
```

### 价值评分

用 0-5 分给每个模块评分：

| 维度 | 问题 |
|---|---|
| Impact | 是否明显改变最终产品质量？ |
| Executability | AI 能否直接据此做出设计或代码决策？ |
| Specificity | 是否有参数、条件、例子，而不是形容词？ |
| Reusability | 是否适用于多个真实项目？ |
| Compatibility | 是否能与现有技术栈、无障碍和性能约束共存？ |
| Verification | 是否能被截图、代码、交互或数据检查验证？ |

建议优先升级：`Impact + Executability + Verification ≥ 12` 的模块。

## 三、全库审计维度

### Visual Intelligence

Composition、Art Direction、Hierarchy、Rhythm、Balance、Spatial Design、Typography、Color、Material、Texture、Shape、Geometry、Lighting、Depth、Contrast、Scale、Proportion、Density、Negative Space、Optical Alignment、Gestalt、Attention、Emotion、Brand、Narrative、Metaphor、Editorial、Photography、Illustration、Motion Graphics、3D、Generative Visuals、Data Visualization、Spatial UI、AI-native UI。

检查重点不是“有没有这些词”，而是 AI 是否能据此决定：删什么、强调什么、怎样组合、用什么参数实现、如何验证。

### Content Intelligence

Information Architecture、Content Hierarchy、Content Density、Content Strategy、UX Writing、Microcopy、CTA、Metadata、Realistic Data、Empty/Error/Loading Content、Onboarding、Notification、Status、Personalization、Content Length、Multilingual、Localization、Cultural Context。

重点检查：页面是否有真实内容模型、合理数据形态、状态文案和翻译伸缩，而不只是漂亮占位文案。

### Product / Interaction / Engineering

核心任务、用户路径、导航、反馈、权限、信任、失败恢复、可撤销、响应式重组、键盘操作、屏幕阅读器、Core Web Vitals、渲染精度、组件复用、设计令牌和维护成本。

## 四、升级和新增的决策门

### 先升级已有文件

当问题是以下情况时，优先修改原文件：

- 只有定义，没有 Prompt 模板或实现参数。
- 有 Prompt，但没有适用条件、反模式或验证。
- 内容分散在多个文件，重复率高但各自没有独特价值。
- 文件只讲视觉，没有内容、状态、响应式或工程边界。
- 文件把“高级、现代、惊艳”等低信息密度形容词当成主要指令。

### 只有满足以下条件才新增

1. 该能力会显著改变 AI 的设计决策；
2. 现有文件没有合理的归属；
3. 不能通过合并、拆分或加一个可执行章节解决；
4. 新文件有明确的输入、输出、依赖、调用场景和验证方式；
5. 总索引能把它接入检索路径。

## 五、审计交付格式

```markdown
# Knowledge Base Audit · YYYY-MM-DD

## 1. Current Knowledge Map
## 2. Missing Dimensions
## 3. Weak Dimensions
## 4. Duplicate Dimensions
## 5. High-Value Upgrade
## 6. New Knowledge
## 7. New Prompt Systems
## 8. Knowledge Architecture
## 9. Priority Roadmap

| ID | 文件 | 问题 | 改动 | AI 决策收益 | 验证方式 | 优先级 |
|---|---|---|---|---|---|---|
```

### P0-P3 定义

- **P0**：会让大多数生成结果失败、半成品或无法使用；立即修复。
- **P1**：高频且显著影响质量，或阻断检索/组合/验证；本轮处理。
- **P2**：提升深度、差异化或特定场景质量；按需处理。
- **P3**：实验性、边缘场景或资料性增强；不阻塞主流程。

## 六、持续进化闭环

每次生成失败都要先判断失败属于哪类：

```text
视觉方向错 → 更新视觉 Pattern 或 Preset
内容不真实 → 更新 C6 内容模型/数据例子
状态缺失 → 更新状态 Pattern 或 Z3 检查项
Prompt 太长 → 更新 Z2 检索/压缩规则
指令冲突 → 更新依赖、优先级或冲突表
实现不可用 → 更新 F 工程约束或验证规则
```

只把可复现、可验证、能改善下一次生成的问题回写知识库；一次性的主观偏好不要直接升级为通用规则。

## 七、进入实战压测后的规则

当知识库已经完成一轮建设后，停止以“继续找缺口”为主要任务，改用 [T1-前端能力压测基准.md](T1-前端能力压测基准.md)：

```text
Benchmark → V0 Native → V1 Knowledge → Z3 → V2 Iterated
→ Compare Evidence → Locate Failure → Upgrade Existing Rule → Re-run
```

没有可运行页面、截图、交互记录或代码证据时，不得填写能力分数，也不得因为知识库文件数量多而推断能力强。
