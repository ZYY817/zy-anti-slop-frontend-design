# K3 · 悬停与指针微观判定

> "鼠标划过去"这件小事里藏着一整套判定逻辑：是真悬停还是路过？等多久响应？响应多久？离开后怎么收？
> 这些概念原散见 R11、V9、B45、G5、B65，本文件聚合为决策对象。

---

## K·悬停意图（Hover Intent）

- **领域**：交互 · **成本**：中
- **定义**：区分"用户想悬停这个元素"和"指针恰好路过"——路过不该触发 hover 反馈（菜单、tooltip、预览卡）。
- **症状（怎么知道这里有问题）**：鼠标划过导航去点别处时，下拉菜单连环闪开（mega menu 悲剧）；tooltip 在指针掠过时弹出又消失；hover 出现的浮层还没移上去就没了。
- **决策点**：
  ① **意图判定**——延迟触发（hover 持续 ≥150-300ms 才算）vs 轨迹预测（指针向目标移动才算，Amazon 经典解法）vs 意图三角（允许指针切向子菜单的三角形区域不触发移出）？
  ② **触发后行为**——已展开的菜单在指针斜切去子项时不关闭；
  ③ **取消条件**——悬停判定中途移出是否取消计时；
  ④ **多目标竞争**——相邻 hover 目标切换时是否有滞后带。
- **实现**：简单场景 `transition-delay: 0` on enter / `transition-delay: 300ms` on leave（R11 的 hover-out 防抖）；复杂场景记录 pointermove 向量做轨迹预测；mega menu 用意图三角。
- **验收**：快速划过不误触发；斜切到子菜单不丢；慢速悬停正常触发；反复进出无抖动。
- **衔接**：R11（hover-out 延迟防抖）、B53（导航 mega menu）、B76（menu ARIA）、K·悬停延迟

## K·悬停延迟（Hover Delay）

- **领域**：交互/动效 · **成本**：低
- **定义**：悬停反馈的进入延迟与离开延迟——进入要快（确认感），离开要慢（容错）。
- **症状**：hover 反馈立即消失导致"闪烁"；tooltip 太急于弹出显得神经质；hover 浮层移出即关，用户来不及移过去。
- **决策点**：
  ① **进入延迟**——即时反馈类（按钮变色）=0ms；弹层类（tooltip）=300-500ms 确认意图后出；
  ② **离开延迟**——浮层 200-400ms 缓冲让用户移过去；纯视觉反馈可 0ms；
  ③ **不对称缓动**——进入 ease-out（快响应）、离开 ease-in（慢淡出）或反之？
  ④ **打断行为**——进入延迟中移出，要不要完全跳过动画（B45：反馈必须 <100ms 先给，再等数据）。
- **实现**：
  ```css
  .tip { transition: opacity 150ms ease-out 0ms; }        /* 进入：快 */
  .tip:not(:hover) { transition-delay: 300ms; }            /* 离开：慢 */
  ```
- **验收**：高频划过不闪；tooltip 不会在路过时弹出；浮层可从触发元素平移过去不丢。
- **衔接**：R11（transition-delay 防抖）、B45（反馈延迟分级）、K·悬停意图

## K·防抖与节流（Debounce vs Throttle）

- **领域**：交互/工程 · **成本**：低
- **定义**：两个被混用的高频事件控制手段——防抖=静止一段时间才执行（合并连续触发为一次）；节流=固定频率上限执行（稀释触发频率）。
- **症状**：搜索框每敲一个字母就发请求；resize 事件里跑重布局导致卡顿；scroll 里跑复杂计算掉帧；把防抖用在该持续响应的场景（拖动跟手用了 debounce = 卡死）。
- **决策点**：
  ① **选哪个**——要"最终结果"用防抖（搜索建议 ~300ms、resize 重算 ~150ms、自动保存 ~1s）；要"过程持续反馈"用节流（滚动进度、指针视差、拖拽位置广播 ~16-100ms）；
  ② **前缘还是后缘**——leading（立即执行一次再等待）vs trailing（等静默后执行）；按钮防连点用 leading，搜索用 trailing；
  ③ **等待时长**——输入类 250-400ms（G5 搜索 300ms）、视觉类 ≤100ms、动画类用 rAF 不用 throttle；
  ④ **取消语义**——组件卸载/新输入到达时取消挂起的 debounce。
- **实现**：动画相关用 `requestAnimationFrame`（天然节流）；搜索 `debounce(fn, 300)`；scroll 监听优先 IntersectionObserver（脱离高频事件，R9 取舍）。
- **验收**：连续输入只触发一次请求；拖拽跟手 1:1 无迟滞（该用节流处没用防抖）；scroll 处理不在每帧跑重计算。
- **衔接**：G5（搜索 300ms）、R9（IntersectionObserver 替代 scroll）、F3（性能预算）、K7·事件委托、K9·响应式vs自适应 类辨析

## K·悬停追踪（Hover Tracking）

- **领域**：交互/视觉 · **成本**：中
- **定义**：根据指针在元素内的位置持续改变视觉状态——跟随式高光、3D 倾斜、指针视差、聚光灯。
- **症状**：追踪生硬（瞬移跟随，缺阻尼）；卡片 tilt 角度过大失真；离开元素后视觉残留不复位；每帧触发 layout 卡顿。
- **决策点**：
  ① **跟随阻尼**——直接 1:1（生硬）还是 lerp 阻尼跟随（`pos += (target - pos) * 0.12`，R11·F1/R20 磁吸跟随）？
  ② **强度上限**——tilt ≤10deg、translate ≤8px、视差偏移 ≤12px（V9/B45 克制原则）？
  ③ **复位方式**——指针离开后 spring 回中还是渐隐归零？
  ④ **更新通道**——CSS 变量 + transform（GPU 合成层），绝不每帧改 layout 属性。
- **实现**：pointermove → 写 `--mx/--my` 变量 → transform/gradient 消费；lerp 0.12 阻尼；`@media (hover:none)` 禁用。
- **验收**：60fps 无掉帧；离开复位；触屏禁用无残留；reduced-motion 下关闭。
- **衔接**：R11·F1（阻尼跟随/磁吸）、V9（tilt/spotlight/shine 配方）、B81（合成层渲染）、K·磁性光标

## K·磁性光标（Magnetic Cursor）

- **领域**：交互/动效 · **成本**：低
- **定义**：自定义光标本身被附近可交互元素吸引、变形——光标成为界面角色而非系统图标。
- **症状**：光标被吸走后用户不知道实际点击点在哪；变形遮挡目标元素；原生光标与自定义光标双显/冲突。
- **决策点**：
  ① **吸引规则**——同 K·磁性吸附（120px 半径/8px 上限/平方衰减），但对象是光标层；
  ② **点击精度**——视觉光标偏移时，实际 hit-test 点跟原生光标还是跟视觉光标（必须跟原生）；
  ③ **形态变化**——hover 可点元素时放大 2.5×/显示动作词（R11·F1 双层光标：内点即时+外环阻尼 0.12）；
  ④ **降级**——`hover:none`/`prefers-reduced-motion`/无 JS 时回退原生光标。
- **实现**：内层小点即时跟随 + 外层环 lerp 跟随；`cursor:none` 只对桌面；mix-blend-mode: difference 保证任何底色可见。
- **验收**：点击位置精确（以原生光标为准）；blend 模式保证跨色可见；触屏完全无自定义层。
- **衔接**：R11·F1（双层光标配方）、V9（光标跟随/磁性光标）、R17（光标作为角色）、K·磁性吸附

## K·自定义光标（Custom Cursor）

- **领域**：交互/视觉 · **成本**：中
- **定义**：用自定义视觉替换系统光标——语义光标（拖手/放大镜/十字）、品牌光标、情境光标（hover 图片显示 "View"）。
- **症状**：用户找不到光标；光标与可点区域错位；`cursor:none` 但 JS 失败=完全没光标；文本输入场景自定义光标遮挡插入点。
- **决策点**：
  ① **必要性**——纯装饰光标 vs 传递语义（拖拽中显示 grabbing、图片区显示 zoom）？纯装饰建议不做；
  ② **可用性底线**——任何状态知道自己在点什么（V9 坑：必须保证可用性）；
  ③ **系统光标处理**——`cursor:none` + JS 层，还是 `cursor: url()` 保留系统热区语义？
  ④ **文本场景**——输入框内恢复 `cursor: text`。
- **实现**：语义场景优先 `cursor: pointer/grab/grabbing/zoom-in` 原生值；视觉光标用双层结构（K·磁性光标）；JS 失败时 `<noscript>` 回退。
- **验收**：所有可交互态有光标语义；原生光标无闪烁双显；可访问性工具仍识别元素角色。
- **衔接**：V9（光标效果）、R11·F1、R17（光标作为角色）、C4（指针无障碍）

## K·触屏无 hover（Hover-less Degradation）

- **领域**：交互/工程 · **成本**：低
- **定义**：触屏没有真正的 hover——`hover` 态要么粘住、要么首次点击触发、要么完全不触发。所有 hover 承载的信息/功能必须有替代路径。
- **症状**：手机上点一下按钮"卡住"在 hover 态；hover 才显示的菜单在手机上永远打不开；卡片 hover 显示的详情在手机上看不见。
- **决策点**：
  ① **hover 承载物分级**——装饰性（变色/阴影）=触屏可无；信息性（tooltip/详情）=必须替代（长按/展开钮）；功能性（hover 才出现的按钮）=必须改为常驻或点击展开；
  ② **粘滞清除**——`:active` 结束后 hover 残留态用 JS `touchend` 清或用 `@media (hover:hover)` 隔离；
  ③ **长按语义**——hover 预览的触屏等价物是长按 500ms + haptic（G3）；
  ④ **媒体查询写法**——`@media (hover: hover) and (pointer: fine)` 才是桌面判定，不是屏宽断点。
- **实现**：
  ```css
  @media (hover: hover) {
    .card:hover .overlay { opacity: 1; }
  }
  @media (hover: none) {
    .card .overlay { display: none; }  /* 改常驻入口或点击展开 */
  }
  ```
- **验收**：触屏遍历一遍——无 hover 粘滞、无 hover 独占功能、长按路径可达；iPad（有鼠标有触屏）双指针模式都正常。
- **衔接**：B65 坑5（移动端 hover）、G3（长按 500ms+haptic）、R11（触屏不做 hover）、B30（响应式输入方式）
