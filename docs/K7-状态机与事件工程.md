# K7 · 状态机与事件工程

> 交互 Bug 的两大根源：状态没有显式建模（"半开"态满天飞）和事件体系乱接（监听器地狱+指针类型分裂）。
> 本文件聚合交互状态机、事件委托、Pointer Events、插值器、渲染管线五个工程词条——它们决定上面 K1-K6 的决策能否正确落地。

---

## K·交互状态机（Interaction State Machine）

- **领域**：工程/交互 · **成本**：中
- **定义**：把组件交互建模为有限状态+显式转移——`idle → hover → pressed → dragging → dropping → invalid`，而非一堆 boolean 散落各处。
- **症状（怎么知道这里有问题）**：组件同时处于"loading 又 error"的矛盾态；拖拽中点击触发了 click handler；hover 态在 drag 开始后残留；改一个状态要翻五个 flag。
- **决策点**：
  ① **状态枚举**——先穷举所有真实状态再写代码（拖拽六态见 K4 速查表）；
  ② **转移条件**——每个箭头写清"什么事件+什么条件下允许转移"（pressed →dragging 需要超过拖动阈值）；
  ③ **非法转移**——显式声明不可能的转移（loading 中不许进入 editing），非法事件被吞而非产生未定义行为；
  ④ **副作用归属**——进入某状态时统一执行该态的视觉/音效/haptic，而非散在事件 handler 里。
- **实现**：简单组件用 `switch(state, event)` reducer；复杂交互用 XState/状态图；React 中 `useReducer` 替代多 `useState`。
- **验收**：画得出完整状态图；任何事件序列下不出现矛盾态；中断恢复后回到合法态（配合 K5·中断状态一致性）。
- **衔接**：D4（状态×变体矩阵穷举）、B73（四态齐全）、B14（边界态）、K5·中断状态一致性

## K·事件委托（Event Delegation）

- **领域**：工程 · **成本**：低
- **定义**：不给每个子元素挂监听，而是在共同祖先上挂一个，通过 `event.target` 分发处理——动态列表、大型表格的标准做法。
- **症状**：动态添加的列表项事件失效（监听器挂在旧节点上）；一万行表格每行三个监听=三万个 handler；解绑遗漏内存泄漏。
- **决策点**：
  ① **何时委托**——子元素多/动态增删/同类型 handler → 委托；单个复杂组件 → 直接挂；
  ② **定位目标**——`event.target.closest('[data-action]')` 而非脆弱的 class 判断；
  ③ **委托边界**——委托挂在"稳定存在的最近祖先"上（列表容器，不是 document，防全局误伤）；
  ④ **不冒泡事件**——focus/blur/mouseenter/leave 不冒泡，委托需用捕获阶段或 focusin/focusout 替代。
- **实现**：
  ```js
  list.addEventListener('click', e => {
    const item = e.target.closest('[data-id]');
    if (!item) return;
    handleItem(item.dataset.id, e);
  });
  ```
- **验收**：动态增删项事件即插即用；性能 profile 无监听爆炸；键盘等效操作同样覆盖。
- **衔接**：F1（DOM 事件基础）、K·Pointer事件、K3·悬停意图（委托+意图判定组合）

## K·Pointer 事件（Pointer Events API）

- **领域**：工程/交互 · **成本**：低
- **定义**：统一鼠标、触摸、触控笔的事件模型——`pointerdown/move/up/cancel` 一套代码覆盖所有指针类型，不再 mouse/touch 两套。
- **症状**：自定义拖拽在手机上失效（只绑了 mouse 事件）；触摸拖动触发页面滚动抢事件；pointercancel 没处理导致拖动态僵尸；双指缩放时单指拖拽还在响应。
- **决策点**：
  ① **pointerType 分流**——`e.pointerType === 'touch'` 时是否要不同阈值/反馈（触屏阈值更大，K4·拖动阈值）；
  ② **pointer capture**——`setPointerCapture` 把后续事件锁定到拖拽元素（指针划出元素也继续收事件，拖拽必需）；
  ③ **touch-action CSS**——`touch-action: none/pan-x/pan-y` 声明元素允许的默认手势，自定义拖拽区必须显式禁默认；
  ④ **cancel 收尾**——`pointercancel`（系统抢事件/来电/手势接管）必须按"无效放下"收尾，不是按成功松手。
- **实现**：自实现拖拽/滑动的标准骨架 `pointerdown → setPointerCapture → pointermove → pointerup/pointercancel`；多指场景跟踪 `e.pointerId` 集合。**capture 时机按热区分流**：专用抓手区（已 `touch-action:none` 声明放弃滚动）可 pointerdown 即捕；整面可拖且需保留点击/选中/滚动的表面，armed 态先挂 window 级 move/up 监听，过拖动阈值再 capture——否则阈值内松手的 click 语义与滚动仲裁被破坏（与 K4·拖动阈值统一口径）。
- **验收**：鼠标/触屏/触控笔三设备行为一致；pointercancel 后状态干净；拖拽不触发页面滚动。
- **衔接**：K4 拖拽全链路（全部用 Pointer Events）、K1·命中区域、G3（手势/触控）

## K·插值器（Interpolator）

- **领域**：工程/动效 · **成本**：低
- **定义**：把"进度 0→1"映射为"属性值 A→B"的函数——动画的一切都是插值：位置、颜色、角度、路径。
- **症状**：颜色插值走 RGB 导致中间变灰（应走 oklch/hsl）；角度插值走短路径错（350°→10° 绕远路）；进度直接用时间未过缓动函数（linear 手感）。
- **决策点**：
  ① **插值空间**——颜色在 oklch/lch 插值（`linear-gradient(in oklch, …)`，B17），尺寸在 px/%/视口单位一致空间插值；
  ② **数值域处理**——角度取最短路径（模 360）、路径点按弧长均匀采样、数字按 tabular-nums 对齐；
  ③ **嵌套插值**——先时间插值（easing: t→p）再值插值（p→value），两层别混；
  ④ **离散值**——visibility/display 等不可插值属性的处理（0% 或 100% 处切换，用 `steps()` 或 JS）。
- **实现**：`lerp(a, b, t) = a + (b-a)*t`；spring 是"按物理模型求下一帧值"而非时间插值（辨析见 K9·缓动vs弹簧）；CSS `calc()` + 自定义属性可写简单插值。
- **验收**：颜色过渡无脏灰；路径动画匀速；数字滚动位宽不抖（tabular-nums）。
- **衔接**：B17（oklch 渐变）、R12（物理插值/lerp 阻尼）、B60（tabular-nums）、K9·缓动vs弹簧辨析

## K·渲染管线（Rendering Pipeline）

- **领域**：工程/性能 · **成本**：中
- **定义**：浏览器把代码变成像素的过程：`DOM + CSSOM → Render Tree → Layout（重排） → Paint（重绘） → Composite（合成）`。不同改动触发不同深度的管线，成本天差地别。
- **症状**：动画改 width/top 引发每帧重排（卡）；`will-change` 滥用内存爆；强制同步布局（读写交替，layout thrashing）；元素都在一个合成层互相牵连重绘。
- **决策点**：
  ① **动画属性白名单**——只动画 `transform`/`opacity`（合成层，跳过 layout/paint）；filter/clip-path 次选；width/height/top/left/margin 禁动画（R9/B45 反复强调）；
  ② **图层策略**——`will-change`/`transform: translateZ(0)` 升层只在动画期间用，用完撤（层太多耗显存）；
  ③ **读写分离**——先批量读（getBoundingClientRect/offsetWidth）再批量写，避免强制同步布局；
  ④ **长任务拆分**——主线程大计算（>50ms）拆 chunk 或用 worker，保证 rAF 按时跑。
- **实现**：性能排查顺序——DevTools Performance 录帧 → 看掉帧处是 Layout/Paint/Composite 哪段 → 对应策略修。
- **验收**：动画稳定 60fps（INP/LCP 达标，F3）；滚动中无长 Layout；层数量可解释。
- **衔接**：R9（transform/opacity 白名单/重排重绘规则）、B81（渲染精度/合成层）、F3（CWV/性能预算）、B5（will-change）、K9·重排vs重绘辨析
