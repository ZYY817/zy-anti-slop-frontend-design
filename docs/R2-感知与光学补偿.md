# R2 · 感知与光学补偿（提示词库 K 组）

> 定位：**数值正确 ≠ 视觉正确。** 眼睛不是尺子——本文讲人眼如何接收画面，以及如何补偿人眼的"不准"，是"高手和普通人"最大的差距所在。
> 覆盖层：L5 髓（贯穿全部；单个条目另标其主导层级 L0–L5）。
> 条目卡格式：**名称（英文）** · L层级 · 难度档位 · 成本 →（现象／视觉收益／同族拓展／提示词片段，视条目取舍）。
> 来源：融合自外部「视觉提示词库 K 组」（v1.x，2026-08-16），系忠实迁移 + 规范适配；技术参数与英文术语保持原样。

---

## 使用说明

前面所有组都在讲"生成什么"。K 组讲的是**人眼如何接收它**，以及如何补偿人眼的"不准"。

这一组的所有条目都有一个共同点：**代码里的数值是"错"的，但看起来是对的**。这正是它高级的原因——普通人写"数学上正确"的代码，高手写"视觉上正确"的代码。

三个基本事实：
1. 人眼对**明度**比对色相敏感得多（所以灰度测试有效）
2. 人眼有**同时对比**效应——同一个颜色在不同背景上看起来不同色
3. 人眼判断"大小"和"对齐"用的是**视觉重心**，不是外接矩形

```
K1 视错觉与同时对比        K4 预注意加工
K2 光学对齐与形状补偿      K5 辨识度与记忆
K3 对比度与可读性算法      K6 注意力与认知负荷
```

## K1 视错觉与同时对比（Illusions & Simultaneous Contrast）

**同一个数值，在不同环境下看起来不同。** 不补偿就会"总觉得不对"。

- **同时对比（Simultaneous Contrast）** · L5 · 进阶 · 成本:低
  - 现象：同一灰色在深底上显亮、在浅底上显暗；同一颜色被互补色包围时显得更饱和
  - 视觉收益：意识到这点后，你会给不同背景上的同类元素**不同的实际色值**，而不是硬套同一个 token
  - 同族拓展：Albers 色彩交互、chromatic induction、White's illusion、Cornsweet 错觉
  - 提示词片段：`同一语义色在深浅背景上分别调整实际值（深底上降 5% 明度、浅底上升 5%），不硬套同一 token`

- **光渗与视觉加粗（Halation / Irradiation）** · L5 · 进阶 · 成本:低
  - 现象：**浅色文字在深色背景上看起来比同字重的深色文字在浅背景上更粗**
  - 视觉收益：深色模式下降字重才"看着一样"
  - 同族拓展：见 `R10·I1` GRAD 轴、`R10·I7` 暗色模式排印、`-webkit-font-smoothing`
  - 提示词片段：`深色模式下文字字重降一档（400→350）或用 GRAD -25；细描边在深底上加粗 0.5px`

- **马赫带（Mach Bands）** · L5 · 进阶 · 成本:低
  - 现象：两个色块交界处，人眼会感知到不存在的亮边/暗边
  - 视觉收益：解释了为什么大面积渐变会显出"带"（即使数值上是连续的）——所以抖动才必要
  - 同族拓展：见 `R6·D6` 画质净化、边缘增强、侧抑制
  - 提示词片段：`大面积渐变必须加抖动（马赫带会放大任何微小台阶）；相邻色块交界处避免过于接近的明度`

- **明度错觉（Value Illusions）** · L5 · 进阶 · 成本:低
  - 现象：Checker shadow、Adelson 棋盘阴影——相同像素值被感知为不同明度
  - 视觉收益：**在有阴影/渐变的背景上，不要相信取色器**，要相信眼睛
  - 提示词片段：`背景有渐变/阴影时，前景色需按位置微调（不能用同一个值），以保持视觉一致`

- **色彩的进退感（Advancing / Receding Colors）** · L4 · 进阶 · 成本:低
  - 现象：暖色/高饱和/高明度显得"靠前"，冷色/低饱和/低明度显得"靠后"
  - 视觉收益：**免费的纵深工具**，不需要阴影或透视
  - 同族拓展：见 `R1·G4` 大气透视、`R5·C7` 冷暖对比
  - 提示词片段：`前景用暖/高饱和，背景用冷/低饱和，仅靠色彩建立纵深`

- **相邻色的振动（Vibrating Colors）** · L4 · 进阶 · 成本:低
  - 现象：等明度的互补高饱和色相邻会"抖动"，刺眼且难读
  - 视觉收益：知道这点就能避免"红底蓝字"式灾难
  - 提示词片段：`避免等明度的互补高饱和色直接相邻；必须并置时用中性色隔开或拉开明度差`

- **图形-背景反转（Figure-Ground）** · L1 · 进阶 · 成本:低
  - 视觉收益：主动利用负空间形成第二个形象（FedEx 箭头式），极高的"聪明感"
  - 同族拓展：格式塔图底关系、双义图形、负空间 logo
  - 提示词片段：`尝试让负空间形成第二层含义（图底反转），作为第二眼奖励（见 R1·G8）`

## K2 光学对齐与形状补偿（Optical Alignment）

**这一节是"看起来很精致"的最大来源，也是最少人做的。**

- **形状面积补偿（Shape Size Compensation）** · L5 · 进阶 · 成本:低
  - 现象：相同高度下，**圆看起来比方小**，三角看起来更小
  - 参考补偿量：圆形放大 2–4%｜三角形放大 5–8%｜菱形放大 5%
  - 视觉收益：一组混合形状的图标才看起来"一样大"
  - 同族拓展：optical sizing of shapes、overshoot（字体设计术语）、图标视觉重量归一化
  - 提示词片段：`混合形状的图标做面积补偿：圆形 +3%、三角形 +6%，使视觉尺寸一致而非几何尺寸一致`

- **字形超出（Overshoot）** · L5 · 进阶 · 成本:低
  - 现象：好的字体里，`o` `e` `s` 的上下边缘会**超出**基线与 x 高度线一点，否则看着比 `n` `x` 矮
  - 视觉收益：解释了为什么手工画的字母表总显得高低不齐
  - 提示词片段：`自绘图形/字形时给圆润与尖角形状 1-2% 的 overshoot，超出对齐线`

- **视觉居中（Optical Centering）** · L5 · 基础 · 成本:低
  - 现象：**几何居中的元素看起来偏低**。视觉重心通常在几何中心上方约 2–5%
  - 视觉收益：标题在区块内、图标在按钮内、播放三角在圆内——都需要向上/向偏移
  - 同族拓展：optical center、播放按钮三角要右移（三角视觉重心偏左）、见 `R10·I3` text-box-trim
  - 提示词片段：`大标题在区块内向上偏移 3%（不用几何居中）；播放三角在圆形按钮内右移 1-2px`

- **视觉边距（Optical Margin）** · L5 · 进阶 · 成本:低
  - 现象：`W` `A` `T` 这类斜边字母、引号、括号的**外接矩形留白多**，数值对齐时看起来内缩
  - 视觉收益：标题左边缘对齐正文才真正"齐"
  - 同族拓展：见 `R10·I3` 悬挂标点、`hanging-punctuation`、负 text-indent、字距微调
  - 提示词片段：`标题以斜边字母(W/A/V/T)或引号开头时，向左负偏移 0.02-0.04em 使视觉左对齐`

- **描边的内外（Stroke Alignment）** · L5 · 进阶 · 成本:低
  - 现象：SVG 默认描边居中（一半在内一半在外），导致尺寸与对齐都偏
  - 视觉收益：图标在网格内精确对齐
  - 同族拓展：`stroke-alignment`（支持有限）、手动内缩 path、`paint-order`
  - 提示词片段：`SVG 图标 path 按 stroke-width/2 内缩，使描边完全在 24px 网格内`

- **视觉重量归一化（Visual Weight Normalization）** · L5 · 进阶 · 成本:低
  - 现象：同样 1.5px 线宽的图标，线条多的看起来更"重"更深
  - 视觉收益：一套图标看起来才是"一家人"
  - 提示词片段：`图标集内做视觉重量归一化：细节多的图标降低线宽或减少细节，使整套视觉重量一致`

- **1px 边框的视觉厚度（Hairline Perception）** · L5 · 进阶 · 成本:低
  - 现象：不同 DPR 下 1px CSS 的实际视觉厚度不同；深底上的浅色线看起来更粗
  - 同族拓展：见 `R9·H6` 发丝线、`@media (min-resolution)`
  - 提示词片段：`高 DPR 屏用 0.5px 分隔线；深色模式下分隔线透明度降低（浅色线视觉更粗）`

## K3 对比度与可读性算法（Contrast & Legibility）

**"看起来够亮"和"算法说够亮"经常不一致。**

- **APCA vs WCAG** · L5 · 进阶 · 成本:低
  - 现象：WCAG 2.x 的对比度公式在**深色背景和中间调**上误差很大——常判"通过"但实际难读，或判"不通过"但实际清楚
  - 视觉收益：APCA（WCAG 3 候选）基于感知模型，与实际可读性吻合得多
  - 参考阈值（APCA Lc）：正文 ≥75｜大字/次要文本 ≥60｜非文本图形 ≥45｜装饰 ≥30
  - 同族拓展：APCA、WCAG 2.1 (4.5:1 / 3:1)、`prefers-contrast`、OKLCH 的 L 通道近似判断
  - 提示词片段：`用 APCA 评估对比：正文 Lc≥75、大字 Lc≥60、图形 Lc≥45；同时保证 WCAG 4.5:1 合规底线`

- **深色模式不用纯黑（Avoid Pure Black）** · L4 · 基础 · 成本:低
  - 现象：纯黑 `#000` 背景 + 纯白文字对比过强，产生"光晕"和眼疲劳；OLED 上还有拖影
  - 参考值：深色底 `#0E0E10`–`#18181B`｜正文文字 `#E4E4E7` 级
  - 同族拓展：见 `R1·G7` 暗色模式一致性、elevation via lightness
  - 提示词片段：`深色模式底色用 #121214 级（非纯黑），文字用 #E4E4E7 级（非纯白）；层级抬升用变亮表达`

- **浅色模式不用纯白（Avoid Pure White）** · L4 · 进阶 · 成本:低
  - 现象：大面积纯白刺眼；极轻微的暖白/冷白更舒适且显高级
  - 参考值：`#FAFAF9`（暖）/ `#FAFAFA`（中性）/ `#F8FAFC`（冷）
  - 提示词片段：`浅色底用 #FAFAF9 级（略暖）而非纯白；正文文字用 #18181B 级而非纯黑`

- **色彩不能是唯一信息通道（Color Independence）** · L5 · 基础 · 成本:低
  - 现象：8% 男性有色觉差异；单靠颜色区分状态（红=错/绿=对）会失效
  - 同族拓展：加图标/形状/文字/图案、色盲模拟检查（protanopia/deuteranopia/tritanopia）
  - 提示词片段：`状态区分不能只靠颜色，必须叠加图标或形状；用色盲模拟器检查关键状态可区分`

- **小字与细线的可读极限（Minimum Sizes）** · L5 · 基础 · 成本:低
  - 参考底线：正文 ≥16px（移动端）｜辅助文字 ≥12px｜可点击目标 ≥44×44px｜细线 ≥1 物理像素
  - 提示词片段：`正文不小于 16px；辅助文字不小于 12px 且必须提高对比补偿；触摸目标不小于 44×44px`

- **字体渲染差异（Font Rendering）** · L5 · 进阶 · 成本:低
  - 现象：同一字体在 macOS（更粗）与 Windows（更细）渲染不同；`-webkit-font-smoothing: antialiased` 会让 macOS 变细
  - 关键判断：**不要盲目加 `antialiased`**，它会让某些字体在 macOS 上过细
  - 提示词片段：`不无脑加 -webkit-font-smoothing:antialiased；在 macOS/Windows 两端实测后决定；深色模式下可考虑加`

## K4 预注意加工（Preattentive Processing）

**哪些视觉属性能在 200ms 内被"不用找就看到"。** 这决定你的焦点设计有没有效。

- **预注意属性清单（Preattentive Attributes）** · L1 · 进阶 · 成本:低
  - 视觉收益：只有这些属性能被瞬间感知。**用它们做焦点，用其他属性做次要区分**
  - 强度排序（从最强）：
    1. **运动 / 闪烁**（最强，也最烦人，慎用）
    2. **色相**（一个红点在蓝点里）
    3. **明度**（一个亮块在暗块里）
    4. **尺寸**
    5. **方向 / 倾斜**
    6. **形状**（较弱）
    7. **添加/缺失标记**（有无下划线）
    8. **空间位置 / 分组**
  - 关键约束：**同一时刻只能有一个"预注意焦点"**。两个红点就等于没有红点
  - 提示词片段：`唯一焦点用预注意属性（色相或明度 + 尺寸叠加）；同页面不得出现第二个同等强度的预注意标记`

- **不用运动做常态强调（No Persistent Motion）** · L5 · 基础 · 成本:低
  - 现象：运动是最强的预注意属性，所以常态动画会**持续抢夺注意力**，让人无法阅读
  - 提示词片段：`运动只用于一次性引导或状态变化；禁止常态循环动画出现在阅读区域附近`

- **数量感知极限（Subitizing Limit）** · L1 · 进阶 · 成本:低
  - 现象：人不用数就能瞬间识别的数量上限是 **4 个**（±1）
  - 视觉收益：导航项、卡片组、步骤数控制在 4–5 个以内最舒适；超过要分组
  - 同族拓展：Miller 7±2（工作记忆）、chunking 分组
  - 提示词片段：`同级选项控制在 5 个以内；超过则分组（每组 ≤5）；步骤流程不超过 5 步`

- **视觉搜索成本（Visual Search）** · L1 · 进阶 · 成本:低
  - 现象：目标与干扰项差异越大越快找到；**多个属性都相似时搜索成本指数上升**
  - 提示词片段：`需要被找到的元素（CTA/搜索框）至少在 2 个预注意属性上与周围不同`

## K5 辨识度与记忆（Recognizability & Memory）

**好看是一次性的，记得住是长期的。**

- **剪影测试（Silhouette Test）** · L1 · 进阶 · 成本:低
  - 方法：把整个画面变成纯黑剪影。**如果剪影还有辨识度，形体设计过关**
  - 视觉收益：这是判断 logo、图标、主视觉是否有"形"的最快方法
  - 提示词片段：`主视觉与 logo 必须通过剪影测试（纯黑剪影仍可辨识）`

- **缩略图测试（Thumbnail Test）** · L1 · 基础 · 成本:低
  - 方法：缩到 200px 宽看。构图、层级、焦点是否还成立？
  - 视觉收益：这是它在社交分享、作品集列表里的真实样子
  - 同族拓展：见 `R1` 组三个眯眼测试、OG 图设计
  - 提示词片段：`在 200px 缩略图尺寸下检查：焦点仍然明确、主标题仍可辨识、构图仍成立`

- **5 秒测试（Five-Second Test）** · L0 · 基础 · 成本:低
  - 方法：给人看 5 秒然后关掉，问他记住了什么
  - 视觉收益：暴露"信息层级是否与意图一致"
  - 提示词片段：`确保 5 秒内能传达：这是什么 + 最重要的一句话 + 一个视觉印象`

- **视觉签名（Visual Signature）** · L0 · 电影级 · 成本:低
  - 视觉收益：一个独一无二、可被复述的视觉元素（"那个有黑洞的网站""那个鼠标会拖出线的网站"）
  - 同族拓展：见 `R1·G8` wow moment、`R7·E5` 人的签名
  - 提示词片段：`设计一个可被一句话复述的视觉签名，它应该是本作品唯一的记忆锚点`

- **一致性带来的识别（Recognition via Consistency）** · L1 · 基础 · 成本:低
  - 视觉收益：见 `R1·G7`。一致的视觉语言让人"认得出这是同一个作品/品牌"
  - 提示词片段：`所有页面/区块共享同一套令牌与形状语言，使任意截图都能被认出属于同一作品`

## K6 注意力与认知负荷（Attention & Cognitive Load）

- **认知负荷预算（Cognitive Budget）** · L0 · 基础 · 成本:低
  - 视觉收益：每个新增的视觉元素都消耗注意力预算。**删掉一个元素通常比加一个效果更有效**
  - 同族拓展：见 `R1·G3` 负空间、`R1·G6` 渐进披露、Hick's law（选项越多决策越慢）
  - 提示词片段：`每个区块只承担一个信息任务；无法删除的次要信息用渐进披露隐藏`

- **视觉动线的强制性（Forced Path）** · L1 · 进阶 · 成本:低
  - 视觉收益：见 `R1·G2`。有明确路径 = 低认知负荷；没有路径 = 观众自己找 = 疲劳
  - 提示词片段：`用对比强度排序建立强制视线路径，不要让观众自己判断从哪看起`

- **变化盲视（Change Blindness）** · L5 · 进阶 · 成本:低
  - 现象：没有动画过渡的状态变化**会被完全忽略**（用户以为没反应）
  - 视觉收益：这是"为什么必须有过渡动画"的科学理由，不只是美观
  - 同族拓展：见 `R11·F3` 转场、`R11·F7` 反馈时序
  - 提示词片段：`所有状态变化必须有过渡动画（≥150ms）或位置连续性，否则会触发变化盲视`

- **注意力的恢复（Attention Recovery）** · L0 · 进阶 · 成本:低
  - 视觉收益：长页面需要"低刺激的休息区"，否则观众在高潮前就疲劳了
  - 同族拓展：见 `R1·G3` 呼吸密度、`R11·F8` 节奏对比、`R1·G8` 情绪弧线
  - 提示词片段：`高信息密度区之后必须跟一个低刺激休息区（大留白/单句话/纯色块）`

- **首因与近因（Primacy & Recency）** · L0 · 进阶 · 成本:低
  - 视觉收益：开头和结尾被记得最牢，中间容易被忘。**把最重要的放首尾**
  - 提示词片段：`最重要的信息放在首屏与页尾；中段用来展开细节`

- **峰终定律（Peak-End Rule）** · L0 · 进阶 · 成本:低
  - 视觉收益：整体印象由**最强的那个瞬间**和**结束时的感受**决定，而非平均值
  - 视觉推论：宁可一处极强 + 其余平淡，也不要处处中等；且**结尾必须收得好**
  - 同族拓展：见 `R1·G8` wow moment 与情绪弧线、单一峰值原则
  - 提示词片段：`集中做一个峰值瞬间 + 一个精心设计的结尾；不要平均分配视觉强度`

| 想解决的问题 | 用哪些 |

| "总觉得哪里不精致但说不出" | `R2·K2` 全套（形状补偿/视觉居中/视觉边距/描边对齐） |

| "图标一组看着不齐" | `R2·K2` 面积补偿 + `R2·K2` 视觉重量归一化 + `R2·K2` 描边对齐 |

| "长页看到一半就累" | `R2·K6` 注意力恢复 + `R2·K6` 认知负荷预算 + `R1·G3` 呼吸密度 |
| "用户说点了没反应" | `R2·K6` 变化盲视 → 加过渡动画 |

**常见坑**：
- 混合形状图标看着大小不一 → `R2·K2` 缺面积补偿
- 标题几何居中但看着偏低 → `R2·K2` 缺视觉居中上移
- 标题左边缘和正文"没对齐" → `R2·K2` 缺视觉边距（斜边字母/引号）
- 深色模式文字显粗显糊 → `R2·K1` 光渗未补偿
- 纯黑底纯白字刺眼 → `R2·K3` 都应该退一步
- 对比度工具说通过但实际难读 → `R2·K3` WCAG 在深色上不准，用 APCA
- 页面有 3 个红色强调点 → `R2·K4` 预注意焦点只能一个
- 导航有 9 个平级项 → `R2·K4` 超过 subitizing 极限，要分组
- 状态切换用户没察觉 → `R2·K6` 变化盲视，缺过渡
- 全页都很用力但没有印象 → `R2·K6` 峰终定律，缺单一峰值与好结尾

> 上面这份"常见坑"与库内的 `B82`（反 AI 味与差异化系统）、`B44`（反面词典与视觉禁忌）可以对读：三者都是**参考清单，不是硬性铁律，按项目自行取舍**。感知层的坑（光渗、视觉居中、APCA）多数值得照做，而风格层的禁忌需要结合项目定位判断。

## K 组 · 六个测试（交付前逐个做）

1. **灰度测试** — 截图转灰度：层级还在吗？（`R2·K1`/`R1·G1`）
2. **眯眼测试** — 眯眼看：有唯一焦点吗？（`R2·K4`/`R1·G1`）
3. **缩略图测试** — 缩到 200px：构图还成立吗？（`R2·K5`/`R1·G2`）
4. **剪影测试** — 变纯黑剪影：主视觉还有辨识度吗？（`R2·K5`）
5. **5 秒测试** — 给人看 5 秒：他记住了什么？（`R2·K5`/`R1·G8`）
6. **色盲模拟** — 三种色盲模式：关键状态还能区分吗？（`R2·K3`）

> 这六个测试全部免费、5 分钟内可做完，却能发现绝大多数"看起来就是差一点"的问题。作品集与个人展示类页面尤其要做这六个测试——它们决定了"第一眼印象"是否成立。
