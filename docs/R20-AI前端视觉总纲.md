# 第一部 · 底层认知

## 1.1 为什么 AI 默认产出平庸

理解这一点，后面所有技巧才有意义。

**AI 生成的 UI 代码 = 训练集的众数。**

互联网上最高频的 UI 是 Bootstrap 模板、Tailwind 文档示例、SaaS 落地页模板。所以 AI 的默认审美就是 **2021 年 Tailwind 教程审美**：居中标题、三张等宽卡片、紫蓝渐变、`shadow-lg`、`rounded-xl`、`transition-all duration-300`。

> 这不是能力问题，是概率问题。你不给约束，它就回落到众数。**你的每一条约束，都是把概率分布往长尾（顶流）拉。**

### 三个机制性缺陷与对策

| 缺陷 | 表现 | 根因 | 对策 |
|------|------|------|------|
| **无视觉反馈回路** | 写完不知道好不好看 | 看不到渲染结果，只能模式匹配 | 补截图 + 审片提示词（本文第九部） |
| **局部最优陷阱** | 每块都合理，拼起来散 | 逐块生成，无全局编排 | 强制「先答后写」（本文 5.2） |
| **均值回归倾向** | 你要 8:1 字号跳跃，它给 2:1 | 极端值在训练集稀有，被拉回均值 | 一切形容词换成具体数值（本文 5.4） |

## 1.2 视觉质量公式

```
视觉质量 = 约束密度 × 参考锚定 × 迭代次数 × 编排意识
```

四个因子是**乘法**关系——任何一项为 0，结果为 0。

- 约束密度 = 0 → 说「做得高级点」→ 众数模板
- 参考锚定 = 0 → 无具体色值/字号/曲线 → 均值回归
- 迭代次数 = 1 → 一次生成收工 → 70 分
- 编排意识 = 0 → 逐块生成不管全局 → 每块都对，整体散

### 约束密度的量化带宽

| 约束条数 | 产出水平 |
|---------|---------|
| 0–3 条 | 众数模板（不可用） |
| 4–10 条 | 及格（结构对、质感缺） |
| 11–25 条 | 良好（有系统感） |
| **26–45 条** | **顶流候选** |
| 45 条以上 | 收益递减 + 冲突风险 |

**目标带宽：26–45 条。**

## 1.3 「顶流」的三支柱定义

顶流 = **气 × 藏 × 手**。翻译成可执行的三句话：

| 支柱 | 含义 | 可执行表述 |
|------|------|-----------|
| **气** | 贯穿生命力 | 全站共用一条缓动曲线、一套间距标尺、一条方向轴线，所有运动像同一个人的步态 |
| **藏** | 克制深度 | 首屏亮点 ≤2 个，强调色全页 ≤5 次，至少 3 处细节需停留 5 秒才发现 |
| **手** | 人的温度 | 至少 1 处刻意的不完美/手绘/破格，且被主动标注 |

## 1.4 四大支柱同级（不是「视觉好 + 顺便有内容」）

```
        顶流表现
   ┌──────┬──────┬──────┬──────┐
 视觉特效  布局构图  信息架构  性能工程
 「好看」  「怎么摆」 「摆什么」 「跑得动」
```

- **视觉特效**决定震不震撼——但没有布局承载就是烟花
- **布局构图**决定结构美不美——每种结构都是决策，不是随手分栏
- **信息架构**决定看得懂找得到——每屏放什么是算出来的
- **性能工程**决定丝不丝滑——掉帧的复杂特效比简单特效更廉价

## 1.5 受控的复杂 vs 失控的复杂

复杂本身不等于高级。区别在三点：

1. **复杂但统一** — 所有特效共用一套时间曲线、色彩、物理参数
2. **复杂但有序揭示** — 不一次全砸，随滚动/交互逐层展开
3. **复杂但流畅** — 60fps 是底线，120fps 是追求

> 公式：**GPU 渲染复杂度 × 编排精密度 × 60fps 流畅度**。三者缺一，复杂就变累赘。

# 第二部 · 维度体系（L0–L5 六层）

> **上层无法修补下层的错误。从 L0 开始，跳级即崩塌。**
> 本层级模型即 `R0`（提示词库入口）分层挑词所依据的 **L0–L5 模型的原始出处**。`R0` 按这六层去 `R1`–`R18` 取词；本文这一部讲清每层要判断什么、做错的代价是什么。全维度的枚举清单见库内 `B15`（`R19` 是其扩展深化版）。

| 层 | 名称 | 含义 | 做错的代价 |
|----|------|------|-----------|
| **L0** | 意 Intent | 给谁、要什么感受、一句话目标 | 整站方向错误 |
| **L1** | 骨 Structure | 信息架构 + 布局骨架 + 网格 + 间距标尺 | 视觉再好也「散」 |
| **L2** | 气 Rhythm | 时间/节奏/密疏/动效系统/缓动 | 页面「死」或「躁」 |
| **L3** | 肉 Surface | 色彩/排印/材质/光影/纹理 | 「不好看」但骨架对就能救 |
| **L4** | 神 Soul | 峰值/藏/手的痕迹/二读时刻 | 「好看但不记得」 |
| **L5** | 髓 Craft | 微工艺/性能/无障碍/一致性 | 95% 精致 + 5% 出错 < 80% 精致 |

**使用方法**：
- 新项目：从 L0 逐级向下，绝不跳级
- 审查现有：从 L5 往上查，找到崩塌的那一层
- 加分项：只有 L0–L3 全稳固后，才开始 L4–L5

### 三种气质的时长映射（速度本身传达气质）

```
静奢/美术馆      hero 揭示 700–900ms · 转场 600ms   （慢 = 高级、审慎）
阅读/个人站      段落 550ms · 手绘 1600ms           （中 = 温度、从容）
产品/技术        交互 250ms · 数据 400ms            （快 = 高效、可信）
```

**统一红线**：无论哪种，**触发反馈必须 <100ms**。放慢的是动画本身，不是响应。

### 三条签名缓动曲线

```css
--ease-dramatic: cubic-bezier(0.16, 1, 0.3, 1);    /* expo out · 戏剧 */
--ease-calm:     cubic-bezier(0.19, 1, 0.22, 1);   /* 更缓 expo · 从容 */
--ease-crisp:    cubic-bezier(0.4, 0, 0.2, 1);     /* material · 干脆 */
```

### 节拍系统（BPM）

```css
--stagger-base:    60ms;                          /* 基础单位 */
--stagger-item:    calc(var(--stagger-base) * 1);  /* 列表项 60ms */
--stagger-block:   calc(var(--stagger-base) * 2);  /* 段落 120ms */
--stagger-section: calc(var(--stagger-base) * 8);  /* 段落间 480ms */
```

**验证**：所有 stagger 值能被 60 整除。

### 注意瞬盲修正（关键）

强刺激后 200–500ms 无法感知第二刺激。所以：
- **强揭示之间**（hero 行、大标题）：间隔 **≥500ms**
- **弱元素之间**（列表项、次要卡片）：60–120ms
- **表达「归属」用同步**（duration+delay 完全一致），**表达「序列」才用 stagger**

### 阴影物理（单一光源 + 色温阴影）

```css
/* 光源恒定：顶部偏左。x 恒为 0，y 恒为正 */
暖调项目：rgba(27,24,21, α)     /* 暖墨 */
棕调项目：rgba(36,30,21, α)     /* 暖棕 */
冷调项目：rgba(10,20,40, α)     /* 冷蓝，读作「洁净/技术」 */

```

**禁止纯黑阴影**——`rgba(0,0,0,*)` 读作「数字化」，破坏物理错觉。

### 间距的时间维度（Kappa 效应）

紧间距 = 感觉快，宽间距 = 感觉慢。

```

```

### 峰终定律编排

每页恰好 1 个情绪峰值 + 1 个结尾印象。中段不放峰值（会被遗忘）。

```
铺垫（≥2 个安静段）→ 峰值（唯一）→ 余韵（克制段）→ 结尾（第二重点）
```

### 未闭合回路（Zeigarnik）

每页留一个「未闭合」元素制造认知黏性，解答在同页：
- 「这是 4 件作品中的一件 →」
- 「6 款游戏中的…」
- 开场留悬念，数字段后揭晓

### 匹配剪辑（相邻段的连续性）

每两个相邻 section 之间必须有 **1 个匹配点**：
- **形状匹配**：上段结束的圆 = 下段开始的圆（位置尺寸接近）
- **颜色匹配**：上段强调色元素位置 = 下段同色元素位置
- **文字匹配**：上段最后一词 = 下段首词

做不到时，至少 section 边界用同一条 1px 线。

# 第三部 · 气质配方（十种可直接选用的预设）

> 每个配方 = 一套可直接落地的完整方向。**选一个作为项目基调**，不要混用两个高能配方。

## 配方 1 · 静奢编辑 Quiet Luxury Editorial

- **气质**：安静、克制、贵、editorial
- **适合**：美术馆、高端 portfolio、奢侈品
- **调色板**：3–4 暖中性（纸白/骨白/灰烬/墨）+ 1 强调色 ≤4 次
- **排印**：serif display + sans body，字号 8:1 极端跳跃，行长 55–65ch
- **动效**：慢（600–900ms）· expo.out · stagger ≥500ms
- **招牌手法**：全屏留白 + 一个巨字 + 一处极细注记
- **反面**：❌ 快动效 ❌ 多强调色 ❌ 感叹号 ❌ 拥挤

## 配方 2 · 温暖手作 Warm Handcrafted

- **气质**：真诚、有温度、手工、亲密
- **适合**：个人站、创作者、独立品牌
- **调色板**：暖亚麻底 `#F0E8D6` + 琥珀强调 `#C8892B` + 深棕墨 `#241E15`（不用纯黑）
- **排印**：serif italic 主导 + Drop Cap + 62–68ch 行长
- **动效**：中速（900ms）· power3.out · 手绘 stroke-dashoffset 1600ms
- **招牌手法**：手绘签名 + 一道高亮笔痕划过关键句
- **反面**：❌ WebGL shader ❌ 完美矢量 ❌ 冷调 ❌ 第三人称 ❌ 技能条/星级

## 配方 3 · 技术精密 Technical Precision

- **气质**：冷静、精确、可信
- **适合**：开发者工具、SaaS 官网、仪表盘
- **调色板**：冷调近白 `#F6F7F9` + 碳黑 panel `#0A0E14` + 电子绿 `#00D46A` + 语义红 `#FF5A3C`
- **排印**：纯 geometric sans + 大量 mono tabular，**零 serif**
- **动效**：快（250–400ms）· power2.out · 数据条形增长

# 第五部 · 提示词工程

> 本部讲 prompt 的**结构与投喂策略**（怎么组织约束）。库内 `Z1`（终极Prompt生成器）给的是成品生成器，`Z2`（Prompt检索与组合编排）给的是检索与组合协议——本部是它们背后的判断依据。

## 5.1 六段式骨架（顺序不能变）

```
① 身份与语境    你在做什么项目的哪一部分
② 任务边界      改什么 / 不改什么（防止 AI 顺手重写）
③ 参考锚定      具体色值、字号、曲线、间距（抗均值回归）
④ 硬约束清单    可 grep / 可测量的规则，26–45 条
⑤ 先答后写      要求它先输出设计决策，等确认再写代码
⑥ 自检与验收    完成后自己逐条核对并报告
```

**为什么顺序重要**：模型对 prompt **末尾**指令遵守度最高。所以自检放最后，并把本次最在意的那一条重复放在末尾：

```
【本次最高优先】如果只能做对一件事，那就是：首屏可见元素 ≤5 个。
其余约束可以妥协，这条不行。
```

## 5.2 「先答后写」——全篇最有效的一招

这一招把 AI 从「模式匹配生成代码」切换到「先做设计决策」。

```
【先答后写 · 不要写任何代码】
在写代码前，先用不超过 200 字回答下面 7 个问题，等我确认后再实现：

1. 这一屏想让访客产生什么感受？（一个词）
2. 视觉主角是哪一个元素？其余元素如何退让？（写出退让手法）
3. 这一屏的信息量决定了什么布局？（为什么不是左右分栏）
4. 字号阶梯用哪几个具体值？最大/最小比是多少？
5. 本段能量等级 lo/mid/hi？与上一段是否连续 hi？
6. 与上一段的匹配剪辑点是什么？（形状/颜色/文字 三选一，写具体）
7. 关掉所有动效后，静态版面靠什么撑住高级感？
```

> **实测差异**：同样的约束清单，加这一段和不加，差距大于「多给 20 条约束」。

## 5.3 任务边界（防止 AI 顺手重写）

```
【任务边界】
只改 src/sections/[路径]/[文件].tsx。
禁止修改：globals.css 的 token 定义、fx/tokens.ts、其他 section 文件。
如果你认为必须改上述文件才能完成，先说明原因并等我同意。
新增依赖需先征求同意。
```

## 5.4 参考锚定：一切形容词换成数值

**AI 无法执行形容词。** 这是抵抗均值回归的唯一办法。

| 你想说 | AI 会理解成 | 应该写成 |
|--------|-----------|---------|
| 慢一点 | 400ms | `duration: 700ms` |
| 字号跳跃大一点 | 1.5× | `hero 128px / body 15px（8.5:1）` |
| 留白多一点 | py-24 | `padding-block: clamp(160px, 12vw, 200px)` |
| 颗粒感弱一点 | opacity .5 | `opacity .28, blend multiply, tile 140px` |
| 阴影柔和 | shadow-lg | `0 24px 60px rgba(27,24,21,.08)` |
| 强调色少用 | 到处都是 | `全页 ≤5 次，逐处列出用在哪` |
| 高级 | 加渐变加阴影 | 见本文 1.3 气/藏/手 三句话 |

### 锚定的三种形式（按强度）

1. **数值锚**（最强）：`128px` / `700ms` / `#C64A2E` / `cubic-bezier(0.16,1,0.3,1)`
2. **计数锚**（强）：`≤5 个` / `恰好 1 处` / `stagger 是 60 的整数倍`
3. **枚举锚**（中）：`圆角只能是 4/8/14/20/28 之一`

⚠️ **禁止「网站名锚定」**：说「参考某知名官网」会得到该站的**刻板印象版**（例如「某大厂 = 居中大字 + 白底」），比不给锚点更糟。要锚定就锚定**具体手法**：「用 1px hairline 分隔 + 零卡片背景色的信息组织方式」。

## 5.5 正定优于否定

| 弱（否定式） | 强（正定式） |
|------------|-------------|
| ❌ 不要用渐变 | ✅ 背景使用纯色 `#EDE9E1`，不声明任何 gradient |
| ❌ 不要用黑色阴影 | ✅ 阴影颜色统一 `rgba(27,24,21,α)`，α ∈ {.08,.12,.20} |
| ❌ 不要居中 | ✅ 标题起始于 12 栏网格第 2 栏，右侧留 4 栏空 |
| ❌ 少用动效 | ✅ 本段动效元素恰好 3 个，列出是哪 3 个 |

**原因**：否定约束需要 AI 先想到再排除；正定约束直接给目标状态。否定式只用于黑名单（本文第六部）。

## 5.6 上下文投喂：三层模型

约束不是越多越好——**贴太多会稀释注意力**，AI 会挑容易的做。

```
┌─ 常驻层（≤60 行）  写进 AGENTS.md / CLAUDE.md，每次自动加载
│  内容：全站铁律（本文附录 A 的 18 条）
│
├─ 任务层（≤120 行）  本次任务贴进 prompt
│  内容：1 个配方 + 本 section 的具体规格

把这段加进项目约束，视觉能力立刻上一个台阶：

## 8.10 Shader / GPU（只在 1 处峰值用）

```
【Shader 硬约束】
- 用 GLSL fragment shader，webgl2 兼容，精度 mediump
- 禁止调用未定义的库函数——所有工具函数（noise、hash）自己写出来
- 输出前列出你用到的所有 uniform 及其含义
- 关键参数（噪波尺度、时间速率、混色比）用 uniform 暴露，不硬编码
- reduced-motion 下暂停 time 更新，只显示静态帧
- 移动端降级到 CSS 版本，写清降级方案
- 循环迭代 ≤8 次，后处理 pass ≤2 层
- canvas 尺寸 = window size × devicePixelRatio 的 0.75（不用 1:1）

【性能红线】
桌面 120fps 目标 / 移动端 60fps 目标。
若在中端手机 <45fps，必须降级为 CSS 版本。

【选型】
只做一处 hero 背景 → 用 ogl（<10KB，不引入 three）
有 3D 模型/相机运动 → three + @react-three/fiber

【写码前先答】
1. 主要视觉元素是什么（流体？粒子？噪波场？）
2. 时间如何影响画面
3. 指针位置如何影响画面
4. 颜色范围（用具体 hex）
5. 与页面主色调如何融合
等我确认再写 GLSL。
```

## 9.2 审片提示词（核心武器）

每次实现完成后，**新开一轮**贴这段。明确「不要写代码」，否则它会边审边改，越改越乱。

```

1. 首屏可见 DOM 元素几个？内容包围盒占视口面积估算？（红线 ≤5 个 / ≤25%）

3. 全文件是否存在 rgba(0,0,0、transition-all、linear-gradient、backdrop-blur、

## 编排指标

## 质感指标（最关键，答不出说明视觉没到位）

### 为什么第 11、12 问最重要

- **第 11 问**筛掉「靠动效撑场面」的假高级。静态版面不高级 = 表面层没做好，动效只是遮羞布。

### 三种方式，效果差 3 倍

## 10.2 AI 生成设计参考图（先画后写）

### 生图提示词的关键：给结构+气质，不给具体元素

生图 AI 擅长气质，不擅长精确布局。

**❌ 差**：`生成一个作品集 hero`

**✅ 好**：
```
生成一张 1920×1080 的落地页 hero 参考图（概念图，非最终页面）。

【构图】
- 12 栏网格，主标题起于第 2 栏，占 8 栏宽
- 上下留白各 25vh，垂直中偏上
- 左上角一处 10px 小注记，右上角一处小注记
- 底部一条 1px 水平线在下方 1/6 处

【视觉气质】
- 底色暖纸白 #EDE9E1，加轻微纸质颗粒
- 主色暖墨黑 #1B1815
- 一处强调色 #C64A2E，只出现在一个词上
- 无渐变、无 backdrop-blur、无粒子

【排印】
- 巨号 display 标题（视觉高度约占 15% 屏幕高度）
- 一句小副标（display 高度的 1/8）
- 一处 10px meta 注记
- 字号极端反差感

【禁止元素】
- 任何按钮/CTA、任何照片、任何粒子/光晕/渐变、居中构图

生成 3 张变体，构图各不相同（不都是左对齐）。
```

### 生图后的分析提示词

```
基于刚才这张参考图：
1. 描述构图（具体百分比：标题占宽百分之几、位于视口上几分之几处）
2. 提取色板（3–5 个主要 hex 值）
3. 估算字号阶梯（最大字号 px vs 最小 px 的比）
4. 描述留白形状（长方形块留白 / 上下留 / 左右留？）
5. 判断哪一处是 signature moment
用这些数据作为下一步实现的硬约束。
```

### 三条铁律

1. 生图分辨率 ≥1920×1080——低分辨率 AI 看不清细节
2. 每次只生一个 section 的参考——不要生「整个网站」
3. 不同 section 用同一色板 prompt——保证整站参考图色调一致

## 10.3 动效参考（视频而非文字）

| 方式 | 适用 |
|------|------|
| ❌ 「像某大厂那种流畅」 | 无效 |
| ⚠️ GIF | 帧率不准，仅示意 |
| ✅ MP4 录屏 5–10 秒 | 主力 |
| ✅✅ 逐帧截图 3–5 张 + 时间标注 | 分析用最强 |

### 分析动效参考的提示词

```
【动效参考分析】
我给你一段 [某交互] 的录屏（5 秒）。不要马上写代码，先分析：
1. 触发条件：什么动作触发（hover / click / scroll / focus）
2. 时长：从开始到结束多少 ms（用帧数估算：帧数 × 1000/60）
3. 缓动：ease-out（快出慢入）/ ease-in / expo / spring？描述曲线感觉
4. 涉及属性：transform 的哪些子属性？opacity？filter？clip-path？
5. 分阶段：一次动作 or 多阶段？各阶段占比？
6. 联动：其他元素有没有跟随反应？延迟多少？
7. 结束态：停在何处？有没有回弹？

产出分析报告 + 用签名缓动重写这个动效的方案。
```

### 录制参考的最简流程

```
1. 目标网页 → 打开 DevTools Performance panel
2. 录制 → 触发动效 → 停止
3. 从 Timeline 读实际时长和缓动
4. 用录屏工具录 5–10 秒
5. ffmpeg 转低体积 mp4
6. 命名：<segment>_<interaction>_<sample>.mp4
   例：pricing_hover_sample.mp4
```

```

```
## 视觉约束卡（常驻层 · 参考清单）

结构
1. 首屏可见 DOM 元素 ≤5 个，内容占视口面积 ≤25%，首屏无 CTA

色彩材质

内容与无障碍
18. 五态齐全 + 点击区 ≥44px + 对比度 ≥4.5:1；
    禁 emoji 图标 / Lorem ipsum / 感叹号 /
