# K4 · 拖拽全链路

> 拖拽是单个操作里状态最多的交互：从"暗示可拖"到"无效放下"共 6+ 个状态，每个状态都是一次设计决策。
> 碎片原在 B45§四、B71（拖拽 FLIP）、R12、K1·拖放目标，本文件按操作时间线聚合成完整决策链。

---

## K·拖动阈值（Drag Threshold）

- **领域**：交互 · **成本**：低
- **定义**：指针移动达到一定距离后才判定为"拖动"而非"点击"——区分点选与拖动的判定线。
- **症状**：想点击却触发拖动（选中文字变拖拽）；轻微手抖就进入拖动态；阈值太大导致拖动"起步延迟感"。
- **决策点**：
  ① **像素阈值**——桌面 4-8px、触屏 8-12px（指肚精度差需更大容差）；
  ② **时间辅助**——按住超过 Xms 未移动仍算点击还是预备拖动？（按住不动 >500ms 进入"长按拖动"模式是移动端惯例）；
  ③ **方向锁定**——水平拖动开始后锁定垂直分量（列表排序常只许单轴）？
  ④ **阈值前反馈**——按下到阈值之间元素是否已经有"被抓住"的视觉（scale 1.01 微反馈）。
- **实现**：pointerdown 记录起点 → pointermove 位移超过阈值才 `setPointerCapture` + 进入拖动态；阈值内松手按 click 处理。
- **验收**：正常点击 100% 不误触拖动；拖动起步无滞后感；触屏滑动页面不意外抓起列表项。
- **衔接**：B45§六（滑动阈值 40% 是另一类阈值——位移比例阈值）、K·命中区域、K·拖拽碰撞检测

## K·拖动预览（Drag Preview / Drag Image）

- **领域**：交互/视觉 · **成本**：低
- **定义**：拖动过程中跟随指针的视觉形象——被拖元素本身、半透明克隆、缩略快照或自定义徽标。
- **症状**：拖动时元素消失（看不到在拖什么）；预览遮挡 drop 目标看不见落点；预览还带着原元素的 hover 态。
- **决策点**：
  ① **预览形态**——原元素（排序场景）/ 半透明克隆 0.9（B45）/ 缩略快照（跨面板拖文件）/ 计数徽标（多选拖 n 项显示 "3 items"）；
  ② **抓取点**——预览相对指针的锚点=按下时的偏移（在哪儿抓的就从哪儿拎起来）；
  ③ **拿起反馈**——scale(1.02-1.05) + rotate(1-3deg) + 阴影加深 + opacity 0.9 = "离开表面"的物理暗示（B45 物理细节）；
  ④ **层级**——预览层 z-index 最高且 `pointer-events: none`（不挡目标判定）。
- **实现**：`.dragging { transform: scale(1.03) rotate(2deg); box-shadow: 0 16px 32px rgba(0,0,0,.2); opacity:.9; z-index:100 }`（B45）。
- **验收**：预览不挡 drop 指示；多选有计数；预览与指针无跳变（抓取点一致）。
- **衔接**：B45§四（拿起/拖动参数）、B58（拖拽中的连续性）

## K·拖动占位（Drag Placeholder）

- **领域**：交互/视觉 · **成本**：低
- **定义**：拖动时在原位置或目标位置显示的占位形态——告诉用户"它会落在哪"和"原来这里有个东西"。
- **症状**：拖走后原位塌陷（列表抖动重排）；目标位置没有插入指示，落下才知道猜错；占位与实元素尺寸不同导致落位跳动。
- **决策点**：
  ① **原位处理**——保留幽灵占位（ghost，半透明描边版）还是立即收起让列表 reflow？
  ② **插入指示**——列表排序用 2px 指示线 + 其他项让位动画（B71 拖拽 FLIP 让位）；区块投放用虚线占位框；
  ③ **尺寸同步**——占位尺寸=被拖元素实际尺寸（含 margin）；
  ④ **让位动画**——其他元素移开时的时长/曲线（spring 或 200ms ease-out），不能让位瞬移。
- **实现**：原生 DnD `dragover` 中算最近插入点 → 在该位置插入 placeholder 节点；其他项用 FLIP 让位（B58§4.3）。
- **验收**：拖动全程列表高度不突变；插入指示与最终落点 100% 一致；无效区域无占位。
- **衔接**：B71（拖拽 FLIP 让位）、B58（FLIP 手动实现）、K·拖放目标判定（K1）

## K·拖拽碰撞检测（Collision Detection）

- **领域**：交互/工程 · **成本**：中
- **定义**：判定拖动元素与候选目标的空间关系——用于排序插入点计算、目标高亮、吸附候选选择。
- **症状**：拖到两目标间高亮来回跳；元素一半在目标里却不认；边缘目标永远判不中。
- **决策点**：
  ① **算法选型**——pointer-inside（指针坐标判定，排序首选）/ rect-intersection（矩形相交比例，>50% 计）/ closest-center（距离最近中心）/ corner-based（网格画布）；
  ② **滞后带（hysteresis）**——在两个候选边界附近 ±4px 内保持当前判定不切换（防抖）；
  ③ **排除规则**——被拖元素自身、不可放置区域从候选集中剔除；
  ④ **性能**——每帧 getBoundingClientRect 成本高，拖动开始时缓存候选 rects，滚动时失效重算。
- **实现**：dnd-kit 的 `pointerWithin`/`rectIntersection`/`closestCenter` 对应上述算法；自实现时 `document.elementsFromPoint`。
- **验收**：边界±4px 内判定稳定不跳；滚动中目标判定跟随（rects 更新）；大列表（>200 项）检测不掉帧。
- **衔接**：K1·拖放目标判定、K·几何约束（K1）、K3·防抖节流

## K·无效放下（Invalid Drop）

- **领域**：交互 · **成本**：低
- **定义**：拖到不允许的区域松手后的处理——拖拽六态的收尾态，决定"失败"的体感。
- **症状**：松手后元素消失/位置错乱；无效放置无任何反馈（用户不知道失败了）；弹回动画生硬瞬移。
- **决策点**：
  ① **预判反馈**——拖到无效区时提前告知：`cursor: no-drop` + 目标区变灰/不显示占位（别等松手才说）；
  ② **回位动画**——spring 弹回原位（B45：spring + 轻微 shake 确认失败）；
  ③ **状态回滚**——拖动期间做过的乐观改动（占位/排序预览）完全回滚；
  ④ **取消通道**——Esc 键中途取消拖拽（等同无效放下）+ 触屏拖出边界取消。
- **实现**：dragover 时检查目标合法性 → `event.dataTransfer.dropEffect = 'none'` + no-drop 光标；drop 无效时 FLIP 回原位 spring。
- **验收**：无效区有先验信号；回位 spring ≤400ms；Esc 全程可取消；回滚后 DOM/状态与拖前一致。
- **衔接**：B45§四（无效放下=弹回+shake）、K·拖放目标判定、K5·动画反转

## K·惯性拖拽（Momentum Drag）

- **领域**：交互/物理 · **成本**：中
- **定义**：松手后元素按释放速度继续滑行并摩擦减速——轮播、地图、画布的"甩"感。
- **症状**：松手即停很"死"；滑行过远超预期；滑行中无法拦截（想停停不下来）；终点不吸附停在半档。
- **决策点**：
  ① **初速度**——取最后 N 帧平均速度（防最后一帧异常值），限制初速上限；
  ② **摩擦系数**——`velocity *= 0.95` 每帧衰减（B45）；不同区域可用不同阻尼暗示材质（R12：滚动 0.95 顺滑/拖拽 0.88 有控制感）；
  ③ **终点预测**——按初速+摩擦预测落点 → 提前吸附到最近合法位置（R12：轮播/抽屉的"翻页"判定）；
  ④ **可中断**——滑行中按下/点击应立即接管停止。
- **实现**：
  ```js
  velocity = (pos - lastPos) / dt;           // 拖动中持续更新
  // 松手后 rAF：
  pos += velocity; velocity *= 0.95;
  if (Math.abs(velocity) < 0.5) snapTo(nearest);  // 低速后吸附
  ```
- **验收**：滑行距离与甩出速度成正比；终点吸附档位不错位；滑行中可点击拦截。
- **衔接**：B45§四（惯性公式）、R12（摩擦语义/终点预测/velocity handoff）、K·吸附（K1）、K5·速度接管

## K·跟手（Tracking / 1:1 Follow）

- **领域**：交互/动效 · **成本**：低
- **定义**：指针移动时元素 1:1 实时跟随——拖拽、滑动、下拉刷新的基础手感。"跟手"的对立面是过渡（transition）。
- **症状**：拖动有迟滞（元素慢半拍）；用了 transition 导致拖动"黏"；跟手中途跳变。
- **决策点**：
  ① **跟随律**——1:1 线性跟随是默认；超边界改阻尼跟随（`offset = max + Δ*0.3`，B45）；磁性元素改平方衰减跟随（R11·F1）；
  ② **禁用 transition**——拖动期间 `transition: none`，松手才恢复（transition 是"从A到B自动播放"，跟手是"指针到哪我到哪"，两者互斥）；
  ③ **更新通道**——只改 transform（GPU），不碰 top/left（B45 坑：top/left 动画=卡顿）；
  ④ **多指/多源**——触摸与鼠标并存时用 Pointer Events 统一（K7）。
- **实现**：`pointermove → el.style.transform = translate(x,y)`（无 transition）；松手后上 transition/spring 做落位。
- **验收**：60fps 跟手；快速甩动不丢帧；松手落位 spring 顺滑接管（初速度接管见 K5·速度接管）。
- **衔接**：B45§六（跟手+阻尼）、R11·F1（阻尼跟随）、R12（velocity handoff）、K7·Pointer事件

## K·拖拽边缘自动滚动（Drag Edge Auto-Scroll）

- **领域**：拖拽/滚动 · **成本**：中
- **定义**：拖拽中指针逼近容器/视口边缘时容器自动滚动，让拖到的目标"进来"。长列表拖拽的隐性必备能力。
- **症状**：拖到容器底部想放到更靠下位置，列表死活不滚，只能松手→滚动→再拖（两段式）；滚动后落点判定错位（文档坐标变了但命中还按旧位置算）；短列表没发作被漏检，上线后用户列表变长才暴露（cases/03 实证）。
- **适用**：可滚动容器内的拖拽（长列表排序/看板跨列）｜ **不适用**：不滚动的容器（决策点①直接不适用）。
- **决策点**：
  ① **触发区**——距边缘多少 px 开始滚？视口/容器 48-80px（cases/03 取 64px）；边缘区内深度越深滚越快
  ② **速度律**——线性 ramp（0→约 14px/帧 按边缘深度）或分段档；起速要慢（接近边缘≠意图滚动）
  ③ **滚动补偿**——容器滚动后指针文档坐标变了：重算 dy/命中 rect（rects 缓存须滚动后失效重算），否则落点漂一格
  ④ **仲裁**——滚动是拖拽的辅助手段不是接管：指针仍在拖动（元素跟随不中断）；`touch-action` 声明的拖拽区内自动滚动不受 pan-y 拦截影响
- **实现**：`pointermove` 中算指针到容器四边距离 → 进入触发区用 rAF 循环 `scrollTop += v(depth)`；容器 scroll 事件里作标记位，`pointermove` 重算时读最新 scroll 补偿；拖出容器边界（更外圈判定，cases/03 取 Y±48/X±64）转无效放下路径。
- **验收**：拖到边缘容器匀速滚且元素持续跟手；滚动后落点判定不漂移；快速划过边缘区不误触发（进入即滚但离开即停）；触屏拖拽可用。
- **衔接**：K·跟手、K·拖拽碰撞检测（rects 缓存）、K6·滚动工程、K·无效放下（越界转出）

## 拖拽全链路速查（六态 × 每态要决定的事）

| 状态 | 关键决策 | 参数锚点 |
|---|---|---|
| 1. 可拖暗示 | 怎么表达"能拖" | `cursor:grab` + 手柄图标 |
| 2. 按下抓取 | 拿起反馈/阈值判定 | scale(1.03)+rotate(2deg)+阴影加深；阈值 4-8px |
| 3. 拖动中 | 预览/碰撞检测/目标判定/边缘滚动 | opacity .9、pointer-inside、hysteresis ±4px、边缘 64px 触发 |
| 4. 悬停目标 | 占位/指示/合法性预显 | 主色 10% 底 + 2px dashed + 插入线；no-drop 光标 |
| 5. 松开落下 | 落位动画/惯性/吸附 | spring 400ms / 惯性 0.95 / 终点预测吸附 |
| 6. 无效放下 | 回滚/弹回/取消 | no-drop 预显 + spring 弹回 + 轻 shake + Esc 取消 |
