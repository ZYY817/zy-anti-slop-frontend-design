# B58 · 视觉过渡与连续性

> 界面之间的"跳变"是廉价感的第一来源。
> 顶级产品的秘密不是"页面变得多美",而是**从一个状态到另一个状态的过程本身就是设计**。
> 元素不会消失,它们**变形**;页面不会切换,它们**流动**;
> 用户不会感到"跳到了新页面",他们感到"内容在演化"。
> 这份文档拆的是:如何用视觉过渡把碎片化的界面缝合成连续的叙事。

---

## 二、连续性的三大原则

### 2.1 元素守恒律(Object Constancy)

**核心**:相同的元素在前后状态中应该被感知为"同一个",而不是消失后新建。

```
❌ 反例:
点击列表项 → 列表消失 → 详情页出现
用户体验: "这两个东西没关系"

✅ 正例:
点击列表项 → 该项目变大/变形 → 变成详情页头图
用户体验: "刚才那个东西展开成了详情"
```

### 2.2 空间可预测性

用户点击的东西,应该从**它所在的位置**开始变化,不是随机弹出。

```css
/* ❌ 弹窗从屏幕中心弹出,与触发按钮无关 */
.modal { animation: fade-in-center 200ms; }

/* ✅ 弹窗从触发按钮位置扩展出来 */
.modal {
  transform-origin: var(--origin-x) var(--origin-y);
  animation: expand-from-origin 300ms cubic-bezier(0.2, 0, 0, 1);
}
```

### 2.3 因果链清晰

**每一次视觉变化都应该有明确的"原因"和"结果"**:

```
用户点击(因) → 按钮按下反馈(即时) → 加载态(过程) → 新内容出现(结果)
```

每一步之间不能有"断层"——用户始终知道自己在哪、发生了什么。

## 三、View Transitions API(2025+ 神器)

### 3.1 基础用法

```javascript
// 同页面状态过渡
function toggleView(callback) {
  if (!document.startViewTransition) {
    callback();
    return;
  }
  document.startViewTransition(() => callback());
}

// 用法
toggleView(() => {
  document.querySelector('.list').classList.toggle('grid-view');
});
```

### 3.2 跨页面过渡(SPA + MPA 通用)

```html
<!-- MPA 启用跨页面过渡 -->
<meta name="view-transition" content="same-origin">
```

```css
/* 页面根级过渡 */
::view-transition-old(root) {
  animation: fade-out 200ms;
}
::view-transition-new(root) {
  animation: fade-in 300ms;
}

@keyframes fade-out { to { opacity: 0; } }
@keyframes fade-in  { from { opacity: 0; } }
```

### 3.3 共享元素过渡(Shared Element)

**这是最强的连续性武器**。

```html
<!-- 列表页 -->
<a href="/product/123">
  <img class="product-image" src="thumb.jpg"
       style="view-transition-name: product-123">
  <h3 style="view-transition-name: title-123">产品名</h3>
</a>

<!-- 详情页 -->
<div class="detail">
  <img class="hero-image" src="full.jpg"
       style="view-transition-name: product-123">
  <h1 style="view-transition-name: title-123">产品名</h1>
</div>
```

浏览器会自动:
1. 记录列表页元素的位置/尺寸
2. 记录详情页元素的位置/尺寸
3. **在两者之间平滑变形**

**结果**:缩略图 → 大图的过渡,完全无缝。像 Apple 相册的效果。

```css
/* 自定义共享元素过渡的曲线 */
::view-transition-group(product-123) {
  animation-duration: 500ms;
  animation-timing-function: cubic-bezier(0.2, 0, 0, 1);
}
```

### 3.4 分层控制过渡

```css
/* 头部固定不参与过渡 */
.header { view-transition-name: header; }

::view-transition-group(header) {
  animation: none;
}

/* 内容区独立过渡 */
.content { view-transition-name: content; }

::view-transition-old(content) {
  animation: slide-out 250ms cubic-bezier(0.4, 0, 1, 1);
}
::view-transition-new(content) {
  animation: slide-in 300ms cubic-bezier(0, 0, 0.2, 1);
}

@keyframes slide-out {
  to { transform: translateX(-30px); opacity: 0; }
}
@keyframes slide-in {
  from { transform: translateX(30px); opacity: 0; }
}
```

## 四、状态间的变形

### 4.1 按钮 → 加载 → 完成

```html
<button class="submit-btn" data-state="idle">
  <span class="btn-text">提交</span>
  <span class="btn-spinner"></span>
  <span class="btn-check">✓</span>
</button>
```

```css
.submit-btn {
  padding: 12px 32px;
  min-width: 120px;
  border-radius: 8px;
  transition: min-width 300ms cubic-bezier(0.4, 0, 0.2, 1),
              background 300ms;
  position: relative;
}

/* idle 态 */
.submit-btn[data-state="idle"] .btn-text    { display: inline; }
.submit-btn[data-state="idle"] .btn-spinner,
.submit-btn[data-state="idle"] .btn-check   { display: none; }

/* loading 态: 缩窄成圆,只剩 spinner */
.submit-btn[data-state="loading"] {
  min-width: 44px;
  padding: 12px;
  border-radius: 22px;
}
.submit-btn[data-state="loading"] .btn-text,
.submit-btn[data-state="loading"] .btn-check   { display: none; }
.submit-btn[data-state="loading"] .btn-spinner { display: inline-block; }

/* success 态: 展开变绿,显示对勾 */
.submit-btn[data-state="success"] {
  background: var(--success);
}
.submit-btn[data-state="success"] .btn-text,
.submit-btn[data-state="success"] .btn-spinner { display: none; }
.submit-btn[data-state="success"] .btn-check   { display: inline; }
```

**关键**:整个过程按钮**没有消失过**,只是**形变**。用户感受到的是"这个按钮在完成任务"。

### 4.2 卡片展开成详情

```css
.card {
  transition:
    transform 400ms cubic-bezier(0.4, 0, 0.2, 1),
    width 400ms cubic-bezier(0.4, 0, 0.2, 1),
    height 400ms cubic-bezier(0.4, 0, 0.2, 1),
    border-radius 400ms;
}

.card.expanded {
  position: fixed;
  inset: 24px;
  width: auto;
  height: auto;
  border-radius: 24px;
  z-index: 100;
}

/* FLIP 技术: 用 transform 模拟位置变化(性能好) */
.card.animating {
  will-change: transform;
}
```

### 4.3 FLIP 技术手动实现

```javascript
// F irst - L ast - I nvert - P lay
function flipAnimate(element, callback) {
  // 1. First: 记录初始位置
  const first = element.getBoundingClientRect();

  // 2. 执行改变(不要 animate,瞬间到位)
  callback();

  // 3. Last: 记录最终位置
  const last = element.getBoundingClientRect();

  // 4. Invert: 用 transform 让它"看起来"还在初始位置
  const dx = first.left - last.left;
  const dy = first.top - last.top;
  const sx = first.width / last.width;
  const sy = first.height / last.height;

  element.animate([
    { transform: `translate(${dx}px, ${dy}px) scale(${sx}, ${sy})` },
    { transform: 'none' }
  ], {
    duration: 400,
    easing: 'cubic-bezier(0.4, 0, 0.2, 1)'
  });
}
```

## 五、页面转场设计

### 5.1 转场类型选型

| 转场类型 | 语义 | 适用 |
|---|---|---|
| **淡入淡出** | 内容替换,无空间关系 | Tab 切换/相同层级页面 |
| **左右滑动** | 前进/后退(层级关系) | 移动端导航栈/多步表单 |
| **上下滑动** | 弹出/收起(临时视图) | Modal/半屏/详情浮层 |
| **缩放** | 进入内部/离开返回 | 图片点开/详情打开 |
| **共享元素** | 元素延续到下一屏 | 卡片 → 详情/列表 → 项目 |
| **切换** | 完全不同上下文 | 登录/主应用之间 |

### 5.2 移动端导航栈的经典转场

```css
/* iOS 风格:右进左出(前进) / 左进右出(后退) */

/* 前进 */
.page-enter { transform: translateX(100%); }
.page-enter-active {
  transform: translateX(0);
  transition: transform 350ms cubic-bezier(0.4, 0, 0.2, 1);
}

.page-exit { transform: translateX(0); }
.page-exit-active {
  transform: translateX(-30%);  /* 后退页向左退 30%,营造深度 */
  opacity: 0.5;
  transition: transform 350ms cubic-bezier(0.4, 0, 0.2, 1);
}

/* 前一页有一定视觉重量,不完全消失 */
```

### 5.3 Modal 的进出

```css
.modal-backdrop {
  position: fixed;
  inset: 0;
  background: oklch(0% 0 0 / 0);
  transition: background 250ms;
}

.modal-backdrop.open {
  background: oklch(0% 0 0 / 0.5);
  backdrop-filter: blur(4px);
}

.modal {
  position: fixed;
  top: 50%;
  left: 50%;
  transform: translate(-50%, -50%) scale(0.95);
  opacity: 0;
  transition:
    transform 300ms cubic-bezier(0.2, 0, 0, 1),
    opacity 250ms;
}

.modal.open {
  transform: translate(-50%, -50%) scale(1);
  opacity: 1;
}

/* 关闭时更快(用户想快速关掉) */
.modal.closing {
  transition:
    transform 180ms cubic-bezier(0.4, 0, 1, 1),
    opacity 150ms;
  opacity: 0;
  transform: translate(-50%, -50%) scale(0.98);
}
```

**规律**:入场时长 > 出场时长(比例约 1.5:1)。入场需要建立注意,出场追求快速。

## 六、加载态到内容态的过渡

### 6.1 骨架屏 → 内容 crossfade

```css
.skeleton {
  opacity: 1;
  transition: opacity 200ms;
}

.content {
  opacity: 0;
  transition: opacity 300ms 100ms;  /* 延迟 100ms,骨架先淡出 */
}

.loaded .skeleton { opacity: 0; pointer-events: none; }
.loaded .content { opacity: 1; }
```

**核心**:骨架屏的**尺寸和位置**必须匹配最终内容,才叫连续。

### 6.2 分块渐进加载(Progressive Reveal)

```css
.item {
  opacity: 0;
  transform: translateY(12px);
  transition: opacity 400ms, transform 400ms cubic-bezier(0.4, 0, 0.2, 1);
}

.item.loaded { opacity: 1; transform: translateY(0); }

/* 交错入场 */
.item:nth-child(1) { transition-delay: 0ms; }
.item:nth-child(2) { transition-delay: 60ms; }
.item:nth-child(3) { transition-delay: 120ms; }
.item:nth-child(4) { transition-delay: 180ms; }
```

### 6.3 图片渐进式加载

```css
.progressive-image {
  filter: blur(20px);
  transition: filter 400ms;
}

.progressive-image.loaded {
  filter: blur(0);
}

/* 或用低质量占位符(LQIP) */
.progressive-image {
  background: url(low-quality-tiny.jpg) center/cover;
}
```

## 七、Staggered 编排(交错入场)

### 7.1 时间编排原则

```css
/* 主元素先入场,次要元素跟随 */
.hero-title    { animation-delay: 0ms; }
.hero-subtitle { animation-delay: 100ms; }
.hero-cta      { animation-delay: 200ms; }
.hero-hint     { animation-delay: 300ms; }
```

### 7.2 CSS 变量批量交错

```css
.item {
  --i: 0;
  animation: fade-up 600ms cubic-bezier(0.4, 0, 0.2, 1) both;
  animation-delay: calc(var(--i) * 50ms);
}

@keyframes fade-up {
  from { opacity: 0; transform: translateY(20px); }
  to   { opacity: 1; transform: translateY(0);    }
}
```

```html
<li class="item" style="--i: 0">...</li>
<li class="item" style="--i: 1">...</li>
<li class="item" style="--i: 2">...</li>
<li class="item" style="--i: 3">...</li>
```

### 7.3 交错时长建议

```
密集元素(列表项/卡片): 40-60ms 间隔
中等元素(区块内内容):   80-120ms 间隔
大型元素(区块之间):     150-250ms 间隔

总时长上限:  单屏入场总时长 ≤ 800ms,超过就"拖"
```

## 九、乐观更新与感知性能

### 9.1 乐观更新模式

```javascript
// 不等服务器,先更新 UI
async function likePost(postId) {
  // 1. 立即更新 UI(乐观)
  incrementLikeCount(postId);
  updateHeartIcon(postId, true);

  try {
    // 2. 后台请求
    await api.like(postId);
  } catch (error) {
    // 3. 失败时优雅回滚
    decrementLikeCount(postId);
    updateHeartIcon(postId, false);
    showToast('点赞失败,请重试');
  }
}
```

### 9.2 感知加速技巧

```
即时反馈(< 100ms):     hover/click 的瞬间响应
简短加载(100-300ms):   骨架屏/占位符
中等加载(300-1000ms):  进度指示器/spinner
长时加载(> 1s):        进度条 + 说明"正在..."/预估时间
超长加载(> 10s):       分步展示中间结果
```

### 9.3 断续内容的连续过渡

```css
/* 内容更新时不要突然刷新,而是 crossfade */
[data-content-state="updating"] {
  opacity: 0.5;
  transition: opacity 200ms;
}

[data-content-state="updated"] {
  animation: subtle-flash 400ms;
}

@keyframes subtle-flash {
  0%   { background: var(--brand-subtle); }
  100% { background: transparent; }
}
```

## 十一、踩坑指南

### 坑1:弹窗从屏幕中心弹出,与点击位置无关
**症状**:用户点击右下角按钮,弹窗从中心弹出,感觉不连续。
**解法**:记录点击位置作为 transform-origin,从点击点扩展。

### 坑2:入场慢出场也慢
**症状**:关个弹窗要等 400ms,烦人。
**解法**:出场时长 ≈ 入场 × 0.6,让用户"想关就能立刻关"。

### 坑3:View Transitions 名字冲突
**症状**:多个元素用同一 `view-transition-name`,动画错乱。
**解法**:每个元素唯一 name,可用 ID 拼接。

### 坑4:骨架屏尺寸和真实内容不匹配
**症状**:骨架消失后内容"跳"了一下(CLS)。
**解法**:骨架的宽高必须严格等于真实内容尺寸。

### 坑5:交错入场时长太长
**症状**:20 个卡片依次入场,最后一个 2 秒后才出现。
**解法**:总时长 ≤ 800ms,超过就减少每项延迟或分批。

### 坑6:动效阻塞交互
**症状**:入场动画期间按钮点不动。
**解法**:动画元素加 `pointer-events: none`,完成后恢复。

### 坑7:忽略 prefers-reduced-motion
**症状**:前庭失调用户看到剧烈动画会晕。
**解法**:全站尊重 `prefers-reduced-motion`,动画降级为 opacity 或直接跳过。

### 坑8:Modal 关闭时背景先消失,内容后消失
**症状**:感觉两个东西不是一体。
**解法**:同步过渡,或让内容先消失背景后消失。

### 坑9:滚动驱动动画在不支持浏览器上闪烁
**解法**:用 `@supports (animation-timeline: scroll())` 特性检测。

## 十二、谁在用(连续性典范)

| 产品 | 连续性手法 | 值得学的 |
|---|---|---|
| **Apple 相册** | 缩略图 → 大图共享元素 | 完美的元素守恒,零跳变 |
| **iOS 系统** | 应用图标 → 应用启动 | 图标"变形"成整个应用界面 |
| **Airbnb** | 房源卡 → 详情页 | 主图共享元素过渡,标题跟随 |
| **Framer 官网** | Section 滚动叙事 | 滚动驱动动画,section 无缝衔接 |
| **Linear** | 状态间形变 | 按钮 loading/success 全程形变 |
| **Superhuman** | 邮件列表 → 详情 | 键盘导航时的滑动切换极致丝滑 |
| **Notion** | 页面切换 | 侧栏保持,内容区无缝替换 |
| **Vercel Dashboard** | 项目切换 | 数据更新用 crossfade 不是刷新 |
| **Instagram** | 照片点开 | 缩略图 → 全屏的 Shared Element |

## 检验清单

- [ ] 相同元素在前后状态间用共享元素过渡(不是消失重建)
- [ ] 弹窗/浮层从触发位置扩展(不是屏幕中心)
- [ ] 页面切换有明确转场(不是白屏跳变)
- [ ] 按钮 loading/success 是形变,不是替换
- [ ] 骨架屏尺寸严格匹配真实内容
- [ ] 加载态到内容态是 crossfade(不是硬切)
- [ ] 列表入场用 stagger(总时长 ≤ 800ms)
- [ ] 出场时长 ≈ 入场时长 × 0.6
- [ ] 有乐观更新(不用等服务器)
- [ ] 使用了 View Transitions API(现代浏览器)
- [ ] 尊重 prefers-reduced-motion
- [ ] 动画元素完成前 pointer-events: none 防止误点
- [ ] 滚动驱动动画有 @supports 特性检测降级
- [ ] 缓动曲线全站统一(不是每处乱选)
