# K1 · 吸附、停靠与几何约束

> 「接近某个位置时界面替你完成对齐」的全部决策对象。吸附体验的差异不在"有没有"，而在阈值、拉动感、落位、失败处理四个决策点上。
> 碎片知识原散见 B45/R11·F1/R12·N5/V9/G3/B65/R16/R20，本文件聚合为决策对象，原理细节用衔接字段指回。

---

## K·吸附（Snapping）

- **领域**：交互/动效 · **成本**：低
- **定义**：拖拽、滚动或移动中的元素接近目标位置时，由系统接管完成最终对齐。用户松手后元素"咔"地落位，而不是停在任意中间态。
- **症状（怎么知道这里有问题）**：松手停在半档；落点需要用户反复微调；轮播翻页判定靠运气；列表项错位看起来"歪了"。
- **适用**：轮播、抽屉/bottom sheet、滑动操作、对齐工具、分页滚动 ｜ **不适用**：自由画布、像素级摆放、创造性涂鸦工具。
- **决策点**：
  ① **触发阈值**——距离还是速度触发？阈值多少？
  ② **磁性拉动感**——进入阈值后位移怎么映射（线性/平方衰减/弹簧接管）？
  ③ **松手落位**——落位动画时长与曲线（spring 参数）？
  ④ **失败处理**——越界怎么办？中途取消怎么办？目标无效怎么办？
- **实现**：
  - CSS 滚动吸附：`scroll-snap-type: x mandatory` + `scroll-snap-align: center`（轮播/分页首选，B65 坑12、R20 配方）
  - JS 吸附：拖拽位移进入 **12px** 阈值即接管，吸附瞬间给小 spring（R12·N5）
  - 落位 spring 档位（R12·N1）：干脆 stiffness 400/damping 30｜标准 200/24｜柔软 120/18｜弹跳 300/12
  - 吸附瞬间可加 haptic **8ms** 轻点（R16·P5 触觉分级）
- **验收**：阈值内必吸附、阈值外不吸附；吸附瞬间有落定反馈（视觉/触觉至少一个）；取消操作可弹回；无"卡在半档"状态。
- **衔接**：B45§五（scroll-snap 手感）、R12·N5（12px 阈值+spring）、G3（bottom sheet 三档吸附）、V10（滚动 pin/snap 语境）、K9·吸附vs停靠 辨析

## K·停靠（Docking）

- **领域**：交互/空间 · **成本**：中
- **定义**：面板、窗口或工具栏被固定到某个区域/边缘的持久状态——吸附是瞬时对齐动作，停靠是持续停留状态（辨析见 K9）。
- **症状**：面板能拖走但回不去；停靠区不暗示可停靠；停靠后周围内容不重新布局（被遮挡或留空洞）；解除停靠无恢复路径。
- **适用**：IDE/设计器面板、桌面应用工具栏、浮动工具球、复杂 dashboard ｜ **不适用**：单次消费内容页、简单工具提示。
- **决策点**：
  ① **停靠指示**——拖动经过停靠区时的预览形态（高亮区/幽灵占位/边缘亮条）？
  ② **停靠布局**——停靠后周围内容 reflow 还是被覆盖？
  ③ **尺寸接管**——停靠后面板尺寸是自适应容器还是保持拖来时的尺寸？
  ④ **解除路径**——拖出/双击/按钮三种解除方式保留几种？停靠状态是否持久化（localStorage）？
- **实现**：拖动经过候选区域时显示 drop 指示（主色 10% 底 + 2px dashed，B45 drop-zone 配方）；停靠后容器进入 grid/flex 布局而非 absolute；记住每个用户的停靠位置。
- **验收**：停靠指示在拖入前出现（不事后解释）；停靠/解除都不丢面板内容；刷新后停靠状态保持；键盘/触屏有等效操作。
- **衔接**：D1（drawer/panel 组件名）、B53§sticky/fixed（固定 vs 停靠的边界）、K9·吸附vs停靠

## K·边缘吸附（Edge Snapping）

- **领域**：交互/空间 · **成本**：低
- **定义**：元素接近视口或容器边缘时自动贴合边缘——浮动按钮贴边、悬浮球自动靠到最近的屏幕边。
- **症状**：悬浮球可以停在屏幕正中间挡住内容；贴边后超出安全区；贴边动画是瞬移而非滑动。
- **决策点**：
  ① **吸附边集合**——只吸左右两竖边，还是四边都吸？角落是否算独立停靠点？
  ② **安全距离**——贴边后离屏边的 inset（含 safe-area）？
  ③ **回缩形态**——闲时是否半隐藏（露出 1/3 提示可拖回）？
  ④ **贴边动画**——松手后滑动过去的时长/曲线？
- **实现**：松手时比较中心点到各边距离 → 动画到最近边；移动端 inset ≥ `env(safe-area-inset-*)` + 8px；spring 落位（stiffness 200/damping 24）。
- **验收**：松手必贴边不留中间态；不遮挡主内容区；可再次拖出；键盘可达。
- **衔接**：G3（移动端安全区/悬浮元素）、B45（spring 落位参数）

## K·磁性吸附（Magnetic Snapping / Magnetic Hover）

- **领域**：交互/动效 · **成本**：低
- **定义**：指针接近元素时，元素（或指针）被"吸引"产生偏移——吸附的主动式：目标来找指针。
- **症状**：磁吸半径过大导致指针"失控"；偏移后元素脱离点击热区判定；多个磁吸元素互相抢指针；触屏上磁吸残留。
- **决策点**：
  ① **吸引半径**——多远开始吸（常用 **120px** 内）？
  ② **最大偏移**——元素最多被拉多远（常用 **8px**，克制）？
  ③ **衰减曲线**——距离如何映射到偏移量，`(1 - d/120)²` 平方衰减比线性更"有吸力"（R11·F1）？
  ④ **松手回位**——指针离开后弹回方式（spring）？触屏是否整个禁用？
- **实现**：pointermove 计算指针-元素距离 → 半径内按比例 translate；`@media (hover: none)` 下整体禁用。
- **验收**：偏移 ≤8px 不破坏布局；指针离开后 spring 回位无残影；热区判定跟随元素实际位置；触屏无残留态。
- **衔接**：R11·F1（120px/8px/衰减公式）、V9（磁性吸附条目）、R20（磁吸跟随 lerp 0.12）、K3·磁性光标

## K·几何约束（Geometric Constraints）

- **领域**：空间/工程 · **成本**：中
- **定义**：对元素位置、尺寸、比例施加的硬性限制——宽高比锁定、最小/最大尺寸、拖动范围限制、对齐网格。
- **症状**：拖拽可把元素拉出容器外；resize 破坏宽高比导致图片变形；缩到极小后控件不可再操作；网格吸附与自由拖动互相打架。
- **决策点**：
  ① **约束种类**——clamp（范围）/ ratio（比例）/ step（步进网格）各需不需要？
  ② **越界反馈**——硬性挡住还是橡皮筋式阻尼（超出后位移递减，阻尼系数 ~0.3，B45）？
  ③ **约束可视化**——到边界时是否给视觉信号（边框变色/手柄变灰）？
  ④ **约束解除**——修饰键（Shift 自由拖动）是否放开约束？
- **实现**：`clamp(min, val, max)`；拖动越界时 `offset = max + (offset - max) * 0.3`（B45 阻尼公式）；resize 时按原始宽高比反解另一维。
- **验收**：任何操作路径下元素不出合法域；越界有即时反馈而非无声失败；约束规则在代码中集中声明而非散落各 handler。
- **衔接**：B45§六（越界阻尼）、R12（弹性边界物理）、K4·拖拽碰撞检测

## K·对齐辅助线（Smart Guides）

- **领域**：交互/视觉 · **成本**：中
- **定义**：拖动元素接近其他元素的边缘/中心/等距关系时，显示临时参考线并配合吸附——设计工具里"自发出现的那根线"。
- **症状**：拖动时辅助线闪烁抖动；线出现了但不吸附（假提示）；元素多时辅助线爆炸满屏线。
- **决策点**：
  ① **参照系**——对齐目标是兄弟元素边缘、中心线、等距分布还是容器网格？
  ② **优先级**——多个候选对齐时谁赢（常用：中心 > 边缘 > 等距；距离近者胜）？
  ③ **出现时机**——进入多少 px 内显示（配合 12px 吸附阈值）？
  ④ **样式语言**——线的颜色/粗细/虚实（洋红 1px 惯例）+ 间距标注数字何时出现？
- **实现**：拖动帧中计算与候选参照物的距离场 → <12px 显示参考线 + 接管位移；间距相等时画等距标识（三条短线）。
- **验收**：线与吸附同步出现（有线必吸）；无候选时无残线；高 DPR 下线宽 1px 锐利。
- **衔接**：R12·N5（12px 吸附阈值）、B46（间距标注规范）、B68（图标光学对齐）

## K·命中区域（Hit Area）

- **领域**：交互/工程 · **成本**：低
- **定义**：实际响应指针操作的区域——可以大于视觉元素本体（视觉 20px、点击 44px）。
- **症状**：小图标按钮"看着能点但点不中"；相邻元素热区重叠导致误触；热区小于平台最小触控尺寸。
- **决策点**：
  ① **热区扩多大**——触控 ≥44×44px（iOS/Android 惯例）、桌面可小但仍建议 ≥24px？
  ② **外扩方式**——伪元素 `inset: -12px` 外扩还是 padding？
  ③ **相邻竞争**——两热区重叠时谁赢（z 序/方向预测）？
  ④ **hover 判定区**——hover 区与点击区是否一致（tooltip 场景 hover 区可更大）？
- **实现**：`.icon-btn::before { content:''; position:absolute; inset:-12px }`（B45）；移动端严格 44px。
- **验收**：元素边缘 12px 内点击有效；误触率不升；hover 区不误挡下层可点元素。
- **衔接**：B45（点击区外扩 12px 配方）、G3（触控目标）、C4（触控目标 WCAG 2.5.5/2.5.8）

## K·拖放目标判定（Drop Target）

- **领域**：交互/工程 · **成本**：中
- **定义**：拖拽悬停时系统如何判定"用户想放到哪"——指针在哪个区域内（pointer-inside）、还是拖动元素与目标相交面积最大（intersection）。
- **症状**：拖到两个目标交界处高亮乱跳；视觉上半张卡片进了目标区却不算；目标区小而密时几乎无法精确投放。
- **决策点**：
  ① **判定算法**——pointer-inside（指针在哪算哪）vs intersection（元素相交比例，常用 >50%）vs 最近中心点？
  ② **目标分级**——嵌套目标（拖到组内某格 vs 拖到组）谁优先？
  ③ **目标反馈**——高亮/虚线/占位符/插入指示线选哪种（B45：主色 10% 底 + 2px dashed）？
  ④ **无效目标**——不允许的放置位置给什么反馈（禁标 cursor:no-drop / 目标区变灰）？
- **实现**：小目标用 pointer-inside（跟手）；大区块/排序用 intersection 或插入位置预测（between-cards 指示线）；pointer capture 锁定拖拽期间事件归属。
- **验收**：交界处不抖动（判定有滞后带/hysteresis）；目标反馈在拖入前出现；键盘拖拽有等效目标循环。
- **衔接**：B45§四（drop-zone CSS 配方）、K4·拖拽全链路、K1·几何约束
