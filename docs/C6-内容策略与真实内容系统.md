# C6 · 内容策略与真实内容系统

> **定位**：补足“内容有微文案，但没有内容系统”的缺口。AI 生成的前端不能只拥有漂亮容器，还必须拥有真实的内容结构、长度、状态、语气和数据关系。
>
> 与 [C5-微文案.md](C5-微文案.md) 的关系：C5 负责句子和语气；C6 负责内容模型、页面层级、数据形态、状态内容和本地化约束。

---

## 一、内容先于组件

生成页面前先回答：

```text
谁在什么情境下阅读或操作？
他们需要先知道什么、再判断什么、最后做什么？
内容的最小单位是什么？
哪些内容是主内容、证据、状态、操作和元数据？
```

### 内容对象模板

```yaml
content_object: 项目 / 商品 / 文章 / 对话 / 报表 / 任务
primary_label: 用户看一眼就能识别的名称
summary: 1-2 句摘要
status: 当前状态 + 人话解释
metadata: [作者, 时间, 数量, 来源, 更新时间]
primary_action: 当前对象最重要的动作
secondary_actions: 次要动作和更多菜单
evidence: 图片、引用、指标、来源或历史
permissions: 谁能看、改、分享、删除
variants: 短标题、长标题、空值、异常值、多语言
```

## 二、页面内容层级

用“任务层级”决定视觉层级，不要先用卡片决定内容：

```text
1. Orientation   我在哪里？这页要解决什么？
2. Value          哪个结果/信息最重要？
3. Evidence       我为什么相信它？
4. Action         下一步能做什么？
5. Status         现在发生了什么？是否需要我处理？
6. Detail         我需要深入时还能看到什么？
```

对应规则：

- 主标题说明对象或任务，不写空泛口号。
- 摘要负责降低理解成本，不重复标题。
- CTA 用具体动词和对象：`创建项目`、`查看发票`、`重试生成`。
- 元数据服务于比较、判断或追溯，不为填空堆信息。
- 装饰不能取得比主内容更强的对比度、面积或动效。

## 三、真实数据和长度测试

禁止默认使用 Lorem Ipsum、`John Doe`、`1234`、随机百分比和互相矛盾的 KPI。模拟数据也必须像真实产品：

| 测试形态 | 至少准备 |
|---|---|
| 0 条 | 首次使用空态 + 原因 + 下一步 |
| 1 条 | 单项布局不能依赖网格填满 |
| 正常量 | 能看出排序、分组、状态和层级 |
| 大量数据 | 分页/虚拟滚动/筛选/汇总策略 |
| 超长标题 | 不截断关键信息，不撑破按钮 |
| 超长用户名/标签 | 可换行、收缩或提供完整查看 |
| 缺失图片/字段 | 有明确占位和替代文本 |
| 异常数字 | 负数、0%、超大金额、未知值有语义 |

### 数据一致性规则

- 数字必须有单位、时间范围和比较基准。
- 图表、KPI、表格和摘要不能互相矛盾。
- “增长 12.5%”必须说明相对什么周期。
- 状态名称在导航、列表、详情和通知中保持一致。
- 示例内容的密度应匹配真实产品，而不是为了视觉均匀随意缩短。

## 四、状态内容系统

每个异步或可编辑对象至少定义：

```text
idle → loading → success
idle → loading → error → retry / edit / contact-support
empty → first-action → populated
populated → filtering → no-results → clear-filter
populated → permission-denied → request-access
edited → saving → saved / save-error → retry
```

每种状态都要有：

1. 状态名称；
2. 用户能理解的解释；
3. 当前是否需要行动；
4. 可执行的下一步；
5. 是否保留用户已输入或已完成的内容。

示例：

```text
网络请求失败
无法加载本次账单。你的筛选条件已保留。
[重试] [检查网络]
```

避免：`出错了`、`暂无数据`、`处理中...` 这类没有原因和下一步的空壳文案。

## 五、内容与视觉的协同

内容形态决定布局和媒介：

| 内容特征 | 设计决策 |
|---|---|
| 长文、深阅读 | 65-75ch、目录、段落节奏、引用和进度 |
| 高密度数据 | 明确列优先级、数字对齐、筛选、汇总和局部留白 |
| 探索式内容 | 预览、分类、推荐、保存和返回位置 |
| 高风险操作 | 后果说明、权限、确认或撤销、审计记录 |
| AI 输出 | 流式状态、来源、置信度/不确定性、编辑、重试和停止 |
| 多媒体叙事 | 媒介选择服务叙事，不为炫技加入视频或 3D |

## 六、语气、个性化与本地化

### 语气契约

```yaml
voice: 专业、克制、可信
person: 统一使用“你”
sentence: 短句、主动语态、具体动词
humor: 仅在低风险成功/空态中使用
error_tone: 不责怪、不掩盖、说明恢复方式
```

### 个性化

明确区分：

- 用户主动设置的偏好；
- 基于行为的推荐；
- 系统推断但需要解释的内容；
- 不应被推断或暴露的敏感信息。

个性化不应改变核心导航、状态颜色或关键术语的稳定性。

### 本地化

- 中文、英文、德文、法文、日文、阿拉伯文至少测试标题、按钮、表格和错误。
- 预留约 30% 文案膨胀，按钮避免固定宽度。
- 日期、时间、数字、货币使用 locale formatter。
- 使用逻辑属性支持 RTL，不把方向写死为 left/right。
- 避免图片内文字、文化特定隐喻和可翻译字符串拼接。

## 七、可直接放进生成 Prompt 的内容协议

```markdown
【内容系统】
- 先定义页面的核心对象、核心任务和内容层级，再决定组件。
- 使用真实或合理模拟的数据：包含单位、日期、状态、来源和彼此一致的数字关系。
- 不使用 Lorem Ipsum、无意义占位词、随机 KPI 或泛化营销口号。
- 每个主要对象定义标题、摘要、状态、元数据、主动作、次动作、权限和异常形态。
- 完整覆盖 empty / loading / success / error / no-results / permission-denied / saving。
- 错误文案说明发生了什么、为什么、用户下一步怎么做，并保留已输入内容。
- 测试 0/1/正常量/大量数据、长标题、长标签、缺失媒体和多语言膨胀。
- 统一语气、人称、术语、日期、数字和货币格式；支持 RTL 和逻辑属性。
```

## 八、内容验收清单

- [ ] 不看视觉也能说清页面的对象、任务和下一步
- [ ] 真实数据关系自洽，单位和时间范围完整
- [ ] 主内容、证据、状态、操作和元数据层级清楚
- [ ] 空态有原因和引导，错误有恢复路径，加载有阶段感
- [ ] 长短内容、0/1/大量数据不会改变产品逻辑
- [ ] 文案能被翻译、扩展和朗读，不依赖颜色或图片内文字
- [ ] 个性化有边界，不暴露不必要的推断
