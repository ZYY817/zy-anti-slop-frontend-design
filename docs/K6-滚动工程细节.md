# K6 · 滚动工程细节

> 滚动是网页最"免费"的交互，也是最容易被做坏的交互——视差/pin/scrub 的花活（V10）之外，是一整层没人系统讲过的工程细节：位置恢复、锚定、穿透、锁定、偏移。
> 碎片原在 B53、G3、R9、B45、D1、V10，本文件聚合为决策对象。

---

## K·滚动恢复（Scroll Restoration）

- **领域**：工程/交互 · **成本**：低
- **定义**：用户前进/后退/刷新页面时，滚动位置恢复到哪里——浏览器默认恢复上次位置，SPA 路由切换需要手动接管。
- **症状（怎么知道这里有问题）**：从详情页返回列表回到顶部（浏览进度全丢）；锚点刷新后落在错误位置；SPA 前进时停在上个页面的滚动位置。
- **决策点**：
  ① **恢复策略**——后退=恢复原位置；前进到新页=归零到顶；同页参数变化=保持还是归零；
  ② **接管对象**——`history.scrollRestoration = 'manual'` 后自行存取 scrollY（sessionStorage 按路由 key）；
  ③ **异步内容**——恢复时内容还没加载完，高度不足怎么办（先恢复到能到的位置，内容到位后再修正）；
  ④ **锚点优先**——URL 带 #hash 时锚点优先于历史位置。
- **实现**：路由守卫记录 scrollY per path；`afterEach` 恢复；配合骨架屏保证高度预估。
- **验收**：列表→详情→返回位置精确恢复；前进永远到顶；慢网恢复不跳。
- **衔接**：B53（锚点导航）、K·滚动锚定、K·锚点滚动偏移

## K·滚动锚定（Scroll Anchoring）

- **领域**：工程 · **成本**：低
- **定义**：视口上方的内容插入/加载/高度变化时，浏览器自动调整 scrollTop 保持用户当前视野——防"页面在我眼前跳"。
- **症状**：顶部图片加载出来把正文顶下去（CLS 体感版）；广告注入时正在读的文字跑了；字体加载完成重排版导致视野位移。
- **决策点**：
  ① **根源治理**——给图片/媒体固定 `aspect-ratio` 和尺寸（B65 坑7：aspect-ratio 防 CLS）比依赖锚定更治本；
  ② **锚定禁区**——某些场景要禁用锚定：`overflow-anchor: none`（如动画展开区域，锚定会导致抖动）；
  ③ **SPA 场景**——路由切换时临时禁用锚定，恢复滚动位置后再启用；
  ④ **与滚动恢复的分工**——锚定管"内容变视野不跑"，恢复管"导航来回位置对"（辨析见 K9）。
- **实现**：图片 `aspect-ratio`、字体 `font-display: swap` + 度量匹配的 fallback、骨架屏按真实高度占位。
- **验收**：弱网加载中滚动读文不跳；CLS <0.1（F3 指标）；展开动画区域无锚定抖动。
- **衔接**：F3（CLS）、B65 坑7（aspect-ratio）、B73（骨架屏）、K·滚动恢复

## K·滚动穿透（Scroll Chaining / Overscroll）

- **领域**：交互/工程 · **成本**：低
- **定义**：内层滚动区到达边界后，滚动继续传递给外层——弹层里滚到底整个页面跟着滚就是穿透失控。
- **症状**：Modal/Drawer 里滚到底页面在动；移动端下拉刷新被浮层内滚动触发；嵌套列表滚动接力不符合预期。
- **决策点**：
  ① **穿透策略**——浮层/侧边栏默认 `overscroll-behavior: contain`（滚动不传出）；正文默认 auto；
  ② **边界反馈**——到边界是给橡皮筋（iOS 拉伸回弹，B45）还是硬停+箭头提示；
  ③ **轮滚接管**——桌面 wheel 事件到边界是否吞掉（JS `e.preventDefault()` 配合 contain 语义）；
  ④ **嵌套方向**——横向滚区与纵向页面滚动的方向锁（水平位移占优时锁垂直）。
- **实现**：
  ```css
  .modal-body, .drawer, .chat-stream { overscroll-behavior: contain; }
  ```
  JS 场景：touchmove 到边界时 preventDefault（注意 passive listener 需显式 `{ passive: false }`）。
- **验收**：浮层内滚到头页面静止；浮层外滚动不受影响；iOS 橡皮筋只在页面级出现。
- **衔接**：G3（移动端滚动/橡皮筋）、R9（overscroll-behavior）、B45（滚动手感）、B53§165（contain 实例）

## K·滚动锁定（Scroll Lock）

- **领域**：交互/工程 · **成本**：低
- **定义**：临时禁止某区域或全页滚动——modal 打开时锁 body、抽屉打开锁背景。
- **症状**：modal 打开背景还能滚（焦点分离）；锁滚后内容右移（滚动条消失 layout shift）；解锁后滚动位置丢失；iOS 锁不住（body overflow:hidden 在 Safari 无效）。
- **决策点**：
  ① **锁定范围**——锁 body 还是只锁背景层（modal 内可滚、body 锁）；
  ② **滚动条补偿**——锁 body 时 `padding-right: 15px`（或实测滚动条宽）补位，防内容跳动；
  ③ **iOS 兼容**——`overflow:hidden` 不够，要 `position:fixed` + 记录 scrollY 复位（react-remove-scroll 类方案）；
  ④ **解锁条件**——ESC/点遮罩/操作完成三路都要解；组件卸载兜底解锁。
- **实现**：现代库用 `overflow:hidden` + 滚动条补偿；iOS 用 `position:fixed; top:-scrollY` 方案或现成 hook。
- **验收**：锁定期背景纹丝不动；无横向位移；解锁回位精确；多弹层叠加解锁按栈回退。
- **衔接**：D1（Scroll Lock 组件名）、B76（modal 焦点管理）、B53、K·滚动穿透

## K·锚点滚动偏移（Anchor Scroll Offset）

- **领域**：工程 · **成本**：低
- **定义**：锚点跳转时目标被固定头部遮挡的问题——`scroll-padding-top` 是给滚动容器留的"缓冲区"。
- **症状**：点目录跳到小节，标题被 fixed header 盖住（B53 坑3）；scroll-behavior:smooth 滚动过头；键盘 Tab 焦点跳到被遮挡位置。
- **决策点**：
  ① **偏移量**——= fixed header 高度 + 8-16px 喘息空间；
  ② **应用对象**——`scroll-padding-top` 作用于滚动容器（html），`scroll-margin-top` 作用于目标元素（更精细，单目标可用）；
  ③ **平滑与否**——`scroll-behavior: smooth`（锚点）vs instant（程序化跳转）；长距离滚动平滑会让用户等待，超长页可 instant + 目标闪烁提示；
  ④ **焦点联动**——锚跳后焦点应移到目标（键盘流），`:target` 高亮提示到达点。
- **实现**：
  ```css
  html { scroll-behavior: smooth; scroll-padding-top: calc(var(--header-h) + 16px); }
  /* 或精细控制 */
  .section { scroll-margin-top: calc(var(--header-h) + 16px); }
  ```
- **验收**：锚点跳转后标题完整露出；焦点跳转可见；无 header 时偏移为 0 不过度留白。
- **衔接**：B53（坑3 + scroll-padding-top）、G8（文档站锚点）、B45（scroll-behavior）

## K·snap 与 scrub 取舍（Scroll Snap vs Scroll-linked Scrub）

- **领域**：交互/动效 · **成本**：中
- **定义**：两种"滚动接管"路线的根本取舍——snap 让滚动停在离散档位（分页感），scrub 让动画进度 1:1 跟随滚动位置（时间轴感）。
- **症状**：该分页的展示做了 scrub（用户停在中间看到半截动画）；该连续叙事的地方用了 snap（每屏"咔"地一下很机械）；snap + scrub 混用互相打架。
- **决策点**：
  ① **内容形态**——离散内容（轮播/分页/档位面板）用 snap；连续叙事（scrollytelling/形变进度）用 scrub；
  ② **控制权**——snap 把节奏交给浏览器（松手后自吸），scrub 把每帧映射交给你（精度高成本高）；
  ③ **性能档**——CSS scroll-snap 免费高性能；JS scrub（GSAP ScrollTrigger/Lenis）要预算（V10：移动端 scrub 考虑改原生 overflow-x + snap 替代，R20 配方）；
  ④ **冲突裁决**——同一滚动容器不要同时 snap 和 scrub；嵌套时内外分工明确（外层 scrub、内层 snap）。
- **实现**：snap：`scroll-snap-type: x mandatory` + `scroll-snap-align`；scrub：GSAP `scrub: 1`（数值=跟随延迟秒数）或 CSS `animation-timeline: scroll()`。
- **验收**：snap 必落档无半档；scrub 双向跟手无延迟漂移；触屏 scrub 有降级方案。
- **衔接**：V10（scrub/pin/scrollytelling）、R9/V14（scroll-driven CSS）、R20（移动端 snap 替代 scrub）、B45（scroll-snap 手感）、K·吸附（K1）

## K·分页模式选型（Pagination Strategy）

- **领域**：滚动/信息架构 · **成本**：中
- **定义**：长列表内容的分段模式决策——分页（离散页码）、无限滚动（自动追加）、加载更多（手动追加）及混合形态的选择与配套。
- **症状**：无限滚动让页脚永远够不到；返回上一页滚了半天的位置从头来过；想分享"第 3 页那个商品"发现 URL 里没有位置；滚了 800 条页面开始卡。
- **适用**：任何超过一屏的列表（商品/订单/feed/搜索结果）｜ **不适用**：短列表（<2 屏别做分段，全展示）。
- **决策点**：
  ① **模式选型**——目标导向（电商/搜索结果，用户要比价回跳）用分页；消费导向（feed/图片流，无回跳目标）用无限滚动；介于之间用"加载更多"+计数（"还有 234 条"）；SEO/审计场景必须分页
  ② **位置保持**——返回恢复滚动位与已加载页数（衔接 K·滚动恢复）；分页天然免疫，无限滚动必须 sessionStorage 缓存或路由 state
  ③ **URL 状态**——分页写 `?page=` 可分享可后退；无限滚动无状态是特性不是缺陷，但要接受"找不到上次那条"
  ④ **终点设计**——无限滚动要有"到底了"语义（页脚提示/结果总数）；加载更多保留页脚可达性
  ⑤ **性能拐点**——DOM 行数 >1000 考虑虚拟化（衔接 K13·虚拟滚动）或分段卸载（滚出视窗的页从 DOM 摘掉）
- **实现**：游标用 cursor 不用 offset（数据变动时 offset 会跳行）；无限滚动 IntersectionObserver 哨兵 + 距底 ~800px 预取（不是触底才加载）；"加载更多"点击后 focus 留在按钮不跳走。
- **验收**：选型与回跳需求一致；返回位置恢复；页脚可达或明确舍弃并给终点语义；千条级不卡。
- **衔接**：K·滚动恢复（本文件）、K13·虚拟滚动共存、C2（模式清单与反模式）、B53（导航）、F3（CLS/性能）
