# K8 · 高级交互模式

> 覆盖度审计发现的系统性空白：这些模式库里零散提及但从没作为决策对象存在。多为中成本、中频使用——值得各立一条。

---

## K·语义缩放（Semantic Zoom）

- **领域**：交互/信息 · **成本**：高
- **定义**：缩放改变的不只是尺寸而是信息密度——缩小看到摘要/热力图，放大看到详情/全文。地图是最经典的例子：zoom out 是城市点，zoom in 是街道门牌。
- **症状**：缩放只是像素放大（字变大内容不变）；缩略层和详情层信息断裂（缩小后找不到刚才的位置）；层级切换靠 jump-cut 无过渡。
- **决策点**：
  ① **层级设计**——几个缩放档？每档显示什么信息集（密度阶梯而非尺寸阶梯）；
  ② **过渡连续性**——跨档时元素 morph 还是 crossfade（对象守恒原则：缩小后摘要位置=原详情位置，B58）；
  ③ **触发方式**——滚轮/捏合/双击/控件按钮各自映射什么缩放语义；
  ④ **性能**——详情层懒加载（进入档位才取数）。
- **实现**：`transform: scale` 连续缩放 + 阈值处切换信息集（IntersectionObserver/range 判定）；数据可视化/图表库（zoom 分层标准模式）。
- **验收**：跨档信息可追踪（我知道我在哪）；缩放过程流畅无白屏；键盘/按钮有等效档位切换。
- **衔接**：B29（数据可视化层级）、B58（变形连续）、C2（缩放交互模式）、V6（3D/空间）

## K·空间导航（Spatial Navigation）

- **领域**：交互/无障碍 · **成本**：中
- **定义**：按几何方向而非 DOM 顺序移动焦点——方向键/手柄的"上下左右"导航（TV 界面、游戏 UI、卡片网格键盘操作）。
- **症状**：方向键焦点按 DOM 顺序跳（视觉上右边才是下一个，却跳到下方）；网格里按右跳到页脚（DOM 顺序≠视觉顺序）；焦点掉到屏幕外。
- **决策点**：
  ① **导航模型**——全空间（按最近邻几何距离）vs 分区（header 区→sidebar 区→content 区逐级下钻）；
  ② **候选算法**——方向投影距离：目标中心在方向轴的投影 + 垂直偏差惩罚项；
  ③ **循环边界**——到边环绕（wrap）还是锁定（stop）；网格行列锁定（行内左右不出行）？
  ④ **焦点可见性**——空间导航更依赖清晰的 focus-visible（TV 上焦点放大 1.1× 惯例）。
- **实现**：简化版——网格内 `Roving Tabindex` + 方向键映射行列移动；完整版——计算方向投影得分选最近候选。
- **验收**：方向键落点=视觉预期 ≥95%；边界行为一致；与 Tab 顺序导航共存不冲突。
- **衔接**：B76（Roving Tabindex/键盘交互模式）、C4（键盘导航）、G3（TV/遥控场景外推）

## K·多阶段动画（Multi-stage Animation）

- **领域**：动效 · **成本**：中
- **定义**：复杂动画拆成多个连续阶段，每阶段有自己的目标、时长和曲线——loading→成功勾号→展开结果，三段形态完全不同的接力。
- **症状**：用一个 animation 硬做三段（中间形态诡异）；阶段间跳变；某阶段失败后续阶段还在播。
- **决策点**：
  ① **阶段划分**——按"语义事件"切（数据到达/校验通过/渲染完成），不按视觉时长切；
  ② **衔接方式**——形态相近阶段用 morph，形态无关阶段用 crossfade（K5·动画接续）；
  ③ **每段曲线独立**——加载旋转 linear 循环、成功勾号 spring、展开 ease-out——一段一曲线；
  ④ **失败分支**——每阶段定义失败去向（错误态段），成功路径和失败路径同建模。
- **实现**：状态机驱动（K7·交互状态机：stage1→stage2→stage3 / →error），promise 链或 animation finished 接续。
- **验收**：各阶段曲线独立合理；阶段间无空档无跳变；失败路径有专属终态。
- **衔接**：K5·动画接续、K7·交互状态机、B73（状态四态）、V13（loading/勾号绘制）

## K·运动引导（Motion Guidance）

- **领域**：动效/注意力 · **成本**：低
- **定义**：用运动把用户注意力引到特定元素——新功能高亮脉冲、表单错误 shake、引导箭头动画、视线追踪式移动提示。
- **症状**：引导动画变成干扰（正在输入时旁边在闪）；动画停了用户还是不知道看什么；多个引导同时抢注意力。
- **决策点**：
  ① **引导强度**——环境提示（idle 呼吸浮动，R11·F8）< 事件响应（操作成功的涟漪）< 强制注意（错误 shake/必填闪）；
  ② **时机**——引导动画在"需要时"触发而非常驻（首次功能、出错、状态变更）；
  ③ **退出**——目的达成即停（用户点击了被引导的元素就撤），不无限循环；
  ④ **排他**——同时只一个强引导（注意力冲突=B56 单一焦点原则）。
- **实现**：`pulse`/`shake`/`spotlight 遮罩` 配方见 B74/V13；引导定位用 anchor positioning（V14）跟随目标。
- **验收**：引导动画 ≤3 次或达成即撤；无多引导竞争；reduced-motion 下用静态高亮替代。
- **衔接**：B56（注意力引导专文）、B74（shake/pulse 配方）、R11·F8（空闲呼吸）、R17（coach marks/hints）、V14（anchor positioning）

## K·预测性加载（Predictive Loading / Anticipatory Preload）

- **领域**：工程/性能 · **成本**：中
- **定义**：根据用户行为预测下一步需要的资源并提前加载——hover 预取、视口预渲染、意图预测加载。
- **症状**：点了才加载有明显等待；盲目预加载浪费带宽拖慢当前页；预测错误加载了永远不用的东西。
- **决策点**：
  ① **预测信号强度**——hover（弱，预取关键资源）/ pointerdown（中，开始加载）/ 浏览模式分析（强，预渲染下一页）；
  ② **预载层级**——`prefetch`（闲时取，低优先级）< `preload`（本页马上要用）< `prerender`（整页预渲染）——强度递增成本递增；
  ③ **触发时机**——hover 持续 ≥150ms 才预取（配合 K3·悬停意图过滤误触）；
  ④ **失败回退**——预测失败不影响实际导航（预取只是优化不是依赖）。
- **实现**：`<link rel="prefetch">`/`Speculation Rules API`（`prerender`/`prefetch` 规则声明式预测）；hover 时 fetch 关键 chunk。
- **验收**：实际导航感知接近 0ms；预取不挤占当前页带宽；数据统计预测命中率。
- **衔接**：F3（资源预加载策略）、R20（hover prefetch）、B9（感知性能）、T2（性能度量）

## K·交互式遮罩（Interactive Masking）

- **领域**：视觉/交互 · **成本**：中
- **定义**：遮罩范围随用户操作变化——跟随指针的聚光灯、滚动驱动的揭示、划动对比（before/after 对比滑块）。
- **症状**：遮罩边界生硬（硬切非羽化）；对比滑块拖动手感差；移动端遮罩跟随手指位置错乱。
- **决策点**：
  ① **遮罩形态**——radial-gradient 聚光 / clip-path 形状揭示 / mask-image 羽化边缘；
  ② **驱动源**——指针位置（聚光灯）、滚动进度（揭示）、拖拽手柄（对比滑块）各自的手感参数（K4·跟手）；
  ③ **性能通道**——只改 mask-position/clip-path 变量（GPU），不重算图片；
  ④ **无 JS 降级**——静态遮罩/全显示兜底。
- **实现**：`mask-image: radial-gradient(circle at var(--mx) var(--my), black 0 120px, transparent 200px)`；对比滑块 `clip-path: inset(0 0 0 var(--x))`。
- **验收**：跟随 60fps；边界羽化自然；触屏/键盘等效可用。
- **衔接**：V5（遮罩/clip-path/揭示动画）、V9（聚光灯光标）、R9（mask 性能）、K4·跟手
