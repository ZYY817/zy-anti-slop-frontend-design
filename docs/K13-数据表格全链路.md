## K·行选择模型（Row Selection Model）

- **领域**：表格/交互 · **成本**：中
- **定义**：用户如何选中行以及选择状态在数据变化后如何存续。
- **症状**：勾了 3 行翻到第 2 页勾全没了（选了"当前页"不是"实体"）；排序后选中行错位；点行任意位置都选中导致想复制文字都不行；全选 checkbox 不知道选的是当前页还是全部 5000 条。
- **适用**：数据表格、列表批量操作场景 ｜ **不适用**：只读报表（不需要选择模型）、卡片流。
- **决策点**：
  ① **选择锚**——按行 id 存选择集（跨页/排序存活），不按行索引存（数据一变就错位）
  ② **范围选择**——Shift+点击范围选？仅桌面端，移动端不提供
  ③ **全选语义**——表头 checkbox 选当前页还是全部匹配？跨页全选要给"已选 N 条 · 选择全部 M 条"显式条
  ④ **点击域划分**——整行点击选中 vs 只有 checkbox 选中？（有批量操作场景推荐 checkbox+行点击选中互斥：文字/链接区域不触发选中）
- **实现**：
  - `selectedIds: Set<id>` 而非 `selectedRows`；渲染时查 id 命中
  - 全选 bar：选了当前页且总数更多时，显示"全选 5000 条"升级链接（Gmail 模式）
  - 三态表头 checkbox：unchecked / indeterminate（部分选）/ checked
- **验收**：翻页/排序/筛选后选中集按 id 存活；批量操作条显示准确数量；全选语义明确（页 vs 全部）；文字可选中复制不误触行选中。
- **衔接**：D4:363-392（行态矩阵）、G2（批量操作条）、K8·空间导航（方向键移动）、K13·虚拟滚动

## K·单元格编辑（Cell Editing）

- **领域**：表格/编辑 · **成本**：中
- **定义**：表格内单元格就地编辑的进入/提交/取消语义与布局稳定性。
- **症状**：单击单元格想选中文字却进入编辑；blur 一下未完成的输入直接保存成脏数据；编辑态单元格高度突变顶开下面行；Esc 想关弹层结果取消了编辑。
- **适用**：数据密度高的可编辑表格（排期表/价格表/库存）｜ **不适用**：低频编辑（用 Drawer/Modal 编辑整行）、复杂关联字段。
- **决策点**：
  ① **进入方式**——单击/双击/编辑钮？（单元格常需选中复制，推荐双击或显式编辑钮；列可配置 editable）
  ② **提交语义**——Enter/blur 提交、Esc 取消恢复旧值；blur 提交要排除点击弹层组件内部（日期选择器点击不应触发提交）
  ③ **脏标记**——编辑未提交的单元格给角标/底色；提交失败恢复编辑态+内联错误
  ④ **布局稳定**——编辑态高度 = 只读态行高（input 高 ≤ row height），不允许撑行
- **实现**：
  - 编辑态渲染 input/select，尺寸与行高对齐（padding 复用单元格值）
  - 提交管线走 K12·异步请求链（乐观更新 + 失败回滚）
  - Tab 提交并移到下一可编辑单元格（Excel 语义）；Shift+Tab 反向
- **验收**：进入方式不产生误触；Esc 恢复旧值；提交失败不丢输入；编辑态不撑行；Tab 可在可编辑单元格间流转。
- **衔接**：K11·内联编辑（通用语义源头）、K12·异步请求链、D4（editing/dirty 态）、G2

## K·列操作与排序（Column Ops & Sorting）

- **领域**：表格/交互 · **成本**：中
- **定义**：列宽调整、列显示/顺序、排序循环的完整行为决策。
- **症状**：表头点了第一次排序、再点没反应（只有单向循环）；拖列宽瞬间表格重排抖动；列设置刷新后丢；多列排序状态用户看不懂。
- **适用**：数据表格 ｜ **不适用**：简单 3-4 列只读表（禁用列操作）。
- **决策点**：
  ① **排序循环**——无→升→降→无（三态循环）还是无→升→降锁定？（推荐三态含回无；默认排序列在规格里写明）
  ② **排序指示**——箭头常驻还是 hover 显现？（当前列常显+方向，其他列 hover 提示可排）
  ③ **多列排序**——Shift+点击加次级排序？显示 1/2/3 优先级角标？（专家功能，默认关闭）
  ④ **列宽**——拖拽 min/max 约束 + 双击自适应；列配置（宽/显隐/顺序）持久化到哪（localStorage per-table-id）
- **实现**：
  - sort 状态机：`{key, dir: asc|desc|null}`；后端排序时把参数放 URL（可分享视图）
  - 列宽 drag：pointermove 实时改 width，min 48px / max 不超出容器；拖动中 `user-select:none` 防选字
  - 持久化：`tableState[id] = {widths, hidden, order, sort}`；提供"重置布局"
- **验收**：三态循环可回无排序；当前排序有明确指示；列宽拖拽不跳不选字；列配置刷新后保留；多列排序有优先级可见性。
- **衔接**：F4:259-277（tanstack 实现）、G2、D4、K13·视觉规格（指示位置）、K6（横向滚动的 sticky 列）

## K·表格视觉规格（Table Visual Grammar）

- **领域**：表格/视觉 · **成本**：低
- **定义**：行分隔语言、列对齐协议、sticky 冻结、选中态防跳的视觉规格——表格"长什么样"的五项必答。
- **症状**：斑马纹+hover+分隔线三件套全上（互相打架）；数字列没右对齐没 tabular-nums 扫读困难；操作列宽度每页漂移；选中行边框让整行跳 1px；横向滚动时表头/操作列滚出视野。
- **适用**：一切数据表格 ｜ **不适用**：卡片式列表。
- **决策点**：
  ① **行分隔语言**——留白分组 / 1px 细线 / 斑马纹 三选一，**不叠加**（G2 坑）；有 hover 高亮时更不需要斑马
  ② **列对齐协议**——文本左、数字右（+tabular-nums）、状态居中、操作列右；表头与数据同对齐
  ③ **sticky 决策**——横向滚动时冻结首列（标识列）和/或操作列；纵向滚动 sticky 表头；多层 sticky 的 z-index 次序
  ④ **选中态防跳**——选中行用 `outline` 或 `box-shadow` 不用 `border`；若必须 border 则 `padding - 1px` 补偿（B65:483-489 技巧）；选中态与 hover 态要可区分
  ⑤ **溢出策略**——截断 vs 换行 vs 缩字号；不可截断白名单（人名/价格/ID/关键操作），截断处给全文路径（tooltip/展开/详情）
- **实现**：
  - 数字列 `font-variant-numeric: tabular-nums` + `text-align: right`（B60）
  - `tr.selected { outline: 2px solid accent; outline-offset: -2px; }` 零布局成本
  - sticky：`th { position: sticky; top: 0 }`、首列 `td:first-child { position: sticky; left: 0; background: inherit }`（背景不透明防穿透）
  - 密度档位衔接 B62（compact/comfortable/spacious 行高与字号档）
- **验收**：分隔手段只用一种；数字右对齐 tabular-nums；选中不跳行；横向滚动首列/操作列存活；截断字段有全文可达路径。
- **衔接**：G2:76-114、B46:139-160（单元格呼吸）、B60:135-238（数字对齐）、B62:380-425（密度档）、B63:252-279（无边框矩阵）、B65:483-489（防跳技巧）、B52（表格空态）、B29（表格里的图表）

## K·虚拟滚动与选择共存（Virtualized Table Semantics）

- **领域**：表格/工程 · **成本**：高
- **定义**：大列表虚拟滚动后，选择集、编辑态、键盘导航、屏幕阅读器如何不丢不乱。
- **症状**：滚出视口再滚回来勾选框丢了（DOM 回收把状态带走了）；表格 5000 行卡死才上虚拟滚动，上了之后 Ctrl+A 全选选不全；屏幕阅读器报行数只有可视那几十行。
- **适用**：>500 行的数据表/长列表 ｜ **不适用**：<200 行（原生渲染更稳，虚拟化得不偿失）。
- **决策点**：
  ① **状态外置**——选择集/编辑值必须存 id-map 而非 DOM（行被回收重渲染后状态还原）
  ② **overscan 档位**——视口外多渲染几行？（5-10 行；太多失去虚拟化意义，太少滚动白闪）
  ③ **动态行高**——行高固定才能精算；动态行高需测量缓存+预估（tanstack virtual 的 estimateSize）
  ④ **a11y 代价**——`aria-rowcount` 报总数、虚拟行 `aria-rowindex` 报真实序号；滚动中读屏焦点处理
- **实现**：
  - tanstack-virtual / react-window：固定行高优先；动态行高给测量回调
  - 键盘导航：方向键移动焦点行时必须滚动到该索引（scrollToIndex），焦点落在虚拟行外要处理
  - 编辑态单元格滚出视口前要么提交要么挂起——回收即丢失
- **验收**：千行不卡；勾选/编辑状态滚动后存活；Ctrl+A/全选语义作用于全量非可视行；读屏报总数与真实行号。
- **衔接**：K13·行选择模型（id 锚）、K8·空间导航、F4（虚拟化库）、F3（性能）、B76（aria-rowcount）

## K·数值呈现（Numeric Display & Delta）

- **领域**：数据呈现/仪表 · **成本**：低
- **定义**：数字如何被呈现与更新——count-up 动效、涨跌方向编码、实时刷新节流的决策，不是字体排版问题。
- **症状**：仪表盘所有数字进页面齐刷刷 count-up 一遍（典型 AI 指纹）；实时行情数字每 100ms 闪一次看不清；涨了但没有任何方向提示要心算对比。
- **适用**：仪表 KPI 卡、行情/计数器、实时数据面 ｜ **不适用**：表格单元格数字（频率太高全动会糊，走 K13·表格视觉规格）。
- **决策点**：
  ① **何时动**——count-up 只为"首次加载建立值感"或"显著 delta"动；常规渲染直接出值；全屏数字齐动 = 全部不动
  ② **方向编码**——delta 必须有方向：↑↓ 箭头 + 语义色 +（可选）徽标底色；色盲冗余靠箭头不靠纯红绿（衔接 C4/B76）
  ③ **更新节流**——实时流 ≥2 次/s 时 throttle 到 500ms-1s；或改推模式（"12 条新数据，点击刷新"）
  ④ **位数稳定**——动画/刷新中数字宽度不变（`tabular-nums` + 定宽），跳位 = 视觉噪音；小数位数与精度口径一致
- **实现**：`font-variant-numeric: tabular-nums`；count-up 用 rAF + ease-out 800-1200ms（B45 参数）且 `prefers-reduced-motion` 下直接出终值；实时数据 rAF 批更新。
- **验收**：无"为了动而动"的全屏 count-up；delta 遮色可辨方向；实时更新不闪不丢帧；数字宽度不随值跳动。
- **衔接**：B45（count-up 时长/缓动参数）、B74（delta 配方）、B60（数字对齐/tabular-nums）、K18·视觉配额（全屏齐动违反峰值数）、B29（数据可视化）
