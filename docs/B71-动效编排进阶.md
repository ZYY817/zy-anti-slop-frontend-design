## 一、Spring 物理动效（弹簧模型）

`cubic-bezier` 是"画一条曲线"，Spring 是"设一组物理参数"。区别：Spring 能被打断后自然接续，更适合手势与拖拽。

### 三个参数的直觉

| 参数 | 含义 | 调大的效果 | 常用范围 |
|---|---|---|---|
| **stiffness / tension** 刚度 | 弹簧多硬 | 更快、更急 | 100 – 400 |
| **damping / friction** 阻尼 | 阻力多大 | 更少回弹、更快停 | 10 – 40 |
| **mass** 质量 | 物体多重 | 更慢、更沉 | 0.5 – 2 |

### 手感配方

| 手感 | stiffness | damping | mass | 用途 |
|---|---|---|---|---|
| 干脆无回弹 | 300 | 30 | 1 | 按钮、开关、Tab |
| 轻微回弹 | 260 | 20 | 1 | 卡片展开、抽屉 |
| 明显弹跳 | 400 | 12 | 1 | 点赞、庆祝、图标反馈 |
| 沉稳厚重 | 120 | 26 | 1.6 | 大面板、全屏弹层 |
| 果冻感 | 180 | 8 | 1 | 玩味交互、品牌动画 |

### 判断准则
- **damping / (2·√(stiffness·mass)) < 1** → 会回弹（欠阻尼）
- **= 1** → 刚好不回弹（临界阻尼，最"干脆"）
- **> 1** → 缓慢趋近，无回弹（过阻尼，显得迟钝）

### CSS 近似
CSS 无原生 spring，但可用多点 `linear()` 逼近：
```css
/* 轻微回弹的 spring 近似 */
transition-timing-function: linear(
  0, 0.28 8%, 0.65 17%, 0.92 25%, 1.05 33%,
  1.03 45%, 0.99 60%, 1
);
```
或用回弹贝塞尔（仅单向超调）：
```css
transition-timing-function: cubic-bezier(0.34, 1.56, 0.64, 1);
```
真正的 spring 需要 JS：Motion / React Spring / GSAP。

- **prompt 措辞**："卡片展开用 spring（stiffness 260 / damping 20 / mass 1），轻微回弹不过头；按钮反馈用临界阻尼无回弹"

## 二、Stagger 的数学（级联延迟）

B58 讲了等差 stagger。这里补全**四种延迟函数**——它们的节奏感完全不同。

### 1. 等差（Linear）— 最常用
```
delay(i) = i × step
```
```css
.item { animation-delay: calc(var(--i) * 60ms); }
```
- **节奏**：均匀、稳定、可预期
- **注意**：项数多时总时长爆炸（20 项 × 60ms = 1.2s，太久）

### 2. 递减步长（Ease-out Stagger）— 项数多时用
后面的项间隔越来越小，总时长可控。
```
delay(i) = total × (1 - (1 - i/(n-1))^2)    /* i 从 0 开始 */
```
```css
/* n=12, total=600ms 的手写值 */
.item:nth-child(1) { animation-delay: 0ms; }
.item:nth-child(2) { animation-delay: 96ms; }
.item:nth-child(3) { animation-delay: 183ms; }
/* … 间隔逐渐缩小，第 12 项落在 600ms */
```
- **节奏**：起步清晰、收尾迅速、不拖沓
- **场景**：长列表（>10 项）、搜索结果

### 3. 波浪（Wave / Sine）
```
delay(i) = amplitude × sin(i × frequency) + i × step
```
- **节奏**：起伏、有机、活泼
- **场景**：装饰性网格、品牌动画、加载点阵

### 4. 从中心扩散（Center-out）
```
delay(i) = |i - center| × step
```
```css
/* 5 项从中间往两边 */
.item:nth-child(3) { animation-delay: 0ms; }
.item:nth-child(2), .item:nth-child(4) { animation-delay: 70ms; }
.item:nth-child(1), .item:nth-child(5) { animation-delay: 140ms; }
```
- **节奏**：绽放、聚焦中心
- **场景**：底部 Tab 栏、工具条、对称布局

### 二维网格的 Stagger
按对角线延迟，比逐行更自然：
```css
.cell {
  /* --r 行号, --c 列号 */
  animation-delay: calc((var(--r) + var(--c)) * 50ms);
}
```
- **感觉**：光从左上扫过
- 若改为 `abs(--r - --c)` → 从对角线向两侧展开

### 步长选型

| 元素类型 | 建议 step | 说明 |
|---|---|---|
| 小元素（标签、图标） | 30 – 50ms | 快速掠过 |
| 列表项、卡片 | 50 – 80ms | 最常用区间 |
| 大区块（section） | 100 – 180ms | 有仪式感 |

**铁律**：`step × 项数 ≤ 800ms`。超了就换递减步长，或只对首屏可见项做 stagger。

## 三、退场动画（Exit Animation）

多数 AI 只写入场，忘记退场——这是"半成品感"的主要来源。

### 退场的三条铁律

1. **退场比入场快**：`出场时长 ≈ 入场 × 0.5~0.7`（用户已经决定离开，不需要欣赏）
2. **缓动反向**：入场用 `ease-out`（快→慢），退场用 `ease-in`（慢→快，加速离开）
3. **退场方向 = 来路**：从下方进来的，就往下方出去（空间可预测）

```css
.panel {                     /* 入场 */
  transition: transform 300ms cubic-bezier(0.16, 1, 0.3, 1), opacity 300ms;
}
.panel.is-leaving {          /* 退场 */
  transition: transform 180ms cubic-bezier(0.4, 0, 1, 1), opacity 150ms;
  transform: translateY(12px);
  opacity: 0;
}
```

### 退场类型学

| 场景 | 退场手法 | 时长 |
|---|---|---|
| Modal 关闭 | scale 1→0.97 + opacity→0 | 150–180ms |
| Toast 消失 | 向上滑出 + 淡出 | 200ms |
| 列表项删除 | 高度收起 + 淡出 + 后续项上移 | 220ms |
| 抽屉收回 | 沿来路滑出 | 200ms |
| 页面离开 | 整体淡出（不做位移，避免晕） | 150ms |
| Tab 切换 | 旧内容淡出 120ms → 新内容淡入 180ms（错开） | 300ms |

### 列表项删除的完整处理
删除时若直接 `display: none`，后续项会瞬移。正确做法：
```css
.item.removing {
  animation: collapse 220ms ease-in forwards;
}
@keyframes collapse {
  to { opacity: 0; transform: translateX(-8px); max-height: 0; margin-block: 0; padding-block: 0; }
}
```
或用 View Transitions 让后续项自动补间（见 B58）。

### 批量退场的 Stagger
退场的 stagger **顺序应与入场相反**（后进先出），或干脆更快、无 stagger：
```css
.item.leaving { animation-delay: calc((var(--n) - var(--i)) * 25ms); }
```

- **prompt 措辞**："每个动效都要写退场：时长为入场的 0.6 倍，缓动改 ease-in，退场方向沿来路返回；列表删除要收起高度让后续项平滑上移"

## 四、连续编排（交互过程中的动效序列）

入场只发生一次，但交互中的编排每次都在发生。

### 因果链编排
一个操作触发多个视觉变化时，按**因果顺序**依次发生，不要同时：
```
点击"保存"
  0ms    按钮按下（scale 0.97）
  60ms   按钮进入 loading（文字→spinner）
  ...    请求中
  0ms    spinner→勾号（形变，不是替换）
  200ms  勾号绘制完成
  350ms  Toast 从顶部滑入
  2500ms Toast 滑出
```

### 三种编排关系

| 关系 | 时序 | 用途 |
|---|---|---|
| **同时（Parallel）** | 同一时刻 | 属性同源变化（opacity + transform） |
| **交错（Stagger）** | 固定间隔 | 同类多元素 |
| **接续（Sequence）** | 前一个结束才开始 | 有因果关系的不同元素 |
| **重叠（Overlap）** | 前一个进行到 60% 时开始 | 最自然，避免"卡顿感" |

**重叠是最容易被忽略的**——纯接续会显得机械，让下一个动作在前一个的 60-70% 处切入，整体更流畅（对应迪士尼的"跟随与重叠"，见 B27）。

## 五、prefers-reduced-motion 完整降级策略

不是"全部关掉"，而是**分级降级**。

### 三档降级

| 动效类型 | reduced-motion 下的处理 |
|---|---|
| 大幅位移、视差、缩放、旋转、3D | **完全移除**，直接到终态 |
| 淡入淡出、颜色过渡 | **保留**（不引发前庭反应） |
| 自动播放的循环动画（旋转、脉冲、轮播） | **停止**或改为静态 |
| 功能性反馈（loading、进度） | **保留但简化**（spinner 可保留，或改为静态文字） |
| Stagger | **移除延迟**，全部同时出现 |

### 全局开关模式（推荐）
用 CSS 变量做统一控制，比逐条覆盖更好维护：
```css
:root {
  --motion-duration: 300ms;
  --motion-distance: 24px;
  --motion-scale: 0.96;
}
@media (prefers-reduced-motion: reduce) {
  :root {
    --motion-duration: 0.01ms;   /* 不用 0，避免某些浏览器不触发 transitionend */
    --motion-distance: 0px;
    --motion-scale: 1;
  }
}
.card {
  transition: transform var(--motion-duration), opacity var(--motion-duration);
  transform: translateY(var(--motion-distance));
}
```

### 兜底清扫（防漏）
```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```
- **注意**：这是兜底，会把淡入也一起干掉。更好的做法是先用变量方案精细控制，兜底只作为保险。

### 提供用户开关
系统设置之外，界面里也给一个"减少动效"选项（写入 `data-motion="reduce"` 到 `<html>`），因为很多用户不知道系统设置在哪。

## 六、编排配方（12 个可直接用的）

1. **Hero 开幕**：背景淡入 → 标题逐词浮现（step 40ms） → 副标 → CTA 弹入（spring 回弹） → 装饰光效
2. **列表加载完成**：骨架屏 crossfade → 项目递减步长 stagger（总 600ms）
3. **卡片 hover**：阴影升高 + 微上移 4px + 图片 scale 1.04（三者同时，200ms ease-out）
4. **点赞**：图标 scale 0.8 → 1.3 → 1（spring 明显弹跳）+ 粒子迸发
5. **表单提交**：按钮压下 → 宽度收缩成圆 → spinner → 形变为勾号 → Toast 接续
6. **Tab 切换**：旧内容淡出 120ms → 指示条滑动 250ms（与内容重叠）→ 新内容淡入 + 轻微上移
7. **抽屉打开**：遮罩淡入 200ms（先） → 面板滑入 280ms（重叠在遮罩 50% 处）
8. **删除确认**：项目变红闪一次 → 收起高度 → 后续项上移 → Toast 带"撤销"
9. **数字变化**：滚动计数 + 变化瞬间轻微 scale up（1.06）再回落
10. **搜索输入**：输入停止 300ms 后 → 旧结果淡出 → 新结果中心扩散 stagger
11. **拖拽排序**：拾起时 scale 1.03 + 阴影加深 → 其他项用 FLIP 让位 → 放下时 spring 落位
12. **成功庆祝**（稀有触发）：勾号绘制 → 环形扩散 → confetti（仅首次/里程碑，见 B47）

## 七、Prompt 模板

```
【动效编排】
- 手感：交互反馈用 spring（stiffness 260 / damping 20 / mass 1），
        按钮用临界阻尼无回弹，庆祝类可明显弹跳
- Stagger：列表项 step 60ms；超过 10 项改递减步长，总时长 ≤800ms；
          底部 Tab 用中心扩散；网格用对角线延迟
- 退场：每个动效必须有退场——时长为入场 0.6 倍，缓动改 ease-in，
        沿来路返回；列表删除要收起高度让后续项平滑上移
- 编排关系：有因果的用接续，但让后一个在前一个 60% 处切入（重叠）
- 无障碍：用 CSS 变量做 motion 全局开关，
          prefers-reduced-motion 下移除位移/视差/循环动画，保留淡入
- 界面内额外提供"减少动效"开关
```

## 八、检验清单

- [ ] 交互反馈用了 spring 或回弹曲线，不是全站一个 ease
- [ ] Stagger 总时长 ≤ 800ms，长列表用了递减步长
- [ ] **每个入场动效都有对应退场**（这条最常漏）
- [ ] 退场时长 ≈ 入场 × 0.6，缓动是 ease-in
- [ ] 退场方向沿来路返回（不是随机方向）
- [ ] 列表删除后，后续项是平滑上移不是瞬移
- [ ] 有因果关系的动效是接续/重叠，不是同时开始
- [ ] reduced-motion 做了分级降级（不是简单全关）
- [ ] motion 参数用 CSS 变量统一管理
- [ ] 自动循环动画在 reduced-motion 下停止
