# K5 · 动画中断与接续

> 真实用户不会等动画播完——他们反复点击、中途反悔、连续触发。动画系统的成熟度不在"播放得多好"，而在"被打断时收得多优雅"。
> 碎片原在 R12（velocity handoff）、R11·F3、B58、B71，本文件聚合为决策对象。

---

## K·动画中断（Animation Interruption）

- **领域**：动效/交互 · **成本**：中
- **定义**：动画尚未播完就被新操作打断时的接管策略——从头重播（生硬）、从当前位置反向（自然）、从当前状态重新插值（最自然）。
- **症状（怎么知道这里有问题）**：
  - 快速反复开关抽屉，动画每次都"跳"回起点重新播放；
  - 打断瞬间元素瞬移到起点/终点（位置不连续）；
  - 连续触发导致动画排队（用户等三遍完整动画）；
  - 打断后状态分裂（视觉开了一半，数据已经是关闭）。
- **决策点**：
  ① **接管起点**——从打断瞬间的当前位置/当前速度继续（不要回到 0%）；
  ② **方向处理**——反向打断是镜像倒放还是重新插值到新目标；
  ③ **时长重算**——剩余距离对应剩余时长（打开到 70% 被关，回退只播 30% 的等效时长，不是整段）；
  ④ **打断防抖**——N ms 内的连续触发合并为最后一次意图（还是每次都响应？交互组件要"每次都响应"，广播型通知可合并）。
- **实现**：CSS transition 天然从中断点接管（属性当前值→新目标）；JS/WAAPI `animation.currentTime` 读写；弹簧动画天然可中断（spring 只有目标态没有"播放进度"）——**可中断性是现代动画库推荐 spring 而非 duration 的核心原因**。
- **验收**：任意时刻打断位置连续；反向打断时长=已播放进度等比例；快速连击不产生动画队列堆积。
- **衔接**：B58（状态间变形/连续性）、B71（连续编排）、K·速度接管、K·中断状态一致性

## K·速度接管（Velocity Handoff）

- **领域**：动效/物理 · **成本**：中
- **定义**：动画/手势切换时，把当前的瞬时速度作为初速度交给下一段运动——拖拽跟手→惯性滑行→吸附落位三段交接不"咯噔"。
- **症状**：松手瞬间元素先停再走（速度归零重启）；spring 从静止开始弹而非延续甩出速度；两段动画衔接处有可见的"折"。
- **决策点**：
  ① **速度采样**——取最后 2-3 帧的平均速度（防最后一帧噪声）；
  ② **接管映射**——手势 px/ms → spring `initialVelocity`（不同库单位不同：framer-motion 直接用 px/s，自实现要换算）；
  ③ **方向一致性**——接管时速度方向反转的处理（反向甩出应继续反向滑行再回弹，不是直接正向回弹）；
  ④ **帧率无关**——积分用固定时间步长（R12：fixed timestep），高刷/低帧下物理一致。
- **实现**：`animate(el, { x: target }, { type:'spring', velocity: currentVelocity })`；CSS 无 velocity 参数——需要接管速度就别用 transition，用 spring 或 JS。
- **验收**：慢速录像逐帧看衔接处——速度曲线连续无折点；不同刷新率下体感一致。
- **衔接**：R12（velocity handoff/fixed timestep）、B45§四（惯性拖拽速度采样）、K·惯性拖拽（K4）

## K·动画反转（Reverse / Bidirectional Animation）

- **领域**：动效 · **成本**：低
- **定义**：同一过渡的正向（展开/选中）与反向（收起/取消）——反向不是简单的 `animation-direction: reverse`，要考虑不对称设计。
- **症状**：展开优雅但收起生硬；反向播放时缓动感觉"倒着走路"；反向时元素次序不合理（先进先出 vs 先进后出）。
- **决策点**：
  ① **对称还是不对称**——多数 UI 反转应对称（相同曲线反向）；但"进来的隆重 vs 出去的干脆"可故意不对称（入场 400ms spring，退场 150ms ease-in 收快）；
  ② **退场缓动选型**——退场用 ease-in 或加速曲线（"离开要果断"），别用 spring 大弹跳（B71 退场系统）；
  ③ **stagger 方向**——正向列表项自上而下入场，反向应自下而上收（镜像队列）；
  ④ **时长比**——常用退场时长 = 入场的 60-80%。
- **实现**：两条独立曲线写正/反向，别依赖 `animation-direction`；CSS `transition` 对称是默认且够用。
- **验收**：打开/关闭各看一遍——无廉价感；往返三次动画状态稳定。
- **衔接**：B71（退场动画系统）、B58（连续过渡）、K·动画中断

## K·动画接续（Animation Chaining / Sequencing）

- **领域**：动效 · **成本**：中
- **定义**：一个动画结束后接续另一个——入场→idle→交互反馈的接力，或多元素按编排顺序依次播放。
- **症状**：串行动画间有静默空档（感觉"卡了"）；接续用 setTimeout 时长对不上动画实际时长；某段被跳过后链路断裂。
- **决策点**：
  ① **接续信号**——用动画结束事件（animationend/finished promise）而非写死 timeout；**例外**：spring 后续编排锚定"感知完成点"（振幅 <2% 即视为完成，约比 finished 早 100-150ms）——物理微振仍在但视觉已停，两段之间不该有感知空档（B86·感知时长）；
  ② **重叠还是接力**——完全串行拖沓，常用 100-200ms 负延迟重叠（前段未完后段已起，B11 入场三层 0-200/200-600/600-1000ms 有重叠）；
  ③ **跳过语义**——前段被打断/跳过时后段怎么办（立即执行 vs 取消整条链）；
  ④ **降级合并**——reduced-motion 下整链合并为一个无动画状态切换。
- **实现**：`await animate(...)` promise 链 / WAAPI `finished` / framer-motion `onComplete`；入场编排用 stagger（30/50/80/120ms，B11）。
- **验收**：链条任何一环被中断时整体不分裂；时长变化不依赖手写常数同步；reduced-motion 降级完整。
- **衔接**：B11（入场三层编排）、B71（stagger 四种数学/连续编排）、B5（动效系统）、K·多阶段动画（K8）

## K·中断状态一致性（Interruption State Consistency）

- **领域**：动效/工程 · **成本**：中
- **定义**：动画被打断时，视觉中间态与数据/逻辑状态必须重新收敛——不能让 DOM 停在"半开"而状态已是"关"。
- **症状**：打断后元素的 inline style 残留（opacity 0.5 卡住）；CSS 类已移除但 transform 还在；父组件认为已收起，子组件动画还在播。
- **决策点**：
  ① **状态主权**——视觉状态从数据状态派生（`data-open`），不维护平行的"动画状态副本"；
  ② **中断收敛**——打断后新目标重新计算，旧的 rAF/timeout 全部清理（cancelAnimationFrame + clearTimeout）；
  ③ **样式清理**——动画结束/中断时移除临时 inline 样式与 will-change；
  ④ **异常兜底**——动画事件丢失（元素被移除/隐藏）时 timeout 兜底收尾。
- **实现**：React/Vue 中动画状态=渲染状态；WAAPI `animation.cancel()` 清场；监听 `animationcancel`。
- **验收**：快速连击 20 次后检查 DOM——无残留 inline style、无僵尸 rAF、视觉=数据态。
- **衔接**：B58（状态连续性）、K7·交互状态机（状态建模防止分裂）、Z3 审计钩
