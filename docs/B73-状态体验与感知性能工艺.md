## 一、骨架屏（Skeleton）的工艺细节

原则（形状像真内容 / shimmer / crossfade / 数量匹配）见 B14。这里讲**具体怎么写好看**。

### 配色规范
骨架不是随便一个灰——要和背景拉开但不刺眼：

```css
:root {
  --skeleton-base: color-mix(in oklch, var(--surface) 92%, var(--fg));
  --skeleton-shine: color-mix(in oklch, var(--surface) 84%, var(--fg));
}
/* 暗色模式：反过来，用比表面亮一点的灰 */
```
- 浅色模式：比背景**深** 4–8%（`#f0f0f0` 底 / `#e0e0e0` 高光）
- 暗色模式：比背景**亮** 6–10%（不要用纯黑上加深灰，会看不见）
- **禁忌**：骨架色对比过强（像一堆灰条），或用品牌色（喧宾夺主）

### 形状匹配真实内容
```css
.skeleton-avatar { width: 40px; height: 40px; border-radius: 50%; }
.skeleton-title  { width: 60%; height: 1em; border-radius: 4px; }
.skeleton-line   { width: 100%; height: 0.8em; border-radius: 4px; }
.skeleton-line:last-child { width: 40%; }   /* 最后一行短，像真段落 */
```

### Shimmer 光泽流动（关键）
```css
.skeleton {
  background: linear-gradient(
    100deg,
    var(--skeleton-base) 30%,
    var(--skeleton-shine) 50%,
    var(--skeleton-base) 70%
  );
  background-size: 200% 100%;
  animation: shimmer 1.4s ease-in-out infinite;
}
@keyframes shimmer {
  from { background-position: 200% 0; }
  to   { background-position: -200% 0; }
}
@media (prefers-reduced-motion: reduce) {
  .skeleton { animation: none; }   /* 改为静态灰块 */
}
```
- **方向**：从左到右（100deg 略斜比 90deg 更活）
- **速度**：1.2–1.6s，太快显焦躁，太慢显卡顿
- **替代方案**：整块 `opacity` 呼吸（pulse），更含蓄

### 无障碍（关键，最易漏）
骨架屏对屏幕阅读器是无意义的噪音，必须标记：
```html
<div class="skeleton-list" aria-busy="true" aria-live="polite">
  <div class="skeleton-card" aria-hidden="true">…</div>
  <div class="skeleton-card" aria-hidden="true">…</div>
</div>
```
- `aria-busy="true"`：告诉 AT 该区域正在加载
- 骨架元素本身 `aria-hidden="true"`：不朗读空占位
- 加载完成后移除 `aria-busy`，用 `aria-live` 让 AT 通报新内容

### 何时用骨架 vs spinner
| 情况 | 用什么 |
|---|---|
| < 300ms | 什么都不显（避免闪一下） |
| 结构已知（列表、卡片、详情） | **骨架屏** |
| 结构未知 / 全屏首载 | spinner 或进度条 |
| 局部小区域刷新 | 局部 spinner 或 pulse |
| 二次加载（已有数据） | 保留旧数据 + 顶部细进度条（不要退回骨架） |

- **prompt 措辞**："列表加载用骨架屏，配色比背景深 6%，shimmer 100deg 1.4s，形状匹配真实卡片，最后一行短；reduced-motion 下变静态"

## 二、渐进揭示（Progressive Disclosure）作为交互模式

B9 把它当视觉叙事的子概念。这里当**交互设计模式**系统讲——核心是"降低初见复杂度"。

### 核心原则
**默认只显示 80% 用户需要的，把 20% 高级功能藏在一步之后。** 不是隐藏信息，是**分层**。

### 五种模式

| 模式 | 形态 | 适合 |
|---|---|---|
| **手风琴 Accordion** | 点击展开区块 | FAQ、设置分组、长表单分段 |
| **展开更多 Show More** | 截断 + "展开全部" | 长文本、评论、标签列表 |
| **抽屉 / 侧滑面板** | 从边缘滑入 | 详情、编辑、筛选 |
| **分步 Stepper / Wizard** | 一次一屏 | 复杂表单、引导流程 |
| **悬浮揭示 Hover/Popover** | 悬停/点击出提示 | 次要信息、术语解释 |
| **高级选项 Advanced** | 折叠的"高级设置" | 90% 用默认，10% 需微调 |

### 揭示的动效（配合 V14 @starting-style / B71）
```css
.details {
  interpolate-size: allow-keywords;   /* 让 height:auto 可动画 */
  transition: height 250ms ease, opacity 200ms;
}
```
或用 `<details>` 原生元素 + View Transitions。

### 无障碍（同样最易漏）
折叠/展开必须有明确的 ARIA 状态：
```html
<button aria-expanded="false" aria-controls="advanced-panel">
  高级设置
</button>
<div id="advanced-panel" hidden>…</div>
```
- `aria-expanded` 状态切换（`false` / `true`）
- `aria-controls` 指向被控制的面板
- 手风琴多项时，每项独立标注
- `<details>`/`<summary>` 原生元素天生带这套语义，能省则省

### 设计要点
- **给出存在暗示**：折叠的内容要让用户**知道下面还有**（渐变遮罩淡出、"展开全部 (12)" 带数量）
- **保留状态**：展开过的，返回时应记住
- **不要藏关键操作**：主 CTA、必填项永远不藏
- **移动端优先**：小屏更依赖渐进揭示

- **prompt 措辞**："复杂表单用渐进揭示——基础字段直接显示，高级设置折叠；长列表截断 + 展开全部(带数量)；折叠内容用渐变遮罩暗示还有更多"

## 三、Error Boundary 的错误隔离 UI

B14 从视觉角度讲了错误分级。这里补**框架层的错误边界**——让局部崩溃不拖垮整页。

### 核心思想
**一个组件报错，只替换它自己的区域为兜底 UI，其余部分照常工作。** 而不是白屏。

### 边界的粒度（嵌套）
```
页面级边界        → 兜底"页面出错了，刷新/回首页"
  区块级边界      → 兜底"这块内容加载失败，重试"（推荐主力层）
    组件级边界    → 兜底空占位或降级简版
```
- **推荐主力放在区块级**：每个独立数据区块（图表、推荐列表、评论区）各包一个边界，一块挂了不影响其余。

### 兜底 UI 的设计要点

| 要素 | 做法 |
|---|---|
| 不显示错误码/堆栈 | 给用户看的是人话，技术细节进日志 |
| 保留区块的**外形尺寸** | 避免布局塌陷、CLS |
| 提供**出路** | 主要是"重试"按钮（局部重载，不刷新整页） |
| 语气温和 | "这部分暂时没能加载" 而非 "ERROR" |
| 区分**可重试 vs 不可重试** | 网络错→重试；权限错→引导登录/申请 |
| 降级而非消失 | 图表挂了 → 退化为数字表格；富文本挂了 → 纯文本 |

### React 示例结构
```jsx
<ErrorBoundary fallback={<BlockError onRetry={reload} />}>
  <RecommendationList />
</ErrorBoundary>
```
```css
.block-error {
  min-height: 200px;              /* 保持区块尺寸，防塌陷 */
  display: grid; place-items: center;
  gap: 12px; text-align: center;
  color: var(--fg-muted);
}
```
- Vue 用 `errorCaptured` / `onErrorCaptured`；Svelte 用 `<svelte:boundary>`。
- **prompt 措辞**："每个独立数据区块包一个 error boundary，兜底 UI 保持原尺寸防塌陷，含重试按钮，图表失败降级为表格，不显示错误码"

## 四、Delight Moment（惊喜时刻）

B47 讲了 Aha 与庆祝分级。这里讲**具体怎么做且不惹人烦**。

### 铁律：稀有性
**Delight 的价值与出现频率成反比。** 每次操作都放烟花 = 噪音。

| 触发时机 | 是否值得 delight |
|---|---|
| 首次完成核心动作（第一条笔记、第一笔交易） | ✅ 强 delight |
| 里程碑（连续 7 天、第 100 个） | ✅ 中 delight |
| 完成一次困难/长流程 | ✅ 中 delight |
| 日常重复操作（每次保存、每次点赞） | ❌ 最多微反馈 |
| 错误发生时 | ❌ 绝不（用户在受挫） |

### 分级（从轻到重）
1. **微反馈**（日常）：按钮弹一下、勾号绘制、颜色轻变 —— 见 B71
2. **小惊喜**（偶尔）：图标俏皮动一下、文案有人味、一点粒子
3. **中庆祝**（里程碑）：环形扩散、局部彩带、成就卡片弹出
4. **大庆祝**（稀有）：全屏 confetti、特殊音效、动画序列 —— 一年几次

### 手法清单
- **形变惊喜**：spinner 变勾号（不是替换，是同一元素形变）
- **粒子**：点赞迸发、完成 confetti（见 V12）
- **文案彩蛋**：空状态、404、加载文案里藏幽默（符合品牌调性时）
- **物理感**：拖拽回弹、开关的过冲、点击涟漪
- **拟人**：吉祥物在关键时刻出现
- **音+触**：完成音效 + haptic（见 B36），移动端尤其有效

### 边界与禁忌
- 尊重 `prefers-reduced-motion`：大庆祝也要有静态替代（如仅显示成就卡片）
- 不阻塞操作：庆祝动画不能挡住"下一步"按钮
- 可跳过/可关闭：重度用户会烦
- 不在专业/严肃语境滥用（金融、医疗、政务克制）
- **品牌一致**：delight 的风格要符合产品人格（见 B70 温度）

- **prompt 措辞**："delight 遵循稀有性——日常操作只做微反馈，首次成就/里程碑才用中庆祝（环形扩散/成就卡），全屏 confetti 仅限稀有大事件；错误时绝不 delight；reduced-motion 有静态替代"

## 五、四态设计速查（加载/空/错误/成功）

每个数据区块都该想全这四态（详见 B14）：

| 态 | 关键工艺 |
|---|---|
| **加载** | 骨架屏（结构已知）/ 保留旧数据 + 顶部进度条（二次加载） |
| **空** | 插图 + 一句话 + 一个 CTA，引导"下一步做什么" |
| **错误** | 保持尺寸 + 重试 + 温和语气 + 区分可否重试 |
| **成功** | 微反馈（日常）/ delight（里程碑）+ 明确"接下来" |

## 六、Prompt 模板

```
【状态体验与感知性能】
- 加载：结构已知用骨架屏（配色比背景深6%，shimmer 100deg 1.4s，
        形状匹配真内容，最后一行短）；二次加载保留旧数据+顶部进度条
- 渐进揭示：基础内容直接显示，高级/次要折叠；
           长内容截断+"展开全部(数量)"，折叠处渐变遮罩暗示
- 错误隔离：每个独立数据区块包 error boundary，
           兜底保持原尺寸防塌陷+重试按钮，图表失败降级表格，不露错误码
- Delight：稀有性原则——日常只微反馈，里程碑才中庆祝，
          全屏 confetti 仅稀有大事件，错误时绝不庆祝
- 四态齐全：每个区块都设计 加载/空/错误/成功
- 全部动效尊重 prefers-reduced-motion（骨架变静态、庆祝有静态替代）
```
