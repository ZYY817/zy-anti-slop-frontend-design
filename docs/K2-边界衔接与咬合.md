# K2 · 边界衔接与咬合

> 多个元素在边界、间距、形状、层级和运动上"严密衔接"的决策对象合集。这是全库原本最散的一类——术语在 B39/B65/B66/B86/R1·G5 都有，但没人把"边界衔接"当一个系统讲。
> 一句话判据：两个元素相接处看起来像"一个整体被切开"，而不是"两块拼上去"。

---

## K·视觉咬合（Visual Interlocking）

- **领域**：视觉/空间 · **成本**：低
- **定义**：相邻元素通过共用边界、对齐间距、呼应形状和一致层级形成紧密配合——接缝两侧被当成一个连续体设计。
- **症状（怎么知道这里有问题）**：
  - 相邻面板出现**两条紧挨着的边框**（1px+1px 变 2px 粗线）；
  - 两个相连圆角互相"打架"（各自的弧度在接缝处断开）；
  - 弹出面板与触发按钮之间有突兀的缝隙或重叠；
  - 阴影在接缝处断裂（左块有投影、右块没有，拼缝露馅）；
  - 面板展开时内容像"突然拼上去的一块"（无共享边界）。
- **适用**：工具栏+面板、按钮组、输入框+附加按钮、卡片+页签、分栏布局、手风琴 ｜ **不适用**：刻意分离的浮层（modal/toast 需要"脱离感"）。
- **决策点**：
  ① **接缝归谁**——共用一条边（-1px margin 或 border-collapse）还是各留半边缝（gap ≥4px）？
  ② **圆角归属**——相接处的角谁圆谁直？（相接内角取直、外露角取圆）
  ③ **阴影连续性**——接缝两侧的投影是否共享同一个光源模型（同一 `--light-angle`，B64）？
  ④ **层级关系**——咬合的元素是否同一 elevation？上下叠时接缝处阴影谁压谁？
  ⑤ **动态咬合**——展开/收起时接缝双方是否同步运动？
- **实现**：
  - 按钮组：相邻边合并 `margin-left: -1px` + 相接角 `border-radius: 0`，两端角保留圆角；
  - 输入框+按钮：按钮左圆角 0、输入框右圆角 0，hover/focus 时 z-index 抬升保证描边完整；
  - 面板接缝：用 `gap` 或单条 divider，禁止双侧各描 1px。
- **验收**：任何接缝处扫描一圈——无双线框、无圆角冲突、无阴影断裂、无意外缝隙；缩放 125%/150% 下接缝仍锐利（B81 亚像素）。
- **衔接**：B65§三（嵌套圆角公式）、B66（六种分隔优先级：留白>色差>阴影>线>装饰>无分隔）、B39（形状语言）、R1·G5

## K·圆角连续性（Corner Continuity / Nested Radius）

- **领域**：视觉/形状 · **成本**：低
- **定义**：嵌套圆角按同心圆规律计算——外圆角 = 内圆角 + padding，否则内角"过尖"、外角"过钝"，视觉不同心。
- **症状**：卡片内图片的圆角比卡片大或相同（看起来角被顶歪）；按钮嵌在卡片里圆角各自为政；接缝两侧圆角半径不成体系。
- **决策点**：
  ① **嵌套公式**——`outer = inner + padding`（B65§3.1），不能内外相等；
  ② **层级梯度**——外层大圆角、内层逐级减小（卡片 24px → 内按钮 8px，B86 形状层级差）；
  ③ **贴边元素**——图片顶到边缘时：贴边侧圆角=卡片圆角，内边侧=0（B65 媒体区公式 `card-radius - padding/2`）；
  ④ **曲率质量**——是否要 squircle 超椭圆（`corner-shape: superellipse(4)`，B39§56-64）替代普通圆弧。
- **实现**：
  ```css
  .card { --padding: 16px; --inner-radius: 8px;
    border-radius: calc(var(--inner-radius) + var(--padding)); }  /* 24px */
  .card .media { border-radius: var(--inner-radius); }            /* 8px */
  .card .media-edge { border-radius: var(--card-radius) var(--card-radius) 0 0; }
  ```
- **验收**：眯眼看嵌套元素"同心"；三档以上嵌套圆角成等差/等比序列；接缝内角为 0。
- **衔接**：B65§三+坑1（嵌套圆角公式）、B39§56（squircle）、B86§十一（转角七型）、B68（图标圆角一致性）

## K·边缘连续性（Edge Continuity）

- **领域**：视觉/空间 · **成本**：低
- **定义**：相邻元素的边缘保持同一条虚拟线——文本基线、卡片顶边、图标中心线、分隔线端点在视觉上是"一根线"的延续。
- **症状**：两栏顶边差 2px 不对齐；分隔线在各列长短不一；图标与文字的垂直中心线错位；卡片底边因内容不同参差但视觉需要齐平。
- **决策点**：
  ① **基准线选哪条**——顶边/底边/中线/基线，每对相邻元素明确一条；
  ② **光学补偿**——圆形/尖形元素要视觉外扩补偿（圆形直径 > 方形边长 ~4% 才显同大，B68 光学补偿）；
  ③ **断裂许可**——哪些地方允许故意断边（错位构图）？有意 vs 事故；
  ④ **跨断点一致**——响应式重排后基准线是否还成立。
- **实现**：`align-items: baseline`（文字基线）；等高卡片 `grid-auto-rows: 1fr`；图标用 `display:inline-flex; align-items:center` 而非目测 margin。
- **验收**：拉参考线检查全页主要水平/垂直边——落在 ≤3 条虚拟线上；截屏翻转检查仍齐。
- **衔接**：B68（图标光学补偿）、B42（尺寸对齐密度）、B66（分隔线参数）、R2（光学对齐/感知补偿）

## K·贴合与无缝衔接（Flush & Seamless）

- **领域**：视觉/空间 · **成本**：低
- **定义**：两个元素边缘齐平接触（flush），或连接处完全无断裂感（seamless）——前者是几何关系，后者是感知结果。
- **症状**：图片与卡片边之间有 1px 露底；深色主题下接缝处出现亮线（border 颜色错）；图案拼接处纹理断裂（tile 不接）；视频/图片网格间有发丝缝。
- **决策点**：
  ① **贴合方式**——`gap:0` + 元素自带边距清零，还是容器 `overflow:hidden` 裁切？
  ② **亚像素缝**——非整数缩放下的 0.5px 缝用什么消（负 margin -0.5px / 统一 scale / 同色描边）？
  ③ **色差控制**——两个"同色"区域相接时色值必须完全一致（`bg` 引用同一 token，不写两个字面量）；
  ④ **纹理衔接**——连续图案用 seamless tile（B39§208：图案单元边缘必须能无缝对接）。
- **实现**：图片网格 `display:grid; gap:0` + `img{display:block}`（消除 inline 基线缝）；亚像素缝用 `box-shadow: 0 0 0 0.5px same-color` 补。
- **验收**：200% 放大截图检查接缝；深浅主题各查一次；不同 DPR 下复查（B81）。
- **衔接**：B39§208（无缝拼接）、B81（亚像素渲染/banding）、B66（背景色差分隔）

## K·曲率连续（Curvature Continuity, G2）

- **领域**：视觉/形状 · **成本**：中
- **定义**：相接曲线的弯曲变化保持平顺——两段圆弧硬接会产生曲率突变（肉眼看得出的"折"），G2 连续意味着切线和曲率都衔接。
- **症状**：自定义形状/波浪分隔线在某个点"折了一下"；圆角矩形看起来像"方框+四个圆贴片"；logo 曲线放大看有硬接点。
- **决策点**：
  ① **连续等级**——G0（相接）/G1（切线同向）/G2（曲率相同）需要到哪级？UI 边界 G1 起步、品牌形状 G2；
  ② **构造方式**——普通 border-radius 只有 G1，要 G2 上 squircle（superellipse(4)，B39）或 SVG 贝塞尔手柄对齐；
  ③ **动画插值**——形状 morph 时曲率是否平滑过渡（V5）；
  ④ **成本权衡**——superellipse 兼容性（`:has()`/`corner-shape` 2025+ 支持度，需 fallback）。
- **实现**：`corner-shape: superellipse(4)`（降级：普通 border-radius）；SVG 曲线保证相邻段控制柄共线等长。
- **验收**：形状轮廓用"曲率梳"检查无突变；与 Apple 式 squircle 并排对比不突兀。
- **衔接**：B39§56-64（squircle/corner-shape）、R1·G5（曲率连续是专业度隐形指标）、V5（形状变形）

## K·形状匹配（Shape Matching）

- **领域**：视觉/形状 · **成本**：低
- **定义**：不同元素之间形成形状上的对应关系——按钮圆角与卡片圆角同族、图标轮廓与容器轮廓呼应、负形与正形互补。
- **症状**：页面里直角、4px、8px、999px 圆角混用无体系；图标是圆润风但容器是硬直角；负空间形状与正形无关。
- **决策点**：
  ① **圆角体系**——全站几个圆角档（≤4 档成尺度，B72 token 化）？
  ② **同族映射**——哪种元素用哪档（卡片 24 / 按钮 8 / 标签 pill / 头像 full，B86 形状层级差）？
  ③ **形状语义**——圆=亲和、直=工业、斜切=精工（B86 转角类型）是否与产品气质一致？
  ④ **负形设计**——留白形成的形状是否被当作形状设计（B22 正负形）？
- **实现**：`--radius-sm/md/lg/full` token 化；组件按映射表取用；icon 的 stroke-linejoin 与容器圆角性格一致（B39：round 柔和/miter 锐利）。
- **验收**：全页圆角取值 ∈ token 集合；同族元素形状语言一致；无"孤立形状"。
- **衔接**：B39（形状/线条语言）、B86§十一（转角七型+层级差）、B72（尺度 token）、B22（正负形）

## K·双重边框（Double Border / Seam Conflict）

- **领域**：视觉/工程 · **成本**：低
- **定义**：相邻元素各自的 border 在接缝处叠加成 2px 视觉粗线——最常见的咬合失败症状，值得单列一个词条。
- **症状**：按钮组中间线比外边粗；表格单元格边框粗细不均；卡片列表分割线"时而 1px 时而 2px"。
- **决策点**：
  ① **合并策略**——`margin-left: -1px`（按钮组）/`border-collapse`（表格）/只给单侧 border（`border-right` 然后最后一个去掉）/gap + 无 border 四选一；
  ② **状态升级**——hover/选中时边框变色元素 z-index 抬升，否则变色边被邻居盖住一半；
  ③ **描边还是分隔**——这组元素真的需要线吗（B66：留白>色差>阴影>线的优先级，能不用线就不用）。
- **实现**：
  ```css
  .btn-group > * + * { margin-left: -1px; }
  .btn-group > *:hover, .btn-group > *:focus { position: relative; z-index: 1; }
  ```
- **验收**：全组边框均匀 1px；hover 态描边完整可见；暗色主题下接缝不发亮。
- **衔接**：B66（分隔优先级）、B65 坑4（选中态边框跳动）、K·视觉咬合
