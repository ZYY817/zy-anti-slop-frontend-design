# 00-调研框架 · 怎么让模型做出"OK 的视觉"
（2026-11 · case07 七轮终审后启动 · 调研期纲领）

## 0. 为什么调研而不是继续打补丁

case07 六轮补丁回归证明：库已能修"失控"（色条/通道堆叠/彩度/按钮权重/名目层/死空间——全部变成可验收词），但**收敛的终点是"与裸跑同级"——克制≠好，减法词产不出创意**。

用户终审第 7 轮定的问题性质：
- "整体界面、层级、内容"三层问题仍在
- "**不想限制配色参数达到某种效果**——要模型自己做出 OK 的视觉"
- "**这个东西做了之后要能获取新内容**"——库要能自我生长，不靠人工逐条喂
- 参照物：larashero3-dotcom/lieflat-less-ai-tone（一个语言类 skill——证明"品味"可以写成 skill 形态，但我们要的是 UI 场景）

## 1. 三个已确认的问题层

| 层 | 现状 | 缺什么 |
|---|---|---|
| 整体界面 | 六补丁收敛到"同级克制" | "好"的定义——收敛≠好，无词管"什么是好的整体" |
| 层级 | 名目层数岗只管"挂几层名目" | **视觉权重怎么分配/视线怎么流动/什么该先被看到**——无词 |
| 内容 | 行描述全是"这是什么" | 信息怎么写/写什么/给谁看——无词（lieflat 是语言层的形态参照） |

## 2. 调研维度（7 个维度 → 5 个并行 agent）

| # | 维度 | 核心问题 | Agent |
|---|---|---|---|
| A | **厂商设计系统怎么编码"好"** | Apple HIG/Material 3/Fluent/Polaris/Primer/Carbon/Spectrum 各自怎么把"好"写成可执行结构？原则→令牌→模式→指引 的层级长什么样？"视觉层级"的规则他们怎么写？ | A1 |
| B | **AI 生成工具的实际做法** | v0/Claude artifacts/bolt/Lovable/Cursor/Figma AI 往 prompt 里注入了什么才不像通用模板？有没有截图自审/vision 评审回路？它们的"设计指导"是什么形态、多长、放哪？ | A2 |
| C | **知识的机器可读形态** | 同一份"品味"写成什么形态模型最能用？Anthropic skills（SKILL.md + progressive disclosure）、AGENTS.md/rules、design tokens（W3C DTCG）、原则 vs 示例 vs 清单 的实证。190 文档库 vs "一个 skill"的边界在哪？ | A3 |
| D | **"好视觉"的本体论** | 剥掉风格，好界面视觉由哪些可分解维度构成？Refactoring UI/Laws of UX/Tufte/CRAP/typography-first 学派/Linear·Stripe·Raycast 的"高级感"拆解/空间节奏/光学对齐/motion 编舞。哪些能写成"决策点+验收句"？ | A4 |
| E | **自我生长机制** | 库怎么"做了之后能获取新内容"？活的 design system 怎么演进？eval-driven 改进怎么落地？能否让 agent 从真实产品 UI 反向挖词？入库的证据闸门是什么？ | A5 |
| F | **内容/文案层** | 界面文案怎么写出人味+信息量？Polaris content/Mailchimp style/Google UX writing/GOV.UK；行描述从"这是什么"到"这对你意味着什么"的改法；lieflat 反 AI 腔方法的可迁移性 | A5 兼 |
| G | **视觉层级专项** | 用户点名第 2 问：视觉权重/视线流/焦点顺序——由 A(厂商写法)×D(设计本体) 交叉覆盖，不单派 | 并入 A1+A4 |

## 3. 产出管线

```
research/A~E 五份报告（各 ≤120 行，全部标来源）
  → 汇总：缺口图谱（我们有什么/缺什么/世界已解决什么）
  → 词库补丁：新决策对象/新文档（闸门不变：可验收+有证据）
  → case08 冷启动回归验证（新词必须改变实际决策）
```

## 4. 入库闸门（所有报告的产出标准）

每条建议必须能回答：**①它的决策点是什么 ②验收句怎么写 ③证据/来源是什么**。答不出 ①② 的，是感想不是词——只进参考不进库。
