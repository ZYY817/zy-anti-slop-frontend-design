## 2. Z1 第0层轻量方向卡（5 项答案原文）

> §二点五 R 闸门判定：常规产品 UI、视觉非主表达 → 不开 R 板块，但方向卡必答。
> 与 v1b（4 项）相比，本轮按更新后的协议答满 5 项，第 4 项"密度与呼吸峰"是本案的设计主轴。

1. **气质三词**：**安静 / 精确 / 有秩序** ——「海港值守日志」气质。通知中心是"值更台上记的每一笔"：不吵、可查、一笔是一笔。工作台像一张摊开的航海日志，不是一面卡片墙。

2. **配色来源与剂量**：取自「午夜海 × 灯塔光束」。顶栏深海军墨 `#14223C`（雾夜海面）、页底雾港米白 `#F2F0E9`、日志纸面 `#FBFAF5`、发丝线 `#DDD8C6`、主墨 `#212B3B`。**品牌动作色 = 海军墨自身**（按钮/链接/focus/完成态全用 navy，不另立彩色品牌色——单色纪律）；**灯塔光束琥珀 `#B8860B`（图形）/`#7E5F08`（浅底文本级）专司"信号"语义**：徽标、未读方钉、到达 toast 信号条、提及 chip、截止 chip——琥珀只做信号不做装饰、不做品牌强调，全页同屏 ≤6 处。**两色职责制：navy 做事，amber 报信。**（与 v1b 的"绿=动作、朱=未读"形成对照的另一套答案：信号色选非红族且与形状签名绑定）

3. **材质档**：哑光纸面 + 1px 发丝线 + 单层浅投影（面板/toast 为双层柔影）。**装饰手法仅 1 种**：值守区下缘一根"海平线"式渐变发丝线（左实右虚，像水平线没入雾里）。无噪点、无玻璃、无大圆角（圆角系统 4/8/12）。**形状签名 = 方钉**：logo 钉、未读钉、头像方、chip 记号方、徽标方角 pill、面板指向箭头是旋转方钉——全页几乎不出现圆点。

4. **密度与呼吸峰**：**基准密度 L3→L4，呼吸峰 = 页首「值守摘要」区，全页唯一放开密度区（≈L1.5），其余一律收紧。**
   - 具体参数：值守区 `padding-block: 76px`、问候语 `clamp(30px,3.6vw,42px)`、字重 300、行长 ≤24ch、四周零卡片零底色纯负空间，仅用一根海平线发丝线收束——**它是页面上唯一"喘口气"的地方**。
   - 收紧区规格：顶栏 L3（60px）；工作区双列与通知面板全部 L4（正文 13-13.5px、条目 ≈52-79px、gap 8-12px、mono 元信息 10-11px、面板 `max-height` 内滚动而非全展开）。
   - 节奏：**顶栏 L3 → 值守区 L1.5（呼吸峰）→ 双列 L4（收）→ mono 页脚（收）**。放-收-收-收，只放一处。
   - **为什么这么答**：Z2 §二点五注明 cases/04 二轮实证——v1b 方向选了"紧凑"且全域同密度执行，产出"笃定但满"，输给有留白起伏的稿；**均匀中等密度是模板味的隐蔽来源**。所以本案把"紧凑"和"放开"都推到档位的两端并让它们相邻：呼吸峰不是"哪里空一点"，是**一个有名有姓的区域**（值守摘要），它有独立的密度档位、独立的字重（300 vs 正文 400/600）、独立的行长纪律（24ch vs 面板 ~45ch）——密度差可被量化复述，不是感觉。
   - 面板内部也执行同一原则：列表 L4 紧凑到底，唯一的"小呼吸"让给空态（44px 上下留白、居中浮标线稿），**不在每条通知之间摊薄间距**。

5. **反面清单**：不做全页均匀中密铺满（本案第一禁忌）；不用 Inter/Roboto/紫蓝渐变/白底+蓝色未读点默认组合；不用三张圆角卡 hero；不用 emoji（全内联 SVG 线稿）；不写"暂无数据"；modal 用量=0；不做孤立组件演示页（范围钉死）；不装外露 demo 触发钮（到达由模拟推送节律触发，像真实产品）；琥珀不用于装饰/品牌职责（只信号）；不堆两种以上装饰手法。

## 5. 命中词条与决策点作答

### K14·打断层级升级链 ★核心决策

① **通道分级**
- Decision：按"是否需要本人动作"分级——`TOAST_TYPES={mention,assign}` → 轻打断 toast（右上信号卡 + [查看] + 5s 计时）；`reply/system` → 零打断（徽标 +1 弹跳 + 列表滑入 + polite 播报）。**面板已打开时一切降为列表内滑入**（注意力已在场）。永不 banner、永不 modal。
- Spec：`arrive()` 三分支 `panelOpen → announce+li-enter / TOAST_TYPES → showArrivalToast / else → badge+announce`。
② **升级规则**
- Decision：不升级。toast 存活窗内同类到达**合并进同一条**（"何叔衡 等 2 条新通知"）；用户忽略不升级。
③ **降级规则**
- Decision：能 inline 的不 toast——单条已读=就地收起+播报；能 toast 的不 modal——两批量操作=toast+撤销。
④ **打断成本表**
- Decision：modal=0（无可撤销不了的事，无必须回答才能继续的事）。

### K14·Toast 队列治理

① 同屏上限：同屏 ≤2（到达通道 + 撤销通道）；到达类合并非叠加，永远最多 1 条。
② 优先级与去重：`ARRIVAL_POOL` 合并池，存活窗内新到达更新同一条标题计数并重臂计时；toast 关闭时清池。
③ 自动消失：到达 5s / 撤销 6s / 信息提示 4s；hover 与 focusin 双通道暂停、leave 恢复**剩余**时长不清零；**setTimeout 承担 deadline，rAF 只画进度条——同一 `remain` 数据源**（v1 反哺经验"进度条须与计时同源"的正确解形态，且比"rAF 兼做计时器"更易测）。
④ 读屏分道：`toastRoot` 容器 `aria-live="polite"` + 每条 `role="status"`；到达 toast 通道不再走独立 announcer（防双读）；无 assertive。

### K14·徽标与未读

① 计数上限：99+ 封顶。
② 清零时机：**开面板不清零**——仅显式动作清零（点方钉 / 点条目 / 全部已读）。
③ 红点 vs 数字：数字徽标（有确切未读语义的待办型产品）；0 时徽标整体隐藏；`aria-label` 同步"通知，N 条未读"。
④ 层级穿透：N/A（单级入口）。
- 未读态视觉（采用"指示器即操作"第 4 形态，本案变体）：**方钉**——未读行右侧实心琥珀方钉即"标已读"按钮，常驻不依赖 hover；已读行同位是空心方钉即"标未读"（双向可逆，比 v1b 多一路反向操作）；桌面 hover 时钉缩为勾号/回箭，触屏钉本就常驻。叠加暖光 tint 底 + 标题字重 + mono 时辰列转琥珀 = 多通道冗余。

### K14·浮层堆叠治理

① 层级表：`workbench(0) < topbar sticky(10) < panel popover(40) < toast(70)`——toast 恒压面板。
② 嵌套许可：单浮层，无 Modal 可能。
③ 焦点栈：非模态 Disclosure——焦点停留铃铛（`aria-expanded/controls`），Tab 依 DOM 顺序入面板；**Esc 先关栈顶 toast（lastElementChild）再关面板**并归还焦点铃铛；`pointerdown` 外点关闭；键盘标已读后**焦点跟随条目到已读区**（B76 焦点不丢失，实证断言 `focus follows`）。
④ 背景锁滚：非模态不锁滚；`.p-body{overscroll-behavior:contain}` 防穿透；底部渐隐 mask 仅"可滚且未到底"时挂载（K6·穿透 + B74·12.2）。

### K12·撤销与破坏性操作（片段取用）

① 确认 vs 撤销：全部已读 / 清除已读均可逆 → Toast+Undo，零 modal。
② 撤销窗口：6s，hover/focus 暂停（与到达 toast 同一 armTimer 机制）。
③ 撤销粒度：整组——一条 toast 撤一组。
④ 实现要点（本轮新增两条实证）：
   - **快照存条目本体不存 id 反查**（到达项晚于快照建立也能正确恢复）；`ORDER` 数组恢复原位。
   - **新批量操作作废旧撤销 toast**（`dismissStaleUndos`）：否则旧快照指向的条目可能已被新操作移除，点"撤销"静默失败——撤销承诺不能是空头支票。本轮无头实证抓到：markAll→clearRead→点旧 toast 的撤销 = 恢复 0 条，修复后恢复语义闭合。
   - **markAll 延迟提交只覆盖快照集**：动画期间新到达的未读不被误吞；撤销在 pending 期内可取消提交（`pendingMarkAll` 句柄，v1b P0 经验吸收）。

### K3·触屏无 hover（片段取用）

① hover 承载物分级：标已读/标未读按钮 = 功能性 → **常驻渲染**（方钉即指示器即操作，空心钉同理常驻仅低透明）；桌面 hover 只做透明度/图标互换增强。
② 粘滞清除：hover 样式全部在 `@media (hover:hover) and (pointer:fine)` 内。
③ 长按语义：N/A（功能常驻）。
④ 命中区：`.n-peg::after{inset:-7px}` 把触控目标扩到 ~44px，视觉仍 30px。

### K6·滚动穿透（片段取用）

① 穿透策略：面板滚动容器 `overscroll-behavior:contain`。
② 边界反馈：硬停 + 按需渐隐 mask 提示可滚。
③ 键盘滚动：`.p-body` 加 `tabindex="0"` + aria-label，键盘用户可滚动长列表。

### K18·视觉配额（片段取用）

① signature 峰值：1 个——通知到达编排（铃摆 + 徽标弹跳 + toast 信号条）；工作台全部让位。
② 强调色配额：琥珀同屏 ≤6 处（徽标/未读钉×N 合算信号系统/到达 toast/提及 chip/截止 chip/水位数）；navy 动作 ≤5。
③ 装饰手法：1 种——海平线渐变发丝线。
④ 同屏动效并发：≤2。
⑤ 纹理剂量：0。

### 未命中 / 判定不适用

- K·权限可见性：仅借其"四策略混排"思路——`全部已读` 未读为 0 时 disable+原因 title；`清除已读` 无已读时隐藏。
- K9#16/#17：撤销 vs 确认、inline vs toast vs banner vs modal 两对辨析的答案即 §K14①④（选型本身即答案）。
- K·权限/流式/表格/吸附等：本案不涉及。
- R 板块：不开闸。

## 6. 设计方向陈述（M1：写码前承诺）

- **产品**：「栈桥 Pier」协作工作台。通知中心 = **值更日志**：每条通知是航海日志的一笔——mono 时辰列打头、类型 chip 为记、方钉销账。
- **字体**：正文系统 CJK 无衬线栈（零依赖约束）；**mono 是本案的"声音"**——时辰列、组头编号、chip、徽标、页脚、水位数字全走 mono（值更官的笔迹）；问候用无衬线 300 细字（非宋体，与 v1b 区隔）；一切数字 tabular-nums。
- **布局签名**：午夜海顶栏压雾港纸面；**呼吸峰值守区**大留白 + mono 更次眉题（`甲班 · 第 3 更`）+ 海平线发丝线收束；工作区 38:62 非对称双列收紧。
- **面板行结构（与前两臂都不同）**：`[09:42]` 时辰列 → 方角首字头 → 两行正文（`<b>` 人名 + `<q>` 引文「」）→ meta 行（chip/项目/截止 chip）→ 方钉操作列——**日志行**而非"卡片条目"。
- **差异化落点**：形状签名统一为"方"（钉/头/chip/徽标/箭头全是方角，几乎无圆点）；双色职责制（navy 动作 / amber 信号）；未读区分 = tint+字重+方钉+时辰列转色四通道。
- **反默认清单**：非紫渐变、非蓝点未读、非圆头像、非三卡 hero、非 emoji、非"暂无数据"、非外露 demo 钮、非均匀中密。

### 无头 Chrome 实证（虚拟时钟桩 + `--dump-dom`，46 断言全 PASS）

- **状态机**：初始 4U/6R/徽标4 → 开面板 aria-expanded → 单条已读 3U/7R 且置顶已读 → 标未读回 4U → 键盘标已读焦点跟随 → 面板开时到达零打断仅滑入 → 关面板 mention 到达→toast+徽标 → reply 到达零打断仅徽标 → assign 到达合并"等 2 条" → hover 暂停存活/leave 到期消失 → Esc 先关 toast 再关面板且焦点归还 → 全部已读 0U+徽标隐+清零条+按钮禁 → 撤销回 7U → pending 期内撤销取消提交 → 旧 undo toast 被新操作作废 → 清除已读 R0 → 撤销回 7R → 全清大海面空态 → 撤销回 14R。
