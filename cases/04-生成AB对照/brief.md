# brief.md · 生成 A/B 对照任务书

> 对齐 T1 协议的 V0（裸模型）vs V1（知识库辅助）对照。**同一任务书发给两个隔离 agent**，V1 额外获得库路径与入口协议。
> 裁判 agent 对两份产出做盲审（不知哪份是哪组），按 K10 九维框架评分。

## 任务原文（两组相同）

```text
为一个团队协作 SaaS 工具实现"通知中心"下拉面板。

功能要求：
- 顶部导航栏有一个通知入口，带未读数提示
- 点击展开面板：通知列表分"未读"和"已读"两组
- 未读通知有视觉区分；单条可标记已读；可一键全部已读
- 新通知实时到达时要有合适的到达呈现（自己想清楚用哪种打断级别）
- 空状态也要有设计
- 数据用真实语义的中文 mock 数据（8-10 条，含不同类型：@提及/任务指派/系统通知/评论回复）

约束：单文件 HTML（内联 CSS/JS），不引外部库，中文界面。
**范围钉死**：交付"一个真实产品工作台页，通知面板嵌在顶部导航内"——不是孤立的组件演示页。页面要有真实的工作台内容（项目/任务/数据），通知面板是其中一部分。
```

## 盲审规则

- 文件重命名副本为 `armA.html`/`armB.html`（顺序随机），裁判不知对应关系
- 裁判按 K10 九维逐维评分（每维 0-10 + 症状证据），输出 `judge-report.md`
- 计分口径：九维均分 + P0 计数（P0 一票否决加权）
- 完成后揭盲，写 `record.md` 对照分析
