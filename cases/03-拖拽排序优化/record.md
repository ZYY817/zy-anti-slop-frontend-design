# record.md · 03-拖拽排序优化 对照记录

> **本案与 01/02 的本质区别**：audit.md 与 after.html 不是我写的——是把 K10 附录的两个 pasteable prompt **原样发给全新 agent（无对话上下文）真跑出来的**。这是对"提示词传送带"的第一次真实验证，也是反哺机制的第一次实际运转。

## 执行方式

```
before.html（我按 AI slop 缺陷模式编写）
  → agent A（全新上下文）：只拿到 K10 诊断 prompt 原文 + 文件路径 + 库位置 → audit.md
  → agent B（全新上下文）：只拿到 K10 修复 prompt 原文 + audit.md + before.html + 库位置 → after.html + repair-report.md
```

agent A/B 对彼此工作无任何先验知识——隔离保证了测试效力。

## 闭环暴露的库级问题（本案最大产出）

真跑提示词比手写审计多挣到的东西——两个 agent 的诚实元反馈暴露了**提示词和知识库自身的缺陷**：

| # | 暴露的问题 | 处置 |
|---|---|---|
| 1 | **K4 vs K7 内部矛盾**：capture 时机两套口径（K4"过阈值才捕" / K7"pointerdown 即捕"） | ✅ 已修：K7 实现字段改为按热区分流（抓手区即捕；整面可拖挂 window 监听过阈值再捕） |
| 2 | **全库词条缺口**：拖拽边缘自动滚动无词条（agent A 发现"拖到边缘不滚"无命中条目可填） | ✅ 已反哺：新增 `K·拖拽边缘自动滚动` 入 K4（64px 触发/线性 ramp/滚动补偿/仲裁），速查表+K0 已同步 |
| 3 | 诊断 prompt 未说明"B/R 指针文档无决策点字段怎么办" | ✅ 已修：加"核心规范转写为决策句式"规则 |
| 4 | 诊断 prompt 未说明"症状存在但无条目命中怎么办" | ✅ 已修：加"标库缺口进反哺清单"规则 |
| 5 | 诊断 prompt 缺 P0 判罚细则与"通过"证据分级 | ✅ 已修：补判罚细则 + ✅/⬜ 分级 |
| 6 | 修复 prompt 规则 1 只覆盖 K 词条，未覆盖指针项；规则 5"不适用"未给库缺口口子；规则 2"保留功能"基线未定义 | ✅ 已修：三处措辞回填 |

**结论**：K10 提示词可独立驱动合格产出，但真跑第一次就挣到 1 个库内部矛盾修复 + 1 个新词条 + 6 处 prompt 措辞修复——这正是"真实测试负责验证，验证结果反哺知识库"的设计意图兑现。

## agent 自答的关键决策点（词条给域、取值 agent 定）

- capture 时机冲突仲裁：pointerdown 即捕（选 K7 口径，触屏仅抓手发起已隔离滚动风险）→ 现 K4/K7 已统一为此口径
- 热区仲裁：触屏仅手柄；鼠标=手柄+行体非文本区；标题区让位文本选择——根治"选中 vs 拖拽互斥"
- 无效区外扩 Y±48/X±64 + 先验 no-drop；三路取消（Esc/cancel/越界松手）统一回滚
- 弹回 WAAPI 280ms，**主动不做 shake**（回滚是"没放"不是"做错"——语义判断加分项）
- auto-scroll（库缺口自答）：64px 触发/线性 0→14px·帧/滚动后 rects 重算
